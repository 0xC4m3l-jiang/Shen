## 1. 需求与验收

**要解决什么**：`MD-5` 原文说「跨模块共享的**类型定义必须**收敛到 `api/`」，而现实是
`api/` 只放**跨进程**契约（proto 生成物），**进程内**共享类型集中在 `core/internal/contract/`（8 个文件）——
[`../design/structure.md`](../design/structure.md) §1.2 / §1.6.2 明确把 `contract` 定义为「只放类型、无逻辑」的词汇表叶子，
`scripts/archcheck` 也早已把它列入结构性目录白名单。**规则文本落后于设计与实现**，按字面执行会得出错误结论。
`MD-19` 的例外清单同样漏了该目录。

**验收判据**：

1. `MD-5` 明确两类落点（跨进程 / 进程内），`MD-19` 的例外清单含 `core/internal/contract/`。
2. 引用这两条规则的活文档同步（模块文档模板 · `policy.md`）；已按现实写作的（`decoy.md` · `director.md` · `spec/config.md`）保持不动。
3. 规则效力**不变**：仍禁止各自定义同名类型、仍禁止清单外目录承载业务逻辑。
4. 记录可回退：注记里写清原文、改动与日期。
5. `make gate` 绿（含追溯检查的规则 ID 引用存在性）。

**不做什么**：不动 `contract/` 目录本身（它是设计的一部分）· 不改任何代码 · 不重排规则编号（`D-6`：ID 是引用句柄）。
