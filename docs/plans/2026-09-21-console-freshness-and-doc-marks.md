## 1. 需求与验收

**要解决什么**（一句话）：用户要「补一个点能力」+「确认文档对应内容标记准确」。
两件事在本轮**合成一件**：审计发现 [`../spec/console-api.md`](../spec/console-api.md) 里写着一句
「『是不是刚重启』由 `/api/summary` 的事件时间范围回答」—— 而**页面根本没显示它**（`first_seen` / `last_seen` 一次都没被用过）。
那句话既是**文档不准确**，也正好指出**该补的能力点**。

**做完之后能做什么**：

1. 打开控制台第一眼就能看到**最后一条事件距今多久**；超过 120 秒（≈24 个刷新周期）标色提醒
   「⚠️ 观测可能已停」；
2. 概览多一行**观测窗口**（`first_seen ~ last_seen`，共 N 条事件）—— 用来判断「核心是不是刚重启」；
3. 六处文档标记被校准（清单见 §7.1），`console-api.md` 的那句承诺**变成事实**。

**验收判据**：

1. 有判定数据时：`/api/summary` 的 `first_seen` / `last_seen` 非空，页面显示观测窗口与「最后一条在 N 秒前」；
2. 无数据时：显示「暂无判定数据」而不是 `NaN` / `Invalid Date`；
3. 超过阈值时：概览文字**标色**（`err` 类），且**不改任何处置**（`AR-10`：只显示）；
4. §7.1 的 6 处不准确**全部改正**，且 `make trace` 绿（悬空链接 / 过期标记）。

**不做什么**：

- **不加接口、不改核心**：数据早就在 `/api/summary` 里（`first_seen` / `last_seen`），本轮**只在页面消费它**；
- **不做图表**：仍然是无构建 + 纯 DOM（因此**不触发** ADR-0020 失效条件 1）；
- **不动告警 / 监控**：告警要等 `severity` 档位定；监控的时序图会触发失效条件 1（见 §7）。

## 2. 设计逻辑

**已确认的决策**：

| # | 问题 | 决定 | 理由 | 落地位置 |
| --- | --- | --- | --- | --- |
| ① | 补哪一个能力点 | **观测新鲜度**（时间窗 + 距今 + 超时标色） | 它在今天的审计里是**唯一一个「文档已承诺、实现没做」**的点 ⇒ 补它同时完成两件事；且**零后端改动**、不引图表、不触发 ADR-0020 | `console/web/index.html` 的 `freshness()` / `fmtWindow()` / `STALE_AFTER_MS` |
| ② | 阈值放哪 | **页面常量**（120 秒），不写成契约字段 | 它是**展示口径**，不是跨进程契约；写进契约会让「改个配色阈值」变成改契约 | 契约 §2 的 `/api/summary` 行注明「这是页面常量」 |
| ③ | 超时怎么办 | **只标色 + 写明「观测可能已停」** | 控制台的任何输出都**不得**影响处置（`AR-10`）—— 它连告警都不算，只是一眼可见的提示 | 同上 |

**仍未定**：无。

**接缝与接口**：**零新增**（本轮不碰 `api/`，也不碰控制台的 Go 代码）。

**数据流**：

```text
ListEvents（核心）
  └─ /api/summary { total, by_action, alerts, l4_conclusions, first_seen, last_seen }
       └─ 页面：概览卡片（原有）+ 「观测窗口：first ~ last（共 N 条）」 + 右上角「最后一条在 N 秒前」
            └─ last_seen 距今 > 120s ⇒ 概览文字标 err 色 + 「⚠️ 观测可能已停」
       └─ 空数据 ⇒ 「暂无判定数据」（不显示 NaN / Invalid Date）
```

**关键函数**：

- `freshness(lastSeen) -> {text, stale}`：把「最后一条距今多久」算成一句话 + 是否过期（`Number.isFinite` 挡住坏时间戳）；
- `fmtWindow(sum) -> string`：观测窗口一行；空数据给明确文案（不给 `NaN`）；
- `STALE_AFTER_MS = 120_000`：页面常量，注释写清「≈24 个刷新周期」与「只标色、不改处置」。

**必须遵守的上位约束**：`AR-10`（只展示，不参与任何处置）· `MD-3`（契约里的承诺必须与实现一致 —— 本轮的核心动机）· `MD-6`（不碰核心时钟）。

## 7. 遗留与未决

| # | 遗留 | 影响 | 去向 |
| --- | --- | --- | --- |
| 1 | 120 秒阈值是拍的 | 流量稀疏时会误报、流量密集时不够敏感 | 页面常量，随实战调；若要按环境配，参照 `SHEN_CONSOLE_ALERT_SCORE` 的做法 |
| 2 | **页面无 JS 测试** | 「无数据」「超时」两条分支没被自动验证 | 若前端继续变复杂，与 ADR-0020 失效条件 1 一起评估（引入前端门禁时顺带补） |
| 3 | 监控时序图 / 告警档位仍未做 | 五个模块里还剩两个 | 开工前必须先重开 `ADR-0020` 失效条件 1（图表/组件化） |
| 4 | AI 生成批次 / 护栏拒绝明细未展示 | 「AI」只到配置态 | 等适配器（ADR-0026 未解决 1） |
