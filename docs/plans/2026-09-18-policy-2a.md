## 1. 需求与验收（PRD 段）

**要解决什么**：判定管线跑得通，但**恒零分、无信号** —— `core/cmd/core/main.go` 传的是空规则集，
没有任何 Go 代码读配置。引擎在跑，但它什么都没判。

**做完之后，用户能做什么**：
1. 改一份配置文件就能让规则生效（不必改代码、不必重新理解模块）；
2. 配置写错了**进程起不来**，并直接指出是哪一行哪个字段 —— 不再有「静默空转」；
3. 一眼看到「策略是否真的生效」：启动日志打印 `policy_id / version / checksum / 规则条数`；
4. 一条命令验完这轮：`make dev`。

**验收判据**：

| # | 判据 | 证据形式 |
| --- | --- | --- |
| 1 | `make gate` 全绿（含 `-race`） | 门禁输出末行 |
| 2 | 每条校验规则有正样本 + 负样本 | 单测用例名 |
| 3 | 示例配置必须能被装载（样例与 schema 不漂移） | `TestExampleConfigLoads` |
| 4 | 合法配置启动成功并打印策略摘要 | 启动日志行 |
| 5 | 缺 `SHEN_CONFIG` / 配置非法 / 版本不递增 → 非零退出并指出字段 | 退出码 + 报错行 |
| 6 | 判定响应仍只含 `action / severity / backend`，影子模式恒 `route_origin` | 冒烟输出 + 装配层单测 |

**不做什么**：

- 不下发面（`api/policy/v1` 的 `Pull` / `Watch` / `Ack`）—— 2a 没有消费者，适配器只调 `Judge`；
- 不改 `judge` / `edge/*`；不改 `control` 的判定面与遥测面；
- 不新增数据模型实体（`Ack` 回执持久化需要新实体，`ST-13` 要求先改 `structure.md` §3，需另行确认）；
- 不做热重载（不监听文件、不响应信号）；
- 不实现 `director`、不接真实存储。

## 2. 设计逻辑（技术设计段）

**决策树**：

```text
policy 2a
│
├── 第 1 轮（范围）
│   ├── Q1 本轮做哪个模块 ──────► policy 2a
│   ├── Q2 空规则集怎么闭合 ────► 新建 spec/config.md + policy 装载 YAML
│   └── Q3 下发面做到哪 ────────► 本轮不做
│
├── 第 2 轮（契约）
│   ├── Q4 spec/config.md 覆盖面 ─► 全表定义 + 严格校验
│   ├── Q5 规则算符范围 ─────────► 沿用 5 字段 × 3 算符
│   └── Q6 version 从哪来 ───────► 配置文件显式声明
│
└── 第 3 轮（运行形态）
    ├── Q7 变更如何生效 ─────────► 启动装载一次
    ├── Q8 快照写不写台账 ───────► 写入 store.PolicyStore
    └── Q9 白名单是否预留 ───────► spec 预留 whitelist 段（只解析不消费）
```

**已确认的决策**：

| # | 问题 | 决定 | 理由 | 落地位置 |
| --- | --- | --- | --- | --- |
| ① | 本轮模块 | `policy` 2a | 阶段 2 中唯一零前置；且能顺带闭合阶段 1 的未闭合项 | `core/internal/policy/` |
| ② | 空规则集闭合 | 新建 `docs/spec/config.md` + `policy` 装载校验 → 版本 + 校验和 → 供 `judge.RuleSource`；缺文件或非法**必须**启动失败 | 禁止静默空转；策略是数据（`ST-24`） | `spec/config.md` · `policy.go` · `main.go` |
| ③ | 下发面 | 本轮不做 | 2a 无消费者；做了也无处可验 | 遗留 §7.1 |
| ④ | 配置文档范围 | 全表定义 + 严格校验（未知键与非法值 = 启动失败） | 静默忽略错键等于配置失效 | `spec/config.md` §2 |
| ⑤ | 规则算符 | 沿用 `contract.Match`：5 字段 × 3 算符 | 零代码改动；表达力缺口另记 | `spec/config.md` §2.4 |
| ⑥ | `version` 来源 | 配置文件显式声明 + 严格递增；回滚 = 高版本 + 旧内容 | 版本号是可编排、可对账的运维语义 | [ADR-0009](../background/decisions/0009-policy-version-source.md) |
| ⑦ | 生效方式 | 启动装载一次 | 影子模式可接受；运行时变更属下发面 | `main.go` |
| ⑧ | 版本台账 | 装载后写入 `store.PolicyStore`（单调性由 store 侧强制） | 复用已留接缝；为下轮下发面备好数据源 | `policy.Publish` |
| ⑨ | 白名单 | `spec/config.md` 预留 `whitelist` 段，只解析与校验、不消费 | `INT-25` 要求在引流判定前生效，配置面先就位 | `spec/config.md` §2.5 |

**仍未定**（本轮范围外）：

| # | 未决 | 阻塞什么 | 去向 |
| --- | --- | --- | --- |
| 1 | 下发面 `Pull` / `Watch` / `Ack`；`Watch` 的流式语义与断线重连 | 适配器与 L2/L3 的本地策略缓存 | §7.1 |
| 2 | `Ack` 回执持久化需要新实体（先改 `structure.md` §3，需用户确认） | 版本对账的跨副本一致性（`AR-13`） | §7.2 |
| 3 | 配置文件与 PostgreSQL 策略台账的最终关系 | 真实存储选型 | §7.3 |
| 4 | JSON Schema 与 Go 校验器的漂移防护 | 长期一致性 | §7.4 |
| 5 | `whitelist` 的消费方（`director` 的引流判定前置） | 误伤护栏 `INT-25` | §7.5 |
| 6 | `rules[].match` 的 `headers` 寻址缺口（`Observation.Headers` 已采集但 `Field()` 取不到） | 一批 Agent 信号不可用 | §7.6 |
| 7 | `severity` 档位（实测问题）· `E2`（TLS 指纹一致性，项目级 P0） | 见各自登记处 | 各文档 |

**接缝与接口**：

| 接缝 | 由谁实现 | 由谁消费 | 依赖方向 |
| --- | --- | --- | --- |
| `judge.RuleSource`（消费方定义） | `policy.Loader` | `judge.Engine` | `policy` → 不 import `judge`（单向） |
| `store.PolicyStore`（既有的唯一 I/O 出口） | `store.PolicyMemory`（本期内存） | `policy.Loader.Publish` | `policy` → `store` |
| `api/policy/v1`（已生成的 proto） | —— **本期无实现** | —— 本期无消费者 | 未接线 |

**数据流（含失败路径）**：

```text
SHEN_CONFIG ──► os.Open ──► policy.Load(io.Reader)
                              │  严格解码（未知键拒绝）
                              ├─► 逐字段校验 ──✗──► 返回错误 ──► 进程启动失败（非零退出 + 字段路径）
                              └─► 构造不可变快照（Payload=policy+rules+whitelist 的紧凑 JSON；Checksum=sha256）
                                     │
                                     ├─► Publish(store.PolicyStore) ──✗──► 启动失败（版本不递增等）
                                     └─► judge.New(loader) ──► 每请求 Rules()（内存读、无 I/O）
                                                                   └─► ShadowDecider ──► 恒 route_origin（影子模式）
```

## 5. 测试与场景

| # | 场景 | 输入 / 前置 | 期望 | 实测 | 证据 |
