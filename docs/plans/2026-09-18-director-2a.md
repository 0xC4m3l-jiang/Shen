## 1. 需求与验收

**要解决什么**：核心当前是 `control.ShadowDecider`，**恒返回放行** —— 适配器永远只会放行。`director` 是让引流真正生效的那一块。

**做完之后，用户能做什么 / 看到什么**：关闭影子（`shadow: false`）后，核心产出真实三值；高分请求被改道（`route_mirage` + 后端名），低分放行。

**验收判据**（照 [`2026-09-17-director-2a.md`](2026-09-17-director-2a.md) §6）：

1. `make gate` 全绿（含 `-race`）。
2. `director` 单测覆盖：三值 × 阈值边界 · 灰度确定性 · `NI-5` 回落 · 分支穷尽（`MD-8`）。
3. 测试**只用替身**，不依赖 `judge` / `policy` 真实实例（`MD-22`）。
4. 端到端：接管模式下高分请求真的被改道。
5. 影子模式下行为与现在完全一致（恒 `route_origin`）—— 回归判据。

**不做什么**：

- 熔断**不落** `director`（落 `control` 服务面，Q6）。
- 不选后端池（多后端 / 健康检查），是阶段 3 的事。
- 不接 `whitelist` 消费（`INT-25`）—— 登记为遗留。

## 2. 设计逻辑

**已确认的决策**（用户 2026-09-18 确认「按推荐」）：

| # | 问题 | 决定 | 落地位置 |
| --- | --- | --- | --- |
| Q1 | 交付范围 | 最小 + 灰度 + 熔断 | 全部 |
| Q2 | 决策函数形状 | 纯阈值：`≥block`→block；`≥mirage`→route_mirage；否则 route_origin | [`director.go`](../../core/internal/director/director.go) `classify` |
| Q3 | 阈值来源 | `ThresholdSource` 接口，2a 由 `policy.Loader` 实现 | [`iface.go`](../../core/internal/director/iface.go) |
| Q4 | 灰度方向与确定性 | 本会改道的按比例**降级为放行**，按 `decision_id` 哈希**确定性** | `director.go` `grayAllows` |
| Q5 | block 是否产出 | 默认**不产出**（构造开关默认关） | `director.go` `Config.BlockEnabled` |
| Q6 | 熔断落位 | `control` 服务面 | [`core/internal/control/breaker.go`](../../core/internal/control/breaker.go) |

**接缝与接口**：替换 `control.Decider`。`shadow: true`（默认）→ `ShadowDecider`（恒放行）；`shadow: false` → `director`。

**数据流（含失败路径）**：适配器 → gRPC → `JudgeService`（熔断检查 → 决策 → 记录）→ `director.Decide` → `judge.Judge` → `classify` → 灰度 → `Decision` → 适配器按三值处置。任何失败的 `Decide` 返回错误 → 适配器 fail-open 放行（`NI-3`/`NI-4`/`NI-5`）。
