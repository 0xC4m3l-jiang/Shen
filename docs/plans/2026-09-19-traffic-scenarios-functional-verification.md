## 1. 需求与验收

**用户要什么**：① 完成**不同场景**的伪造流量，方便**整体功能验证**；② 跑一次测试脚本确认整体逻辑没问题，
并**帮助找到功能逻辑上的欠缺**。

**验收判据**：

1. 场景覆盖**能力维度**（而非零散样本）：自动化探针 · 扫描器指纹 · 敏感端点 · 注入与穿越 · 破坏性方法 · 会话与缓存 · 白名单 · 正常对照 · 边界。
2. 期望值**与真实规则一致**（分数、信号、决策），并能验证 `ST-10`（判定复用）、`ST-7`（不回显）、`NI-1`（不影响业务）。
3. 能输出三类结论：断言通过/失败 · **已知缺口**（设计有、当前没做到）· L4 结论核对（`AR-12`）。
4. 缺口必须**可行动**：每条给出类别（未实现/精度/未覆盖）、实测证据、怎么关。
5. 说清**哪些能力在当前环境里根本验不了**（影子模式、无后端、无集群）与原因。
6. `make gate` 绿。

**不做什么**：不做压测 · 不实现攻击载荷库 · 不改判定逻辑（缺口只登记，不在本轮修）。

## 2. 设计逻辑

| # | 问题 | 决定 | 理由 |
| --- | --- | --- | --- |
| ① | 只有 2 条示例规则，多数流量只能"观察" | 示例规则扩到 **16 条**（扫描器指纹 / 敏感路径 / 注入标记 / 方法维度） | 没有规则的流量验证不到判定；示例规则是**可替换的样例**，不是产品内置策略 |
| ② | "缺口"要不要算失败 | **不算**，单独一段打印 | 缺口是"已知未做"，做成红灯会让每次验证都红；列出来才是它的用途 |
| ③ | 判定复用怎么验 | 场景级 `session: shared` + `same_decision_as_previous` | `ST-10` 是**有意为之**的取舍，必须能被验证而不是靠嘴说 |
| ④ | 出口卫生怎么验 | 每个场景检查响应头（`x-shen*`/`Via`/`Caddy`）**与响应体**（不得出现命中信号名/判定 id） | `ST-7` 的直接检查：泄漏了就等于把判定告诉对手 |
| ⑤ | L4 怎么验 | `--check-l4`：结论存在性 + 证据引用必须真实存在（`AR-12`） | 结论是近线产出的，无法在请求路径上断言 |

## 3. 追溯矩阵

| 规则 | 验证方式（场景/检查） |
| --- | --- |
| `ST-7` 不回显 | 33 个场景逐一检查响应体与响应头；命中信号名不得出现 |
| `ST-10` 判定复用 | `session-reuse`（同会话 → 同一 `decision_id`）· `session-distinct`（换会话 → 不同） |
| `NI-1` 不影响业务 | 每个场景断言状态码（`status_in` 可声明业务自身行为，如演示站的 501） |
| `NI-5` 改道回落 | 本环境无法验证（见 §3 缺口说明） |
| `OH-2` 可见面卫生 | `header_findings()` + 全量 0 命中 |
| `AR-11` 幂等 | 控制台事件数 vs 判定数（重复判定不重复记） |
| `AR-12` 证据存在 | `--check-l4`：结论引用的 `evidence_ids` ⊆ 遥测里的 `decision_id` |
| `AR-14` 态势去重 | 135 个判定 → 少量结论（实测 2~6 条） |
| `INT-11` 影子模式 | 全量断言 `action=route_origin`（无改道/拦截） |
| `INT-25` 白名单 | `whitelist-monitoring` 作为**缺口**登记（配置未消费） |

$ scripts/shen.sh traffic --check-l4

      实测：当前分数 0.3、信号 ['path-probe']

## 7. 遗留与未决

| # | 遗留 | 影响 | 去向 |
| --- | --- | --- | --- |
| 1 | **查询串对判定不可见** | SQLi/穿越等参数载荷默认不判 | 缺口中最高优先；加 `query`/`raw_uri` 字段 |
| 2 | 编码即可绕过 | 一次 URL 编码即过 | 匹配前归一化/解码 |
| 3 | 前缀语义（误伤 + 绕过） | 误伤 `/.gitignore`；可被前缀绕过 | 路径段边界匹配 + 归一化 |
| 4 | PUT/PATCH 未建模 | 写操作覆盖不全 | 补方法维度基线规则 |
| 5 | 白名单（`INT-25`）未消费 | 内部探针将来可能被引流 | 接入 `director` 判定前置 |
| 6 | `severity` 恒为 `none` | 控制台"告警"永远为 0 | 定档位（设计已登记未决项） |
| 7 | 期望值与示例规则**手工同步** | 改规则不改场景会假红 | 可让脚本读 policy 规则清单做交叉校验 |
| 8 | 改道/拦截等路径在本栈验不了 | 覆盖不完整 | 需要非影子模式 + 登记后端（或专项接入演练） |

## 7.1 审视记录

| # | 发现 | 类型 | 证据 | 动作 | 结果 |
| --- | --- | --- | --- | --- | --- |
| 1 | **查询串不参与判定** | **真实能力缺口** | `/download?file=../../etc/passwd` 与 `/search?q=union+select` 均 0 分 0 信号 | 转为 `gap`（类别：未覆盖）并写清怎么关；**不在本轮修** | ✅ 已登记 |
| 2 | 共享会话场景每轮都生成随机 cookie | 脚本 bug（自伤） | `session-reuse` 报"期望复用同一判定，实际换了" | 会话在**场景级**生成一次 | ✅ 复用验证通过 |
| 3 | 第一轮就断言"与上一条不同/相同" | 脚本 bug | 报"需要 --repeat ≥ 2" | 只在 `previous_decision is not None` 时断言 | ✅ |
| 4 | 非 ASCII 路径直接把请求发崩 | 脚本 bug | `'ascii' codec can't encode characters` | 按 percent-encoding 发送（真实客户端行为），匹配按**解码形态**比较 | ✅ 200 且匹配成功 |
| 5 | `method-put`（缺口类）因演示站 501 被判失败 | 断言写错（业务行为当成引擎问题） | `HTTP 501：业务被影响（NI-1 不允许）` | 场景声明 `status_in`；`NI-1` 检查保留 | ✅ |
| 6 | **单独 `restart core` 导致控制台彻底不可达** | **运维陷阱** | 容器全 `Up`、端口 HTTP 000；日志无异常 | 新增 `scripts/shen.sh restart`（整栈重建）+ 运行手册故障表 + 验证文档 §4 | ✅ 已修并记录 |
| 7 | 示例规则太少使验证很浅 | 覆盖不足 | 初版 33 条里绝大多数只能"观察" | 示例规则扩到 16 条并同步期望值 | ✅ |
