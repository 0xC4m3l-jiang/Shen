## 1. 需求与验收（PRD 段）

**要解决什么**：开发循环（`AGENTS.md` §4）已经规定了四段，但**产物形状靠人记**：
代码写完再补文档就对不上，事后想复核「这轮改了什么、验证过没有」只能翻历史。

**做完之后，用户能做什么**：
1. 每轮结束只看两处就知道结果：`docs/Log.md`（一轮一条）与 `docs/plans/<日期>-<主题>.md`（变更包）；
2. 文档与代码漂移、规则 ID 写错、模块缺测试 —— `make gate` 当场报出来；
3. 明确"这一轮算不算做完"：变更包五段 + 门禁 + `make dev` 的证据行。

**验收判据**：

| # | 判据 | 证据形式 |
| --- | --- | --- |
| 1 | `make trace` 零错误（提示与登记豁免单独列出） | `make trace` 输出 |
| 2 | 引用不存在的规则 ID → 报 `D-3` 并给出 `文件:行` | 注入实验 |
| 3 | 模块有代码没文档 → 报 `MD-17` | 注入实验 |
| 4 | 模块有代码没单测 → 报 `MD-22` | 注入实验 |
| 5 | 变更日志最新条目缺段 → 报 `DEV-2`；引用不存在的路径 → 报 `DEV-2` | 注入实验 |
| 6 | 豁免过期（检查又通过但 allow.txt 还留着）→ 报 `ALLOW` | 注入实验 |
| 7 | `make gate` 包含 `trace`，全绿 | 门禁输出 |

**不做什么**：

- 不做「153 条规则逐条映射到代码」的全量矩阵（成本高，本轮只做模块级 + 引用存在性）；
- 不校验测试的真实覆盖面（那属于覆盖率与场景表，机器查不了「测得好不好」）；
- 不改任何 `docs/design/` 内容（本轮是流程与工具，不动基线规则）；
- 不引入新依赖。

## 2. 设计逻辑（技术设计段）

**决策树**：

```text
开发循环
├── Q1 用什么承载 ────────► 技能 + 机器校验 + 模板（三件套）
├── Q2 产物住哪 ──────────► 复用 docs/plans（变更包）+ 另建 docs/Log.md（变更日志）
├── Q3 查到多细 ──────────► 模块级四向对应 + 规则 ID 存在性
├── Q4 拦不拦门禁 ────────► 进 make gate（缺口靠 allow.txt 显式登记）
└── Q5 证据存多细 ────────► 贴关键行 + 场景表（场景/期望/实测/证据）
```

**已确认的决策**：

| # | 问题 | 决定 | 理由 | 落地位置 |
| --- | --- | --- | --- | --- |
| ① | 承载 | 技能 + 机器校验 + 模板 | 方法论管人、门禁管机器、模板管形状，缺一样就退回靠记 | `.pi/skills/dev-loop/` · `scripts/tracecheck/` · `docs/plans/_change-package.md` |
| ② | 产物位置 | 变更包复用 `docs/plans/`；**另建** `docs/Log.md` | 不新增目录层（`AGENTS.md` §1 分层是强约束）；日志给「事后复核」一个固定入口 | `docs/plans/<日期>-<主题>.md` · `docs/Log.md` |
| ③ | 追溯粒度 | 模块级四向对应 + 规则 ID 引用存在性 | 规则 ID 级全量映射要先补 153 条历史映射，收益低于成本 | `scripts/tracecheck/main.go` |
| ④ | 门禁 | `trace` 进 `make gate`；缺口写 `allow.txt` 且**过期即报** | 与「不绿不算完成」一致；豁免不许腐烂 | `Makefile` · `scripts/tracecheck/allow.txt` |
| ⑤ | 证据 | 变更包内贴「场景 → 期望 → 实测 → 证据」表 + 门禁/`make dev` 关键行 | 能反驳「跑了吗」，又不把仓库变成日志堆 | `_change-package.md` §5/§6 |
| ⑥ | 访谈规范 | 每轮固定用 `grill_deck` 一次问完整个前沿（非交互退化为 markdown + 推荐答案） | 前沿没问完就动手，返工从第一个决定开始 | `.pi/skills/dev-loop/SKILL.md` ① |
| ⑦ | 输出形状 | 结论先行 · 编号 · 禁止开场白/收尾 · 一组 ≤5 项 · 报错给原因与下一步 | 供人快速扫读与复核 | 同上「输出形状」段 |

**仍未定**：

| # | 未决 | 阻塞什么 | 去向 |
| --- | --- | --- | --- |
| 1 | 是否升级到规则 ID 级全量映射 | 更细的追溯 | 若某轮出现「改了判定规则却找不到测试」再评估 |
| 2 | `structure.md` §1.4 的三文件约定是否升格为规则（现为提示 `TC-1`） | `edge/mirror/` 是否要补 `iface.go` | 需用户确认升格（`AGENTS.md` §3.1） |
| 3 | 变更包的机器校验深度（现只核存在性与日志形状） | 更强的门禁 | 观察几轮后再定 |

**接缝与接口**：`scripts/tracecheck` 读文档（`docs/design/modules.md` §1.1、`docs/design/README.md`、`docs/Log.md`）——
**清单从文档解析，不硬编码**（与 `archcheck` 同规矩）；解析结果异常即报错退出。
豁免文件 `allow.txt` 是唯一的人工输入，且必须带理由。

**数据流（含失败路径）**：

```text
docs/design/README.md ──► 规则前缀表
docs/design/*.md ──────► 已定义规则 ID（加粗定义）
docs/design/README.md ──► 已废弃/旧编号登记（§4.1 / §4.1.1）
docs/design/modules.md ─► 模块 ↔ 源码目录 ↔ 模块文档
                              │
全仓 *.md + AGENTS.md ────────┼─► 规则 ID 引用 ──✗──► D-3「引用不存在的 ID」+ 文件:行
有代码的模块目录 ─────────────┼─► 文档九章 ──✗──► MD-2 / MD-17
                              ├─► 单测文件 ──✗──► MD-22
                              └─► iface.go ──✗──► TC-1（提示，不拦）
docs/Log.md 最新条目 ─────────┴─► 四段标记 + make gate + 路径存在 ──✗──► DEV-2
                                                  │
                                          allow.txt 命中 ──► 打印豁免；未命中 ──► ALLOW「豁免过期」
```

## 9. 后续追加：技能强制写进 `AGENTS.md`（2026-09-18）

**为什么要追这一节**：§1 的验收判据只保证「门禁能查」，没保证「开发时真的会加载技能」。
用户指出：如果 `AGENTS.md` 不写明，AI 开发时可能拿不到或不用这套流程 —— 工程化就落不了地。

**本节的决定**：

| # | 决定 | 落地位置 |
| --- | --- | --- |
| ⑧ | **开工前必须加载 `dev-loop` 技能**；未加载即视为流程未执行，该轮不算完成 | [`AGENTS.md`](../../AGENTS.md) §4（强制条款） |
| ⑨ | `AGENTS.md` 内置**技能路由表**：强制 2 个（`dev-loop` · `spec-first-dev`）+ 按需 5 个（`design-decision` · `threat-model` · `adversarial-benchmark` · `research-survey` · `skill-creator`），每个写清「何时用 / 产物」 | 同上 |
| ⑩ | 新增门禁检查 `DEV-3`：`AGENTS.md` 点名的技能文件**必须存在**且有 `name` / `description` 头；`dev-loop` 与 `spec-first-dev` **必须被点名** | [`scripts/tracecheck/main.go`](../../scripts/tracecheck/main.go) |

**新增注入实验**（真实执行）：

```console

✗ DEV-3  AGENTS.md 点名的技能文件不存在（技能被改名或删除，而规范还指着它）
✗ DEV-3  AGENTS.md 没有点名这个强制技能 —— 没写进规范就等于没强制

# 技能文件把 `name:` 改成别的键
✗ DEV-3  技能文件缺 YAML 头部（name / description）—— 缺了就不会被正确触发
```

**边界**：`DEV-3` 只能核「点名的技能存在 + 强制的被点名」，
**核不了**「有没有真的按五步走」—— 后者靠变更包与 `docs/Log.md` 留痕事后复核。
