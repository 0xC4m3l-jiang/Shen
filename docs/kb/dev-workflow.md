# 开发规范与链路（学习用图）

> **性质**：知识库材料（非规范）。规范本体在 [`../../AGENTS.md`](../../AGENTS.md)、
> 全局技能 `~/.pi/agent/skills/dev-loop/SKILL.md` 与 `~/.pi/agent/skills/audit/SKILL.md`。
> 本文件的图只是帮助理解**它们怎么串起来**。
>
> 读完的收益：知道开工先做什么、一次改动要留哪些东西、门禁替你核了什么、出问题往回退到哪一步。

## 1. 三层结构：谁管什么

```text
┌─ 系统层  ~/.pi/agent/ ────────────────────────── 对所有项目生效 ────────┐
│                                                                         │
│  AGENTS.md            三条铁律（每次都进上下文，极短）                  │
│                       · 先规格后代码 · 不绿不算完成 · 可追溯            │
│                                                                         │
│  skills/dev-loop/     通用规范：S/M/L 分级 · 五步 · 产物形状            │
│                       · 追溯接口 · 评审 · 返工路径                      │
│    ├─ assets/         4 份模板（适配面/变更包/日志/AGENTS 片段）        │
│    └─ scripts/        devloop-init.sh（在任意项目落地骨架）             │
│                                                                         │
│  skills/audit/        审视：漂移 / 无用信息 / 僵尸内容                  │
│                       + 四道删除门槛                                    │
└───────────────────────────────┬─────────────────────────────────────────┘
                                │ 项目用 .pi/devloop.md 声明自己的差异
                                ▼
┌─ 项目层  Shen/ ─────────────────────────────────────────────────────────┐
│                                                                         │
│  AGENTS.md        项目强制规范（**最优先**，与全局冲突时以它为准）      │
│  .pi/devloop.md   **适配面**：文档路径 / 验证命令 / 依据在哪            │
│  .pi/skills/      3 个技能（全部自建 Markdown）                         │
│                   dev-loop-project · evidence-and-decisions             │
│                   · threat-model                                        │
│  docs/log.md      变更日志（每轮一条，最新在上）                        │
│  docs/plans/      变更包（含追溯矩阵 §3 与审视记录 §7.1）               │
└───────────────────────────────┬─────────────────────────────────────────┘
                                │ 项目自建工具（规范只规定接口）
                                ▼
┌─ 工具层  make / scripts ────────────────────────────────────────────────┐
│                                                                         │
│  make gate    一轮的验收命令 = 静态检查 + 架构 + **追溯** + 许可 + 单测 │
│  make dev     效果验证：配置干跑 → 起核心 → 冒烟 → 规则回放             │
│  scripts/tracecheck/   6 类检查 + allow.txt 显式豁免（过期即报）        │
└─────────────────────────────────────────────────────────────────────────┘
```

**一句话**：规范在系统层（跨项目）、差异在项目层（一行配置）、核验在工具层（项目自己的命令）。

## 2. 一轮开发的链路（时序）

```text
⓪ 分级：S（单点）/ M（模块级）/ L（决策级）—— 决定走多少
        │
        ▼
① 访谈   整轮前沿一次问完（grill_deck / markdown + 推荐答案）
         · 事实自己查，别问用户    · 声明「不做什么」
         · 未达成共识 → 停在这里，不动代码
        │
        ▼
② 定稿   决策（用户确认才成规则）· 取舍 → ADR · 契约 → spec
         · 文档先于代码    · 产出变更包（docs/plans/YYYY-MM-DD-主题.md）
        │
        ▼
③ 开发   范围声明（要改 / 不改 / 已注意到）→ 最小实现
         · 不加未要求的依赖、接口、配置项
        │
        ▼
④ 验证   make gate → make dev → 证据表 → 独立评审（M/L，冷上下文）
        │
        ▼
⑤ 记录   变更包回填（追溯矩阵 §3 · 证据 §6）· docs/log.md 追加一条
        │
        ▼
⑥ 审视   audit（仅 L 档）：修不准 / 删无用 / 标废弃
         · 四道门槛：无引用 · 非对外契约 · 非历史记录 · 记录在案
         · 结果写进变更包 §7.1
        │
        ▼
⑦ 提交   make done MSG="…"   ← 门禁 → 提交 → 校验工作区干净（一条命令）
         · 没有提交就没有回退点：本轮改错 = 一条 git 命令的事
        │
        └──► 下一轮 ①
```

**卡住时往回退**（见 §6）：门禁红 → 判断是代码错还是检查错；前提被证伪 → 回到 ①。

## 3. 门禁链路：`make gate` 替你核了什么

```text
make gate
├─ fmt-check      格式化（gofmt -l，不改文件）
├─ vet            go vet ./...
├─ staticcheck    固定版本工具（未安装 → 失败，不跳过）
├─ errcheck       未处理的错误返回值
├─ archcheck      顶层目录 · 跨平面依赖 · 模块清单 · store 唯一 I/O 出口 · CGO · 语言层数
├─ trace          六类检查：
│                   ① 模块文档 ↔ 代码 ↔ 单测       (MD-2 / MD-17 / MD-22)
│                   ② 规则 ID 引用真实存在         (D-3 / D-8)
│                   ③ 变更包与变更日志的形状        (DEV-1 / DEV-2)
│                   ④ AGENTS.md 点名的技能存在      (DEV-3，含全局技能)
│                   ⑤ 过期状态标记（「待建」但已有） (TC-2)
│                   ⑥ 悬空链接（相对路径 / ~/）     (TC-3)
│                   错误 → 拦 ｜ 提示（未升格为规则的约定）→ 只打印
│                   已知缺口 → allow.txt 显式登记；豁免过期也报
├─ leakcheck      可观测面泄漏扫描（OH-1 / OH-3）：
│                   扫描响应面模块的**字符串字面量** ↔ OH-1 禁用清单；
│                   查响应头/ Cookie 名 ↔ OH-5（决策与分数禁止回传）；
│                   豁免三类：规则级（内部日志·错误串·struct tag）· 文件级
│                   （`//check-leak:filter <理由>`，如 AR-22 黑名单表）· 逐条（allow.txt）
├─ licensecheck   许可审计（拦 AGPL / SSPL / BUSL）
└─ test -race     全部单测（含数据竞争检测）
        │
        └─► 任一失败 = 这一轮没完成（不得声称完成、不得注释检查）
```

## 4. 追溯链路：一根线追回去

```text
   需求 / 规则                文档                    代码                 测试              证据
 ┌──────────────┐      ┌──────────────┐      ┌──────────────┐     ┌────────────┐    ┌──────────────┐
 │ AR-13 版本化 │─────►│ modules/     │─────►│ policy.go    │────►│ policy_    │───►│ make dev     │
 │ MD-17 文档先行│      │ policy.md §1 │      │ Publish()    │     │ test.go    │    │ 输出行      │
 └──────────────┘      └──────────────┘      └──────────────┘     └────────────┘    └──────────────┘
        │                     │                     │                   │                 │
        └─────────────────────┴─────────────────────┴───────────────────┴─────────────────┘
                                    这四跳由 make trace 核「存在与对应」
                                    最后一跳由人核：证据是否真的证明了期望
```

**写不出的格子就是问题**：

| 写不出 | 说明 | 处理 |
| --- | --- | --- |
| 规则/需求编号 | 改动没有依据 | 回到 ① 访谈，或写进「遗留」 |
| 文档章节 | 实现没有文档 | 文档先于代码（`MD-17`），补写 |
| 测试 | 这条需求没验 | 补测试，或明写「未覆盖」 |
| 证据 | 「我说测过了」 | 贴命令与输出行，否则不算验 |

## 5. 技能路由：什么时候加载哪个

**全景（全机 5 个：全局 2 + 项目 3，全部纯 Markdown）**：

```text
┌─ 全局  ~/.pi/agent/skills/ ───────────────────────────────────────────┐
│  dev-loop              通用流程：S/M/L 分级 · 五步 · 产物形状         │
│                        · 追溯接口 · 评审 · 返工路径                   │
│  audit                 审视：漂移 / 无用 / 僵尸 + 四道删除门槛        │
└──────────────────────────────┬────────────────────────────────────────┘
                               │ 项目只补差异，不重写规范
┌─ 项目  .pi/skills/ ──────────▼────────────────────────────────────────┐
│  dev-loop-project      实例化 + 开工纪律                              │
│                        开工门禁四查 · 范围声明 · 最小实现 · 追溯行为  │
│  evidence-and-decisions 三段：调研 → 决策(ADR) → 对抗基准             │
│                        证据分级 A/B/C · 失效条件 · 对照组 · 可复现包  │
│  threat-model          资产 · 对手分档 · 失效路径 · 识破路径表        │
└───────────────────────────────────────────────────────────────────────┘
```

**路由（何时加载哪个）**：

```text
开工 ──► dev-loop（全局，强制）+ dev-loop-project（本项目实例化，强制）
              │
              ├─ 动代码前 ──────────► dev-loop-project §1/§2   产物：开工门禁四查 + 范围声明
              ├─ 要调研 / 找依据 ──┐
              ├─ 出现真实取舍 ──────┤─► evidence-and-decisions  产物：证据分级材料 / ADR / 基准包
              ├─ 要声称「有效」 ────┘
              ├─ 改安全相关路径 ────► threat-model            产物：资产/对手/失效路径 · 识破路径表
              └─ L 档收尾 ──────────► audit                   产物：审视表
```

> **合并口径**：一个技能 = **一类触发面**，不是「一个动作」也不是「一个主题」。
> 所以「开工纪律」进了实例化技能（同一个触发面），而「调研 / 决策 / 基准」合成一个（同一条链），
> `threat-model` 则单独留着（安全评审是另一类触发）。合并/移除记录见 [`known-issues.md（H-1）`](known-issues.md（H-1）)。
>
> 项目技能名带 `-project` 后缀不是审美问题：pi 遇到同名技能会**保留先加载的**
> （全局先于项目），两个都叫 `dev-loop` 时，项目那份永远不会生效。

## 6. 失败与返工路径

```text
┌─ 门禁红了 ──────────────┐   ┌─ 前提被证伪 ──────────┐   ┌─ 需要临时放宽 ──────┐
│ 先判断：代码错 / 检查错 │   │ 停下，不要闷头改代码  │   │ 写进 allow.txt      │
│ 代码错 → 修代码         │   │ 回到 ① 访谈           │   │ 写清理由 + 到期条件 │
│ 检查错 → 改检查并说明   │   │ 决策记录走「重开」    │   │ 日志里点名          │
│ 禁止：注释掉检查        │   │ 保留原记录 + 失效条件 │   │ 过期会被门禁报出来  │
└─────────────────────────┘   └───────────────────────┘   └─────────────────────┘

做完发现做错了 → **不改历史记录**：变更包追加「修正」小节 + 日志追加一条修正条目
```

## 8. 常见误解

| 误解 | 实际 |
| --- | --- |
| 「规范是建议」 | 全局 `AGENTS.md` 写的是**必须**；项目的更优先。不按分级走完 = 这一轮不算完成 |
| 「文档后补也一样」 | 补出来的文档通常与实现对不上；模块/组件文档**必须先于**实现 |
| 「改了再说」 | 决策未经用户确认不得升格进规范层；Agent 不得自行升格 |
| 「门禁过了就没事」 | 门禁只核**形状与存在性**：语义是否一致、内容是否真无用，仍靠人读（技能 `audit`） |
| 「历史记录过时了可以删」 | 决策记录 / 变更日志 / 废弃登记是**当时的快照**，过时是正常的，**保留并标废弃**，禁止删 |
| 「清理顺便重构」 | 审视只做三件事：修不准 / 删无用 / 标废弃。重构是另一个改动，另开一轮 |

## 9. 三分钟上手

```sh
# 1. 开工前：读三份（顺序不能反）
#    AGENTS.md（项目强制）→ .pi/devloop.md（适配面）→ 全局技能 dev-loop（流程）

# 2. 判断改动分级（S / M / L），按该档的必做项走

# 3. 验收入口（一轮做完的定义）
make gate    # 静态检查 + 架构 + 追溯 + 许可 + 单测(-race)
make dev     # 效果验证：配置干跑 → 起核心 → 冒烟 → 规则回放

# 4. 快速内循环（不想等全量门禁时）
make check   # 构建 + 格式化 + vet + 架构 + 追溯
make replay  # 规则回放：样本 → 分数 → 命中信号
make smoke   # 在线冒烟：判定面形状 + decision_id 幂等

# 5. 收尾（L 档）：audit 审视 → 变更包 §7.1 + docs/log.md 追加一条

# 6. 在别的项目启用同一套规范
bash ~/.pi/agent/skills/dev-loop/scripts/devloop-init.sh /path/to/project
```

## 环境与产物放在哪 / 怎么起环境

**这两件事的权威在运行手册**，本文件不再重复（避免两处维护）：

| 我要… | 去哪 |
| --- | --- |
| 看某个东西（Python 环境 / 门禁二进制 / Go 依赖副本 / 容器定义）放在哪 | [`../ops/runbook.md`](../ops/runbook.md) §5「产物卫生」 |
| 起环境（Docker 一键 / 本地进程）与端口、日志命令 | [`../ops/runbook.md`](../ops/runbook.md) §1「启动」 |
| 只想知道"改了代码之后怎么重建" | [`../ops/runbook.md`](../ops/runbook.md) §4「更新」 |

> 一句话版：容器与本地产物**都不落仓库**（统一落临时目录），改了代码必须 `scripts/shen.sh restart`（带 `--build`），
> 日志默认**不跟随**（`make docker-log S=core`）。
