# docs/kb —— 功能知识库

> **本目录不具约束力。** 它是沉淀：FAQ、已知问题、踩坑、经验。
> 可随时增改，**允许不确定**。规则请写进 [`../design/`](../design/README.md)。

| 文件 | 放什么 |
| --- | --- |
| [`faq.md`](faq.md) | 高频问题：这个项目为什么这么设计、东西在哪、怎么改 |
| [`known-issues.md`](known-issues.md) | 踩过的坑：症状 → 原因 → 结论 |
| [`dev-workflow.md`](dev-workflow.md) | 开发规范与链路图（三层结构 · 一轮时序 · 门禁 · 追溯 · 技能路由） |
| [`removed-skills.md`](removed-skills.md) | 已移除的技能：为什么删 · 怎么恢复（技能 `audit` 门槛 ④ 的登记处） |

## 与相邻目录的区别

| 目录 | 区别 |
| --- | --- |
| [`../design/`](../design/README.md) | **必须遵守**的规则。知识库是参考，**不具约束力** |
| [`../spec/logs.md`](../spec/) | 字段的**权威字典**（类型 / 含义 / 敏感级 / 保留期）。知识库不承担这个职责 |
| [`../background/decisions/`](../background/decisions/README.md) | 决策的**理由**与失效条件。知识库只记「怎么做」，不记「为什么拍这个板」 |

## 怎么写一条

**已知问题**必须写清三样，缺一样就没用：

1. **症状** —— 你看到什么（报错原文、截图描述）
2. **原因** —— 为什么会这样
3. **结论** —— 现在怎么做

**不写**「以后可能需要注意」这类没有动作的话。
