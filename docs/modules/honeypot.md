## 1. 职责

**做什么**：

- **后端池**：维护「逻辑后端名 → 具体蜜罐实例」的映射，供 `director` 的 `route_mirage` 使用；
- **类型注册**：蜜罐类型是一个**声明式清单**，每种类型有「是否启用」的配置开关；
- **生命周期**：启动 / 停止 / 健康 / 资源上限，承载 `MD-14` / `MD-15` / `MD-16` 的进程纪律；
- **管理接口**：供 `console` 查看与维护蜜罐状态（后续）；
- **接入契约**：定义蜜罐必须满足的最小契约（承接流量 + 事件回传），使自研与第三方实现可互换。

**明确不做什么**：

- **不实现任何具体蜜罐** —— 不写协议仿真、不写命令表、不写假文件系统（[ADR-0011](../background/decisions/0011-honeypot-entry-external-backends.md)）；
- **不做判定**（`AR-2`）与**不做决策**（`MD-12`）；
- **不主动连接任何目标** —— 它只承接已被 `route_mirage` 送来的流量（`SB-6`）。

### 蜜罐类型清单（配置可开关；本设计只登记，不实现）

| 类型 | 仿真对象 | 默认 |
| --- | --- | --- |
| `ssh` | 交互式 SSH 假主机 | off |
| `mysql` | MySQL 握手 + 查询捕获 | off |
| `redis` | Redis 命令级仿真 | off |
| `ftp` | FTP 登录 + 目录列举 | off |
| `elasticsearch` | HTTP 形态 API 仿真 | off |
| `nginx-admin` | 假登录控制台 | off |
| `web-clone` | Web 应用克隆（自包含） | off |
| `internal-wiki` | 内网 wiki 假站点 | off |
| `database` | 内网数据库假实例 | off |

> 默认全部 **off**：蜜罐是幻境后端，只有在明确配置、且完成影子模式观察后才启用（`INT-11`）。
> 新增类型 = 加一项配置 + 提供一个满足契约的后端，**不改代码**。

## 2. 输入 / 输出契约

跨模块与对外的契约不在这里（`MD-3`），只引用：

| 方向 | 契约 | 定义位置 |
| --- | --- | --- |
| 输入 | 蜜罐配置（类型 / 开关 / 地址 / 上限） | [`../spec/config.md`](../spec/config.md) 的 `honeypots` 段 |
| 输入 | `route_mirage` 的逻辑后端名 | `contract.Decision.Backend`（[`../design/structure.md`](../design/structure.md) §2） |
| 输出 | 后端池解析结果（逻辑名 → 实例） | `../spec/honeypot.md`（待建） |
| 输出 | 蜜罐接入契约 | 同上 |

本模块内部数据结构：`Backend`（蜜罐实例）、`TypeSpec`（类型声明）、`Pool`（后端池）。

## 3. 依赖

| 允许依赖 | 原因 |
| --- | --- |
| `contract` | 进程内共享类型 |

| 禁止依赖 | 原因 |

> 规则 `MD-6`：核心模块禁止外呼、禁止写业务存储、禁止依赖系统时钟做判定。

## 4. 关键规则

| 规则 | 与本模块的关系 |
| --- | --- |
| `MD-26` | 蜜罐**必须**经本模块管理；具体实现**禁止**编译进核心 |
| `MD-14` | 蜜罐子进程**必须**按进程组回收、双层超时 |
| `MD-15` | 蜜罐资源创建与释放**必须**对称 |
| `MD-16` | 蜜罐并发连接数与线程数**必须**设上限 |
| `NI-7` | 蜜罐**必须**受 cgroup CPU / 内存上限约束 |
| `NI-10` | 蜜罐不可达时**必须**回落放行，**禁止**阻断业务 |
| `AR-9` | 核心无状态多副本；后端池状态**必须**外置 |
| `SB-6` | 本模块**禁止**主动连接目标 —— 只承接 `route_mirage` 送来的流量 |
| `SB-8` | 抓取 / 克隆类能力**必须**配置目标白名单，私网与云元数据默认阻断 |
| `ST-24` | 蜜罐类型与开关是**数据**（配置），不是编译进代码的分支 |

## 5. 状态与生命周期

| 状态 | 存在哪里 | 生命周期 | 多副本一致性 |
| --- | --- | --- | --- |
| 后端池定义 | PostgreSQL（`honeypot` 实体，见 [`../design/structure.md`](../design/structure.md) §3） | 长期 | 强一致（经 `store`） |
| 健康状态 | Redis（TTL）+ PostgreSQL（审计） | 短 TTL | 最终一致 |
| 蜜罐实例 | 进程外（第三方或 `honeypot-protocol`） | 由本模块编排 | 各自独立 |

> 规则 `AR-9`：核心无状态多副本；本模块不持有蜜罐实例的运行状态，只持有**编排意图**。

## 6. 失败模式与降级

| 失败情形 | 行为 | 是否满足 `NI-1` | 依据 |
| --- | --- | --- | --- |
| 蜜罐不可达 | `route_mirage` 回落真实业务（适配器侧已实现） | ✅ | `NI-5` |
| 后端池为空 | `route_mirage` 一律回落业务；启动日志点名 | ✅ | `NI-5` |
| 蜜罐启动超时 | 标记 unhealthy，不加入池；**禁止**让核心启动失败 | ✅ | `NI-1` |
| 蜜罐资源超限 | 按 `MD-16` 拒绝新连接并记录 | ✅ | `NI-7` |
| 蜜罐子进程挂死 | 按 `MD-14` 进程组回收 + 双层超时 | ✅ | `MD-14` |
