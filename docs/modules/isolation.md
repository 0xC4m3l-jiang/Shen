## 1. 职责

**做什么**：

- **隔离记录写入**：把被隔离的来源（会话 / IP）连同理由与到期时间写入；
- **TTL 过期**：到期自动解除（不依赖人工）；
- **查询短路**：适配器在判定前先查隔离名单，命中则**不再调用核心**（省一次往返）。

**明确不做什么**：

- **不做判定**（`AR-2`）—— 隔离状态由 `judge` / `director` 的结论决定，本模块只**记录与查询**；
- **不做决策**（`MD-12`）；
- **不引入可见处置** —— 命中隔离**只让后续请求不再问核心**，客户端**不可见**（与 `challenge` 不同，见 [ADR-0002](../background/decisions/0002-decision-model.md)）。

## 4. 关键规则

| 规则 | 与本模块的关系 |
| --- | --- |
| `NI-10` | **隔离名单读不到时**：回退调用核心判定（fail-open），**禁止**阻断业务；**必须**告警 |
| `AR-9` | 状态**必须**外置（核心无状态多副本） |
| `MD-20` | 访问存储**必须**经 `store` |
| `NI-4` | 查询**必须**有超时；超时即视为未命中（回退核心判定） |
| `NI-5` | 任何不确定状态回落放行 |
| `NI-13` | 隔离记录按类别配置保留 |

## 5. 状态与生命周期

| 状态 | 存在哪里 | 生命周期 | 多副本一致性 |
| --- | --- | --- | --- |
| 隔离生效 | `store`（Redis，TTL） | 到期自动解除 | 最终一致（外置） |
| 隔离审计 | `store`（PostgreSQL） | 按保留策略 | 强一致 |

> 规则 `AR-9`：核心无状态多副本；隔离状态**必须**外置，**禁止**进程内名单。

## 6. 失败模式与降级

| 失败情形 | 行为 | 是否满足 `NI-1` | 依据 |
| --- | --- | --- | --- |
| 隔离名单读不到 | 回退调用核心判定（fail-open），不阻断 | ✅ | `NI-10` |
| 查询超时 | 视为未命中，回退核心判定 | ✅ | `NI-4` |
| 写入失败 | 记录告警；不阻断业务 | ✅ | `NI-1` |
