## 1. 职责

**做什么**：

- **投毒响应改写**：按**注入规则**改写响应（改道侧）——规则是**数据**（`ST-24`），
  由核心配置 `injects` 持有、经策略面下发给适配器（见 [`../spec/policy-payload.md`](../spec/policy-payload.md)），本模块只负责执行；
- **假路径注入**：把诱饵路径/链接注入页面（HTML 注释、隐藏元素、可见 Developer API 页脚）；
- **蜜饵注入**：投放 API 路由蜜饵、凭证蜜饵、文件蜜饵的入口。

**明确不做什么**：

- **不实现判定**（`AR-2` / `MD-9`）· **不做决策**（`MD-12`）· **不做 LLM 推理**（`AR-7`）；
- **不维护会话状态**（`AR-7`）· **不写核心状态**（`AR-7`）；
- **不改写业务侧响应** —— 改写**只能**作用于蜜罐侧（`INT-8`）；
- **不独立部署** —— 被适配器引用（`ST-5`）。

## 2. 输入 / 输出契约

| 方向 | 契约 | 定义位置 |
| --- | --- | --- |
| 输入 | **注入规则**（`kind` / `snippet` / `marker`） | 核心配置 `injects`（[`../spec/config.md`](../spec/config.md) §2.12）→ 策略面 `inject_rules`（[`../spec/policy-payload.md`](../spec/policy-payload.md)） |
| 输入 | 诱饵定义（来自 `decoy`，用于假路径/钩子内容） | [`../modules/decoy.md`](decoy.md) |
| 输入 | 决策（来自 `director`，经适配器） | `common/api/judge/v1` |
| 输出 | 改写后的响应（仅蜜罐侧） | —— |

## 4. 关键规则

| 规则 | 与本模块的关系 |
| --- | --- |
| `AR-6` / `AR-7` | 适配器只做四件事；本模块只做「执行处置」这一件 |
| `MD-9` | 适配器边界：不判定 / 不推理 / 不持状态 / 不写核心状态 |
| `MD-10` | **禁止**持有跨请求业务状态 |
| `MD-11` | **禁止**阻塞调用 |
| `ST-5` | **禁止**独立部署，必须作为适配器内模块被引用 |
| `INT-8` | 响应改写**只能**作用于蜜罐侧 |
| `NI-9` | **禁止**新增客户端可见的 Cookie 或响应头 |
| `OH-1` / `OH-5` | 注入内容**禁止**含禁用串；**禁止**回显判定信息 |
| `MD-23` | 不得产生可归因于防御行为的信号 |

## 6. 失败模式与降级

| 失败情形 | 行为 | 是否满足 `NI-1` | 依据 |
| --- | --- | --- | --- |
| 改写失败 | **透传原响应**（不改写，不阻断） | ✅ | `NI-1` |
| 诱饵定义缺失 | 不注入该诱饵 | ✅ | `NI-5` |
| 内容黑名单命中 | 丢弃该内容 | ✅ | `AR-22` |
