## 1. 职责

**做什么**：

- 管理**诱饵资产**的全生命周期：定义 → 投放 → 绑定 → 回收/轮换；
- 提供**五类诱饵面**（依据 [ADR-0010](../background/decisions/0010-functional-camouflage.md)）：

  | # | 诱饵面 | 伪装成什么 | 交互语义 |
  | --- | --- | --- | --- |
  | 1 | **Developer API 诱饵** | 站点公开的开发者接口 | 注册 → 心跳 → 领任务（功能性伪装核心） |
  | 2 | **指令文件蜜饵** | 项目级信任入口（`AGENTS.md` / `CLAUDE.md` / `.cursorrules`） | Agent 自动读取即命中 |
  | 3 | **MCP 诱饵** | JSON-RPC 工具服务（`query_db` / `run_diag`） | 调用工具即命中 |
  | 4 | **消耗战数据集** | 无限分页的假数据（逐行水印） | 持续抓取 → 高交互成本 |
  | 5 | **三类蜜饵 + SSRF 蜜饵** | API 路由 / 凭证 / 文件 / 云元数据 | 命中即自动化证据 |

- 产出**投放片段**（JS 片段 / nginx location / SQL INSERT / 文档建议），让诱饵能真正被投放；
- 产出**诱饵内容定义**（假数据形状），由 `responder` 生成具体内容；
- **诱饵多态**（[ADR-0016](../background/decisions/0016-decoy-polymorphism.md)）：标识（文件名 / 凭证形态 / API 路径 / 数据字段）
  按**会话或时间窗**轮换；**会话内冻结**（与 `AR-30` 划界），以对抗多 Agent 共享记忆的众包识破。

**明确不做什么**：

- **不做判定** —— 判定只在 `judge`（`AR-2`）；
- **不做决策** —— 去向由 `director` 决定（`MD-12`）；
- **不实现任何蜜罐** —— 那是 `honeypot` 模块与第三方后端（[ADR-0011](../background/decisions/0011-honeypot-entry-external-backends.md)）；
- **不在诱饵面上阻断** —— 诱饵面必须 observe-only（`MD-25`）；
- **不向第三方投递载荷或发起连接**（`SB-5` / `SB-6`）；
- **不伪造第三方品牌** —— 诱饵内容必须基于自有或已获书面授权的素材（`SB-3` / `SB-4`）。

## 2. 输入 / 输出契约

跨模块与对外的契约不在这里（`MD-3`），只引用：

| 方向 | 契约 | 定义位置 |
| --- | --- | --- |
| 输入 | 诱饵配置（类型 / 开关 / 投放位置） | [`../spec/config.md`](../spec/config.md) 的 `decoys` 段 |
| 输出 | 诱饵资产（路径 / 凭证 / 文件 / API 定义 / 指令文件 / MCP 工具） | `../spec/decoy.md`（待建） |
| 输出 | 投放片段 | 同上 |
| 输出 | 诱饵内容定义（供 `responder`） | 同上 |

本模块内部数据结构：`Asset`（诱饵资产）、`Placement`（投放片段）、`Binding`（蜜饵绑定链）。

> 规则 `MD-5`：跨模块共享类型收敛到 `contract` / `spec/`；本模块不定义与它同名的类型。

## 3. 依赖

| 允许依赖 | 原因 |
| --- | --- |
| `contract` | 进程内共享类型 |
| `store` | 诱饵资产与投放记录持久化（唯一 I/O 出口，`MD-20`） |
| `policy` 接口 | 读取诱饵开关与灰度的策略面 |

| 禁止依赖 | 原因 |
| --- | --- |
| `judge` / `director` | 依赖方向单向（`MD-4`）；诱饵面不参与判定与决策 |
| `honeypot` | 诱饵面与幻境后端是两个独立关注点 |
| 适配器（`modules/deception/`） | 适配器 → 核心单向；诱饵的**注入执行**在 `edge-injection` |

> 规则 `MD-6`：核心模块禁止外呼、禁止写业务存储、禁止依赖系统时钟做判定。

## 4. 关键规则

| 规则 | 与本模块的关系 |
| --- | --- |
| `AR-2` | 判定不在本模块；诱饵面不实现任何判定逻辑 |
| `MD-12` / `MD-13` | 本模块**禁止**产出或复制决策取值；诱饵面不决定去向 |
| `MD-20` | 诱饵资产的持久化**必须**经 `store` |
| `MD-25` | **诱饵面必须 observe-only** —— 集中常量（诱饵前缀集）在决策执行处统一豁免 `challenge`/`isolate`/`block` |
| `AR-30` | **一致性**：会话内同 `(会话, 资源)` 同答案；多态只在**会话边界**选择，会话内冻结（[ADR-0016](../background/decisions/0016-decoy-polymorphism.md)） |
| `NI-9` | 诱饵**禁止**引入新 cookie 或响应头 |
| `OH-1` / `OH-2` | 诱饵内容**禁止**含禁用串；判据是「会不会出现在攻击者屏幕上」 |
| `OH-5` | 诱饵**禁止**回传决策结果或分值 |
| `SB-3` / `SB-4` | 诱饵内容必须基于自有或书面授权素材；克隆能力须标注 |
| `SB-5` / `SB-6` | 禁止向第三方投递载荷或发起连接；本模块是被动组件 |
| `ST-22` | 话术/模板**必须**随代码分发，**禁止**存放于运行期可变存储 |
| `ST-24` | 诱饵类型与开关是**数据**（配置），不是编译进代码的分支 |

## 5. 状态与生命周期

| 状态 | 存在哪里 | 生命周期 | 多副本一致性 |
| --- | --- | --- | --- |
| 诱饵资产定义 | PostgreSQL（`decoy` 实体，见 [`../design/structure.md`](../design/structure.md) §3） | 长期；有轮换 | 强一致（经 `store`） |
| 投放记录 / 绑定链 | PostgreSQL（`decoy` + `chain_node`） | 长期 | 强一致 |
| 命中记录 | 事件流（`telemetry` → ClickHouse） | 按保留策略 | 最终一致 |

> 规则 `AR-9`：核心无状态多副本；诱饵资产**必须**外置到存储，进程内不持有。

## 6. 失败模式与降级

| 失败情形 | 行为 | 是否满足 `NI-1` | 依据 |
| --- | --- | --- | --- |
| 诱饵资产读不到 | 该诱饵面不投放，业务不受影响 | ✅ | `NI-5` |
| 诱饵内容生成失败 | 回落到静态兜底内容；**禁止**返回错误页顶替业务响应 | ✅ | `INT-8` |
| 诱饵被识破信号上报 | 记录并触发轮换（阶段 2b 后） | ✅ | `ADR-0010` |
| 诱导流量误伤正常用户 | 白名单 + 只对高置信改道；诱饵路径须「正常用户不会访问」 | ✅ | `INT-25` |
