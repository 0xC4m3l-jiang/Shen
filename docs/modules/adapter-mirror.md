## 1. 职责

### 做什么

- 接收被镜像过来的 HTTP 请求副本，转成判定请求发给核心。
- 把每次观测（含核心的判定结果）记为一条事件。

### 明确不做什么

- **不处置** —— 不改写响应、不改道、不阻断。
- **不在请求路径上** —— 因此它**不适用**依赖「引擎在路径上」的那批规则。
- **不实现判定逻辑** —— 只读取头与路径，不做任何判别。

## 2. 输入 / 输出契约

| 方向 | 契约 | 定义位置 |
| --- | --- | --- |
| 输入 | HTTP 请求（镜像副本） | 本模块的 `Receiver.ServeHTTP` |
| 输出 | `api/judge/v1` 的 `JudgeRequest` / `JudgeResponse` | `api/judge/v1/judge.proto` |
| 输出 | `api/telemetry/v1` 的 `TelemetryEvent` | `api/telemetry/v1/telemetry.proto` |

## 3. 依赖

| 允许依赖 | 原因 |
| --- | --- |
| `api/*` 生成的 stub | 跨进程契约是**唯一**允许的跨边界方式 |
| 标准库 `net/http` | 需要 HTTP 入口 |

| 禁止依赖 | 原因 |
| --- | --- |
| **`core/internal/*`** | 编译期强制：Go 的 `internal` 规则让本包无法 import 核心内部类型 |
| `contract` | 同上 —— 那是进程内类型，跨进程不该用 |

> 这条边界不是靠人工检查，是**编译器**保证的。

## 4. 关键规则

| 规则 | 与本模块的关系 |
| --- | --- |
| `INT-1` | 本模块实现接入形态① |
| `INT-6` | 镜像形态不适用失败放行、硬超时、熔断等在路径规则 |
| `ST-3` | 适配器禁止 import 核心内部包 —— 编译器强制 |
| `SB-5` / `SB-6` | 只消费副本，不主动连接任何目标 |
| `AR-6` / `AR-7` | 只做拦截 / 查缓存 / 处置 / 上报四件事；本形态不做处置 |

## 5. 状态与生命周期

| 状态 | 存在哪里 | 生命周期 | 多副本一致性 |
| --- | --- | --- | --- |
| 无 | —— | 每个副本独立处理 | 无状态，可随意扩容 |

## 6. 失败模式与降级

| 失败情形 | 行为 | 是否满足 `NI-1` | 依据 |
| --- | --- | --- | --- |
| 核心不可用或超时 | **仍返回 202**，并记一条"判定缺失"的事件 | ✅ | 本形态不在业务路径上，镜像源不受影响 |
| 请求体过大 | 只读前 64 KiB（可配），其余丢弃 | ✅ | 全量缓冲会拖垮大文件上传 |
| 遥测上报失败 | 忽略，不影响 202 | ✅ | 遥测不阻断 |
