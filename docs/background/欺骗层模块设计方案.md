# 欺骗层模块设计方案

> 主线：核心能力设计与实现。版本：0.1；日期：2026-09-21。
> 本文定义一个可独立开发的“受控线索生成与响应改写”模块，不定义网关、部署、路由或其他模块的实现。
> 接口为语言无关的设计伪代码，不是可直接运行的完整代码；能力与验收项为设计要求，不是已有测试结果。

## 1. 核心能力范围

**模块职责：接收响应快照与可信投放上下文，选择合适的合成线索，安全地产生改写结果，使客户端有机会自主发现一个可探索的资源。**

输入：不可变响应、请求元信息、可信作用域、已校验的策略与资源描述。

输出：完整的新响应或“不修改”的结果，以及本次处理的有限元数据。

| 能力 | 设计范围 | 不承担的能力 |
|---|---|---|
| 内容伪装 | 用模板呈现合成服务的名称、说明和可发现入口，保持同一模板版本的一致性 | 不改变真实业务身份，不假造真实泄露，不冒充第三方 |
| 自主发现诱导 | 增加非执行性的资源线索，客户端自行决定是否访问 | 不强制跳转，不劫持 Agent 指令，不建立控制通道 |
| 场景适配 | 根据获批响应类型、页面范围和资源类别选择模板 | 不自动抓取生产内容生成环境画像 |
| 安全响应改写 | 结构化插入、编码、大小检查、原子返回、失败不修改 | 不重写业务 API 契约或执行逻辑 |
| 关联标记 | 按活动或会话作用域生成不具生产权限的标记 | 不识别真实操作者，不把标记当认证凭据 |
| 处理观测 | 记录候选、跳过、完成改写、失败原因和开销 | 不声称客户端已收到、阅读或进入蜜罐 |

**行为模拟不属于本模块。** 本模块只有展示层的一致性，不保存虚拟文件系统、会话中的业务状态或多轮对话，也不生成对探测请求的持续响应。

### 1.1 首版能力与扩展点

- 首版：静态模板、完整 UTF-8 HTML 响应、每次至多插入一个线索片段、活动级标记、确定性选择、预览和解释。
- 后续可扩展：独立文档渲染、特定响应头、经验证的内容编码及会话级标记。
- 默认不支持：生产 JS/CSS 修改、生产 OpenAPI 增补、签名响应、流式改写和在线 LLM 生成。
- 一个扩展是否可用由适配器能力和策略共同决定，不能因为注册了适配器就自动启用全部响应类型。

## 2. 关键功能点与设计逻辑

### 2.1 策略编译与准入

使用 `compile` 将原始配置转换为不可变 `PolicySnapshot`，而不是每次请求解释任意配置脚本。

校验内容：

1. 模板、插入位置及资源引用均存在且版本明确。
2. 所有目标地址属于允许范围；只接受受支持的相对引用或 HTTPS 地址，禁止脚本 URI、协议相对地址、用户信息段和控制字符。相对引用必须依据可信的响应 URL 及文档实际基地址解析后再检查范围；无法可靠处理 `<base>` 时跳过，不能只检查原始路径字符串。
3. 正则或匹配表达式必须有复杂度边界，优先精确匹配和预编译规则。
4. 处理时限、最大输入/输出、最大新增字节、并发上限和配置有效期必须存在且有效。
5. 展示变量只能来自批准的合成字段，不读取任意请求头、Cookie、请求体或响应正文作为模板变量。

准入顺序为：**硬性安全限制 → 有效期与停用状态 → 范围匹配 → 可支持的表示 → 标记/缓存约束 → 采样与额度 → 模板选择**。普通规则不得覆盖硬性安全限制。

### 2.2 内容伪装与模板选择

一个模板只描述一种线索形态，例如“合成服务目录中的一个条目”，不包含可执行脚本、下载执行说明或改变 Agent 权限的指令。

- `ResourceDescriptor` 提供资源名称、合成摘要、固定入口、资源版本和允许显示的标签。
- `LureTemplate` 描述展示格式、允许变量、插入锚点、输出上限和内容类型。
- 使用固定版本及稳定选择键，让相同场景不随机切换身份、版本和入口。
- 线索不成为真实业务的必经步骤，不删除现有内容或制造认证失败以迫使客户端访问。
- 客户端可能忽略线索；模块不假设其会读取 HTML 注释、特定文件名或任何隐藏内容。

优先级相同的规则使用固定次序打破平局；`explain` 返回命中的规则、被排除项及原因，便于维护人员复现。

### 2.3 安全改写

首版只对完整、未压缩、UTF-8 的获批 HTML 表示做改写；其他情况返回 `Unchanged`，不临时解压或猜测字符集。

- 用支持源文本位置的 HTML tokenizer/parser 定位获批插入点，不用简单字符串替换匹配 `</body>`；缺少锚点、出现解析歧义时跳过。
- 用解析结果确定插入区间，保留其余源字节；不通过整页 DOM 重新序列化改变非目标区域。
- 文本与属性分别转义，模板生成的 URI 再做范围及 scheme 校验；新增片段中禁止事件属性、脚本节点和未经审核的外部资源。对原页面不做脚本清理或其他内容重写；无法安全插入时跳过。
- 读取输入但不原地修改；在有界候选缓冲中完成插入、验证和元数据调整，全部成功才返回新响应。
- 不修改状态码、业务 Cookie、认证信息、CSP、CORS 等安全字段；只允许处理改写必需的长度等表示元数据。
- 在返回之前检查取消、时限及资源预算；不返回部分响应，也不自行重试原业务请求。

`ResponseView` 中的头部必须是可保留多值的结构，不能用单值字典折叠多个 `Set-Cookie`。

### 2.4 表示兼容与缓存约束

| 条件 | 首版处理 |
|---|---|
| 非 GET、状态码非 200 | 不修改；特别不能向 HEAD、1xx、204、304 增加正文 |
| `Range` 或条件请求头存在 | 不修改；不参与范围和条件请求协商 |
| 请求或响应带 `no-transform` | 不修改 |
| 非完整正文、SSE/WebSocket/gRPC、附件 | 不修改 |
| 非 UTF-8、非 identity 内容编码、未知类型 | 不修改 |
| 响应带验证器、摘要、签名或可信上下文标记“完整性保护” | 首版不修改；不能通过删除保护字段来支持投放 |
| 内容超过限制或输出增长超预算 | 不修改，不分段插入 |
| 共享缓存表示 | 只允许稳定的活动级模板与活动级标记，不因用户风险或请求随机数改变内容 |
| 明确禁止共享存储的表示 | 可选会话级扩展；需要可信能力声明且响应满足规定的非共享缓存约束 |
| 缓存属性不明 | 不修改，不能仅根据 `Set-Cookie` 推断私有缓存 |

首版不实现改写表示的验证器，因此含 `ETag`、`Last-Modified` 等表示走保守跳过。未来支持时，应由专门的表示适配器处理一致的条件请求语义，而非在模板逻辑中零散删除字段。

活动级线索可按配置版本变化，但模块不负责清除旧缓存或收回已经返回的内容；`ResourceDescriptor.valid_until` 只能约束新生成，不能保证旧链接消失。

### 2.5 标记与去重

默认标记标识活动/资源，而不是某个人。需要会话标记时，仅使用可信的匿名作用域，不使用原始 IP、Cookie 或身份信息拼接 URL。

- 使用标准密码库提供随机标记或 HMAC；包含用途、版本、作用域和到期信息，密钥不进入模板。
- HMAC 防止未经授权构造有效标记，但不阻止转发和重放，也不提供身份归因。
- 对共享响应使用稳定标记；不把每请求唯一值放进共享缓存表示。
- 响应含本模块已经生成的片段时不重复插入。去重元信息应由可信调用上下文或可验证的内部标记确认，不能把任意外来 HTML 注释当作身份凭据。
- 相同输入、策略版本和选择键应得到相同模板；同一个 `operation_id` 的重复操作不能重复扣减投放额度。

### 2.6 预览、解释和额度

`preview` 执行完整候选渲染与校验，但使用预览专用标记，不占用正式额度、不产生正式处理事件，不签发可用于实际关联的令牌。

在线处理使用两类独立控制：

- 本地处理预算：输入、输出、新增字节、处理时限及并发。
- 生成次数配额：通过可替换的 `QuotaPort` 原子预留，按成功产出而非客户端送达计数；失败释放未消费额度。

本地配额实现只保证本实例；若要求多个实例共享上限，`QuotaPort` 实现必须提供对应作用域的原子性，模块不假定内存计数具有全局效力。

## 3. 内部实现机制与数据流

### 3.1 内部组件

| 组件 | 单一职责 |
|---|---|
| `PolicyCompiler` | 校验配置、编译匹配器与模板、产出不可变快照 |
| `EligibilityEvaluator` | 判断是否可处理，给出可解释的跳过原因 |
| `LureSelector` | 按版本、规则优先级和稳定选择键选一项线索 |
| `MarkerIssuer` | 产生限定用途的标记，不管理登录态 |
| `RepresentationAdapter` | 定位插入点、生成候选表示、处理必要元数据 |
| `OutputValidator` | 检查地址、编码、安全元素及输出边界 |
| `QuotaGuard` | 预留/完成/释放生成额度，限制并发与计算预算 |
| `ResultBuilder` | 构造原子结果、脱敏元数据和诊断事件 |

### 3.2 单次处理流程

```text
RequestMeta + TrustedContext + immutable ResponseView
                       ↓
              捕获一份 PolicySnapshot
                       ↓
               准入与表示能力检查
              ├─ 不满足 → Unchanged(reason)
              ↓
      确定性选择模板与 ResourceDescriptor
                       ↓
       预留生成额度 → 生成作用域限定标记
                       ↓
          定位插入点 → 候选缓冲中渲染
                       ↓
       校验内容 / 大小 / 元数据 / 剩余时限
              ├─ 失败 → 释放额度 → Unchanged(reason)
              ↓
          完成额度 → 返回 Modified(candidate)
                       ↓
             尝试记录 lure_rendered 事件
```

`lure_rendered` 只代表模块成功生成候选响应，不叫 `lure_delivered`。模块没有网络发送能力，不能宣称客户端收到或理解内容。

### 3.3 状态与并发

- 请求间不共享可变模板或响应缓冲；策略快照与资源描述只读。
- `activate` 通过原子引用切换版本。已开始的处理使用其捕获的版本完成，不混用新旧配置。
- `pause` 阻止新的处理获取有效快照；在途处理仍可能结束。暂停并不承诺撤销已经返回的结果。
- 密钥、策略和模板均记录版本；不可修改已经发布版本的内容。回退是重新激活旧快照，不是覆盖历史配置。
- 操作去重记录及额度预留均有有界保留期；期限外的相同 `operation_id` 不承诺去重，调用者不得无限期复用。

## 4. 核心数据定义

| 数据类型 | 必需内容 | 约束 |
|---|---|---|
| `TrustedContext` | `scope_id`、`operation_id`、`selection_key`、截止时间、获准标签、缓存处理能力 | 来自可信调用者，不从访客请求头直接采信 |
| `RequestMeta` | 方法、规范化资源标识、必要的协商/条件头 | 外来内容仍是不可信数据；不携带生产凭据 |
| `ResponseView` | 状态码、多值头、不可变原始字节、完整性/编码元信息 | 改写失败时原对象保持不变 |
| `ResourceDescriptor` | `resource_id`、版本、固定入口、合成展示字段、有效期 | 不负责注册资源；地址必须获准且已可用 |
| `LureTemplate` | ID/版本、适配器类型、插入锚点、模板、允许变量、输出上限 | 非可执行内容；变量集合封闭 |
| `PolicySnapshot` | 版本、匹配规则、模板/资源引用、缓存模式、预算、有效期 | 由编译产生，不可变 |
| `RenderMeta` | 操作 ID、规则/模板/资源版本、耗时、字节增量、标记摘要 | 不含原始业务正文或秘密 |

`selection_key` 用于稳定选择，不是身份认证。共享缓存模式下只能使用与公开表示一致的选择维度，例如页面与策略版本，不能加入用户级字段。

## 5. 核心接口与抽象

以下签名体现语义，不限制具体语言，也不表示模块要提供 HTTP 管理 API。

```text
interface DeceptionCore {
  compile(spec: PolicySpec, resources: ResourceDescriptor[]): CompileResult
  activate(snapshot: PolicySnapshot): ActivationResult
  pause(): void
  transform(ctx: TrustedContext, req: RequestMeta, original: ResponseView): TransformResult
  preview(ctx: PreviewContext, req: RequestMeta, original: ResponseView): PreviewResult
  explain(ctx: TrustedContext, req: RequestMeta, original: ResponseView): DecisionTrace
}

type TransformResult =
  Modified { response: ResponseView, meta: RenderMeta }
  | Unchanged { reason: SkipReason, policy_version: Optional<Version> }

interface RepresentationAdapter {
  supports(req: RequestMeta, response: ResponseView): SupportDecision
  render(original: ResponseView, lure: RenderedLure, limits: RenderLimits): CandidateResult
}

interface MarkerIssuer {
  issue(scope: MarkerScope, resource: ResourceDescriptor): MarkerResult
}

interface QuotaPort {
  reserve(scope: ScopeId, operation_id: Id, expires_at: Instant): ReservationResult
  finish(reservation: ReservationId, outcome: GENERATED | SKIPPED): FinishResult
}

interface EventSink {
  tryAppend(event: DeceptionEvent): ACCEPTED | DROPPED
}
```

接口语义：

- `CompileResult` 包含具体字段路径的错误列表；无效编译结果不能激活。
- `Unchanged` 不返回伪造错误页，调用者仍持有原响应；模块不决定是否发送响应。
- `Modified` 含完整且已验证的新表示，不要求调用者逐项执行未验证的修改补丁。
- `QuotaPort.finish` 幂等；预留过期或无法确认额度时不返回新投放内容。异常路径不得泄漏永久预留。
- `EventSink.tryAppend` 非阻塞且内存有界，不能成为业务响应的同步外部依赖。
- `RepresentationAdapter` 无网络访问、路由选择或任意代码执行权限；新增适配器需通过相同契约测试。

## 6. 错误处理与模块不变量

| 情况 | 结果 / 原因码 |
|---|---|
| 未启用、暂停、无有效配置 | `Unchanged(DISABLED / POLICY_UNAVAILABLE)` |
| 范围不匹配、采样未中 | `Unchanged(NOT_ELIGIBLE / NOT_SELECTED)` |
| 模板/资源失效 | `Unchanged(RESOURCE_UNAVAILABLE)` |
| 禁止变换、表示不支持、已有插入 | `Unchanged(NO_TRANSFORM / UNSUPPORTED_REPRESENTATION / ALREADY_APPLIED)` |
| 缓存约束未知或冲突 | `Unchanged(CACHE_CONSTRAINT)` |
| 配额、时限、取消、大小越限 | `Unchanged(QUOTA_EXCEEDED / DEADLINE / CANCELLED / SIZE_LIMIT)` |
| 解析或安全校验失败 | `Unchanged(PARSE_FAILED / OUTPUT_REJECTED)` |
| 内部非预期错误 | 保持原对象，返回 `Unchanged(INTERNAL_ERROR)`，内部记录脱敏诊断 |
| 事件输出失败 | 结果不被改写为错误页，增加丢失计数；越过本地诊断阈值可暂停后续投放 |

不变量：

1. 任何 `Unchanged` 分支都不修改原输入；任何 `Modified` 都是完整结果。
2. 任何成功片段都只能引用批准的合成资源。
3. 安全限制不能被“识别为 AI”或“高风险”标签覆盖。
4. 不执行网络发送、不改变请求目的地、不在线调用模型。
5. 模块错误处理不能保证承载进程崩溃时的可用性，不能将函数级失败保护等同于系统级高可用。

## 7. 模块边界与对外依赖

| 依赖/前提 | 是否必需 | 边界 |
|---|---|---|
| 已取得的完整响应和可信上下文 | 必需 | 模块不获取上游响应，不解释未授权流量 |
| 审核后的模板、资源描述及有效快照 | 必需 | 模块校验其结构与范围，不创建目标服务或管理路由生命周期 |
| `Clock`、随机数/密码库 | 必需 | 用于超时、版本有效期和标记；可替换为测试实现 |
| HTML tokenizer/parser | 首版必需 | 固定兼容版本，限制输入和资源消耗 |
| `QuotaPort` | 必需 | 可用本地有界实现；跨实例配额语义由其实现保证 |
| `EventSink` | 可替换 | 可以是本地有界记录器，不绑定数据库、消息队列或告警产品 |
| 标记密钥提供方 | HMAC 模式需要 | 仅通过受控接口取得，模板和事件不接触原密钥 |

明确排除：AI 身份鉴定、攻击定性、WAF、登录授权、HTTP 服务端监听、TLS、反向代理、强制分流、蜜罐多轮响应、SOC、控制台及项目部署。

模块可使用本地模板、伪响应、内存额度和记录器独立验证，不需要先完成其他业务模块。

## 8. 开发维护与验收

建议内部划分为 `policy`、`lure`、`representation`、`marker`、`quota`、`diagnostics`；核心逻辑依赖抽象，不导入具体代理框架。

开发顺序：先实现准入和不修改契约，再实现一种 HTML 模板与结构化插入，随后增加标记/配额/预览；其他表示适配器在首版契约稳定后扩展。

| 验收维度 | 必备测试 |
|---|---|
| 不修改保证 | 对每个失败原因比较原始字节、头集合和状态码；不得部分修改 |
| 改写正确性 | 非插入区间字节保持一致；模板转义正确；重复处理不重复插入 |
| HTTP 约束 | HEAD、204/304、Range、条件头、no-transform、压缩与保护表示全部按策略跳过 |
| 缓存与标记 | 共享模式不输出会话唯一值；未知模式跳过；活动级选择稳定 |
| 恶意输入 | 畸形 HTML、特殊字符、脚本 URI、超长变量、深层结构均受控失败 |
| 并发与额度 | 操作去重、并发额度争用、预留释放、策略切换无数据串扰 |
| 可维护性 | 规则解释可复现、错误码稳定、模板版本有黄金样例与兼容测试 |
| 性能边界 | 达到配置的输入/输出/时间/并发限制时及时退出，不无界分配 |

本模块指标仅含改写候选数、跳过原因、改写完成数、耗时分布、字节增量、额度占用与事件丢失。没有客户端访问证据时，不输出诱捕率或 AI 识别率。
