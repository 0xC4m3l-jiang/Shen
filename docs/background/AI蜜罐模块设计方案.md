# AI 蜜罐模块设计方案

> 主线：核心能力设计与实现。版本：0.1；日期：2026-09-21。
> 本文定义一个可独立开发的“有状态合成交互引擎”，不定义流量获取、网关、部署或其他模块的实现。
> 接口为语言无关的设计伪代码；文中的验收项尚待实现验证，不代表已有性能或诱捕成效。

## 1. 核心能力范围

**模块职责：在预定义的合成场景内接收交互请求，用确定性状态机和可选 LLM 生成一致、受限、可记录的仿真响应。**

输入：可信作用域、有效会话引用、规范化的交互请求、版本化场景。

输出：已提交的仿真响应或明确的失败结果、状态版本、执行模式及脱敏交互证据。

| 能力 | 设计范围 | 不承担的能力 |
|---|---|---|
| 交互诱捕 | 提供有意义的合成资源及可持续的多步交互 | 不负责让客户端发现入口，不主动获取外部流量 |
| 服务行为模拟 | 模拟受支持的资源查询、分页、有限状态变化和错误语义 | 不执行真实 Shell、SQL、上传程序或系统调用 |
| 场景与交互面扩展 | 用版本化场景及处理器增加合成页面、API 或资源类型 | 不扫描或复制真实攻击面，不动态开放端口 |
| 智能响应 | 在确定事实约束下用模型补充非关键描述或解释 | 不让模型任意创造权限、协议行为或状态变化 |
| 状态一致性 | 隔离会话、稳定资源身份、幂等提交、并发控制 | 不与真实业务状态同步 |
| 行为记录 | 记录请求类别、响应模式、状态变化、模型校验及停止原因 | 不声称读取 Agent 内部推理，不把访问等同于恶意 |

“AI 蜜罐”不意味着每个请求必须调用模型。**确定性仿真是基础，可选模型增强是受限能力；没有模型时仍可进行完整的基础交互。**

### 1.1 首版能力与扩展点

- 首版：一个合成资源场景、规范化 HTTP 请求类型、只读资源查询与一种受限写操作、会话状态、确定性响应、可选模型描述、幂等及预算。
- 首版不实现真实 HTTP 服务端监听；模块只处理请求对象并返回响应对象。
- 后续扩展：新的 `SurfaceHandler`、新的资源类型及受控协议语义；每个扩展需明确动作集合、状态约束和降级响应。
- SSH/MCP 等只有完成对应语义与输入输出适配后才列为能力，不能把“LLM 能生成相似文本”称为完整协议支持。

## 2. 关键功能点与设计逻辑

### 2.1 场景定义与合成资源

使用不可变 `ScenarioSpec` 定义一个自洽环境，至少包含：

- `scenario_id`、场景版本、Schema 版本、处理器版本和模型/提示模板版本。
- 可用交互面、输入/输出 Schema、允许动作、状态不变量及未支持动作的行为。
- 初始合成资源、资源关系、可发现的下一资源引用、静态错误响应。
- 会话寿命、轮数、状态大小、并发、输出及模型预算。

`ScenarioRegistry` 在注册时校验：引用完整、动作无歧义、资源数/深度/文本大小有界、模板可编译、不存在真实凭据及未经批准的外部地址。仅关键字扫描不足以保证合成性，素材来源和人工审核仍是输入前提。

场景更新必须新建版本。新会话采用新版本，已有会话固定旧版本，不能中途切换服务身份或数据模型。版本删除要等待绑定会话结束及所需重放保留期完成。

### 2.2 有界资源图与交互面扩展

将资源表示为有向图：节点是合成文档、对象或集合；边是可继续探索的资源引用。

- 节点 ID、关联关系及内容由场景数据和会话种子确定，同一状态下稳定可复现。
- 列表、详情、统计值和分页游标从同一份状态计算，不能分别让模型自由生成。
- 分页集合有确定上限；游标绑定会话、资源和集合数据版本，过期或失配时返回固定错误，不能无限生成下一页。集合数据版本仅在相关数据变化时递增，不使用每回合都会增长的提交版本，否则只读翻页也会让游标失效。
- 模块内输出的链接/引用只允许指向场景登记的资源；地址映射由已校验的场景字段提供，模型不得添加外部目标。
- 场景图允许受控回访，但限制资源总量、最大探索深度和会话轮数，避免自增的无限图。

这里的“攻击面扩展”是**合成交互覆盖扩展**，不是主动部署真实漏洞。新增交互面通过处理器注册完成，不允许由用户输入或模型输出动态安装插件。

### 2.3 确定性服务行为

`SurfaceHandler` 负责把规范化请求映射为明确动作，再由 `StateReducer` 计算结果。

动作范围例子：

| 动作 | 行为 | 状态规则 |
|---|---|---|
| `LIST_RESOURCES` | 返回合成资源集合及有界分页信息 | 只读；集合版本固定 |
| `READ_RESOURCE` | 返回当前合成资源字段 | 不存在时返回一致的 `NOT_FOUND` |
| `UPDATE_SYNTHETIC_NOTE` | 更新一个获准合成备注字段 | 仅允许字段、长度和字符集范围；不写宿主文件 |
| `GET_SERVICE_INFO` | 返回场景登记的身份、版本和功能 | 同会话不随机改变 |
| `UNSUPPORTED_ACTION` | 返回场景定义的未支持响应 | 不转交真实系统，不虚构操作成功 |

语法错误、对象不存在、未支持和暂时不可用使用不同的领域结果。不能把所有输入都返回“成功”，也不能为了保持交互而宣称真实网络或系统动作已经发生。

对查询式输入使用受限解析器或结构化参数，不调用真实 SQL 引擎；对命令式文本使用显式支持的语法，不调用 `eval`、子进程或任意系统解释器。

### 2.4 智能响应：事实固定，表述可变

采用 **确定性计划优先，模型只增强获准内容** 的首版策略：

1. 处理器解析动作，状态机产出 `ResponsePlan`：状态码/结果码、结构化事实、合法引用、拟提交状态与可增强字段。
2. 没有可增强字段或没有模型预算时，直接用确定性模板生成响应。
3. `ContextBuilder` 只提供合成事实、必要的状态摘要、脱敏后的本轮文本和有界历史。
4. 模型返回受限 `ModelDraft`，只能填写指定的描述字段；不提供工具调用，不接受任意状态补丁。
5. `DraftValidator` 检查 Schema、长度、字段集合、资源引用及明显冲突；重要事实由模板固定输出，不依赖模型自觉遵守。
6. 校验失败、超时或模型不可用时，使用相同 `ResponsePlan` 的确定性版本。

**自然语言的完全事实一致性无法靠 Schema 保证。** 对状态、权限、结果码、数量、资源身份等关键事实始终使用确定性字段。模型描述无法可靠检查时就不展示，不能把模型自评当作唯一安全校验。

模型可辅助把长尾自然语言映射到既有动作，但这是后续独立扩展：分类结果仍需明确的参数校验和许可检查；低置信度不能直接引发写操作。首版不包含此扩展。

### 2.5 会话与状态一致性

会话生命周期：`ACTIVE → CLOSED` 或 `ACTIVE → EXPIRED`，关闭和过期为终态。短暂模型故障只改变本轮执行模式，不隐式重置会话。

会话保存：

- 模块生成的 `session_id`、可信 `scope_id`、场景/处理器/策略版本。
- 初始种子、虚拟资源状态、单调增长的 `state_version`。
- 绝对到期时间、空闲到期时间、已消费轮数和资源预算。
- 有界近期交互、已完成请求的重放记录及最小证据。

会话引用不是生产身份凭据；公共请求携带一个 ID 并不足以授权访问任意作用域的会话。模块逐次校验可信 `scope_id`、会话归属、场景和到期状态，不把 IP 或 UA 当会话主键。

内存会话仓库可以用于单进程实现和测试，但必须明确“不保证进程重启后恢复”；有持久化要求时仓库实现需提供相同的原子及并发契约，核心不绑定具体数据库。

### 2.6 幂等、并发与提交

模块以 `(scope_id, session_id, interaction_id)` 标识一次逻辑交互，并保存规范化输入指纹。

- 已完成的相同 ID、相同输入返回原提交结果，不再次变更状态或调用模型。
- 相同 ID、不同输入返回 `IDEMPOTENCY_CONFLICT`，不能覆盖旧结果。
- 相同 ID 正在处理时返回 `IN_PROGRESS`；同会话的不同交互默认串行，忙时返回有界的 `SESSION_BUSY`，不建立无上限队列。
- `beginTurn` 取得带租约和单调 fencing token 的处理权；`commitTurn` 同时检查 token、租约、当前状态版本和会话仍有效，过期执行者不能提交。
- 租约长度必须覆盖受限处理窗口；需要续租时也不能突破会话/单轮时限。取消、关闭和过期都会使旧提交权无效。
- 最终响应先验证，再把“新状态、状态版本、最终响应、幂等记录、最小证据”在一次仓库原子操作中提交，**提交成功后才返回成功响应**。

如果提交响应丢失，使用相同交互 ID 查询重放记录；仓库不可用时返回 `Pending(COMMIT_UNKNOWN)`，不能将“不知道是否提交”标为“未提交”后重新执行。重复请求的网络投递可能发生多次，本模块保证的是保留期内不重复提交状态，不是网络 exactly-once。

`beginTurn` 先检查作用域，再查相同输入的已完成记录；关闭/过期会话在重放保留期内仅允许返回既有结果，不刷新寿命、不增加回合、不调用模型。新交互仍返回会话终态错误。已消费 ID 的去重信息至少保留到会话终止；完整响应被清理后保留已消费标记，返回 `REPLAY_UNAVAILABLE`，不把旧 ID 当新操作。终态记录全部过期后返回过期/不存在，不自动复活会话。

租约接管只恢复未提交回合。若原执行者在模型调用后崩溃，重新处理可能再次产生推理费用；状态幂等不能保证供应方调用恰好一次。每次恢复尝试使用新的 `AttemptKey = (TurnKey, fencing_token)` 预留并记录预算，已发生或未知的旧费用不退款。首版没有足够费用预算时采用确定性降级，不自动补调用模型。

### 2.7 预算、降级与取消

分开管理状态正确性和资源费用：

- 会话/模块级处理限额：并发、总轮数、输入大小、资源数、状态大小、输出大小和总时间。
- 模型限额：调用次数、上下文、最大生成量、费用预留和单次截止时间。
- 调用前原子预留额度，确认不足就走确定性响应；模型未调用时可释放预留。
- 模型已开始执行后，即使业务回合取消或未提交，也可能产生费用。未知用量按保守上界记账，不能直接全额退回再无限重试。
- 截止时间和取消信号传递到模型客户端；迟到结果不得提交或污染后续会话。请求取消不等于供应方已停止计费。
- 首版模型调用不自动重试，避免隐藏的费用和时延放大；所有重试策略必须消耗显式预算。
- 超过安全上限时可结束会话或返回受控拒绝，不坚持“永不阻断”。

资源预留与会话状态不一定由同一存储实现；费用账本优先保守限制。跨存储不确定时允许暂时保留额度，但不允许未确认额度的推理继续执行。

## 3. 内部实现机制与数据流

### 3.1 内部组件

| 组件 | 单一职责 |
|---|---|
| `ScenarioRegistry` | 校验、保存版本化场景，供会话固定引用 |
| `InputNormalizer` | 限长、规范化、Schema 校验，拒绝歧义，不采信输入中的身份声明 |
| `SessionEngine` | 会话生命周期、租约、幂等、提交与恢复 |
| `SurfaceDispatcher` | 从已登记交互面定位唯一处理器 |
| `SurfaceHandler` / `StateReducer` | 识别受支持动作，产生响应计划与合法状态变化 |
| `ContextBuilder` | 基于固定事实构建有界模型上下文 |
| `ModelResponder` | 通过受控提供方生成可选文本草稿 |
| `DraftValidator` / `ReplyRenderer` | 验证草稿并生成完整响应对象 |
| `BudgetGuard` | 资源预留、用量核对、取消和费用上限 |
| `EvidenceRecorder` | 生成脱敏、结构化的本轮证据，与提交记录关联 |

### 3.2 单轮数据流

```text
TrustedScope + SessionRef + SurfaceRequest + interaction_id
                           ↓
         输入规范化 / 大小检查 / 场景交互面检查
                           ↓
       beginTurn：查重 + 归属/到期检查 + 取得处理权
          ├─ 已完成 → 返回原提交结果
          ├─ 冲突/忙/过期 → 返回明确状态
          ↓
       原子预留资源额度，读取固定版本状态
                           ↓
         Handler → StateReducer → ResponsePlan
          ├─ 不支持 → 确定性未支持响应
          ├─ 无模型或预算不足 → 确定性模板
          └─ 可增强字段 → 有界上下文 → 模型草稿
                                      ↓
                               校验失败即用模板
                           ↓
        验证最终响应与拟提交状态，生成最小证据
                           ↓
       commitTurn：检查 fencing token / 版本 / 有效期
       原子保存状态 + 完整响应 + 幂等记录 + 最小证据
          ├─ 未提交 → 不返回成功、不暴露候选状态
          ↓
           返回已提交响应；尝试输出可选诊断事件
```

未支持动作的响应也作为已处理回合留痕，但不修改合成资源；可以增加回合序号/状态版本以保持提交总序。HTTP 无正文请求或状态由适配器正确处理，不能为保留会话而违反协议。

### 3.3 示例：合成目录与备注

1. 列出场景预置的两份合成文档，返回稳定的资源 ID。
2. 读取某资源，结构化字段来自当前状态；模型最多生成一段非关键的阅读说明。
3. 修改获准的合成备注，状态机校验字段并提交新版本。
4. 再次读取时看到新备注；不会因为模型上下文被裁剪而丢失。
5. 请求不存在的执行能力时返回未支持，不能通过模型补写“已执行”。

该例只说明模块行为，不涉及客户端如何发现入口、网络监听或其他模块的实现。

## 4. 核心数据定义

| 数据类型 | 必需内容 | 约束 |
|---|---|---|
| `ScenarioSpec` | ID/版本、资源图、交互面、处理器版本、Schema、模板、预算 | 发布后不可变，资源与动作集合封闭 |
| `SessionState` | 作用域、场景版本、种子、资源状态、版本号、期限和消费量 | 不含真实业务数据或权限 |
| `SurfaceRequest` | `surface_id`、操作名、受限参数、限长的不可信文本 | 协议已解码但仍需校验；不包含生产 Cookie/Authorization |
| `ResponsePlan` | 固定结果码、事实、引用、拟提交状态、允许增强字段 | 由确定性逻辑创建，模型不能覆盖关键字段 |
| `ModelDraft` | Schema 版本、允许字段的描述文本 | 不含状态补丁、任意 URI、执行命令或工具调用 |
| `TurnRecord` | 交互 ID、输入指纹、前后版本、最终响应、执行模式、最小证据 | 原子提交；响应与状态绑定 |
| `EvidenceRecord` | 事件 ID、作用域、会话/交互 ID、场景版本、动作、结果、变更摘要、用量和原因 | 摘要脱敏，不默认记录原始请求或模型上下文 |
| `ObservationTag` | 可选的来源标签/关联 ID 及验证状态 | 只作关联提示，不授予权限，不依赖另一模块存在 |

`SurfaceReply` 由注册适配器定义为受限响应对象；HTTP 类型包含结果状态、多值头和完整有界正文。`ReplyRenderer` 根据允许 Schema 输出 JSON 或安全模板，不能将模型 Markdown/HTML 原样作为可执行页面返回。

## 5. 核心接口与抽象

以下是模块内 API，不要求为每个方法建立网络端点。

```text
interface HoneypotCore {
  registerScenario(spec: ScenarioSpec): RegistrationResult
  openSession(scope: TrustedScope, scenario: ScenarioVersion): OpenResult
  interact(scope: TrustedScope, session: SessionRef, request: Interaction): TurnResult
  closeSession(scope: TrustedScope, session: SessionRef, reason: CloseReason): CloseResult
  inspect(scope: TrustedScope, session: SessionRef): SanitizedSessionView
}

type Interaction = {
  interaction_id: Id,
  request: SurfaceRequest,
  deadline: Instant,
  cancellation: CancellationSignal,
  observation: Optional<ObservationTag>
}

type TurnResult =
  Committed { reply: SurfaceReply, state_version: Version, mode: ResponseMode, replayed: Boolean }
  | Pending { code: IN_PROGRESS | COMMIT_UNKNOWN, interaction_id: Id }
  | Rejected { code: ErrorCode, retryable: Boolean }

type ResponseMode = DETERMINISTIC | MODEL_ASSISTED | FALLBACK

interface SurfaceHandler {
  validate(request: SurfaceRequest): ValidationResult
  plan(request: SurfaceRequest, state: ReadonlySessionState): PlanResult
}

interface ModelPort {
  generate(context: BoundedContext, limits: ModelLimits, cancel: CancellationSignal): DraftResult
}

interface SessionRepository {
  create(initial: SessionState): CreateResult
  beginTurn(key: TurnKey, input_fingerprint: Digest, deadline: Instant): BeginResult
  commitTurn(lease: TurnLease, expected_version: Version, commit: TurnCommit): CommitResult
  abortTurn(lease: TurnLease, reason: ErrorCode): AbortResult
  lookupTurn(key: TurnKey): StoredTurnResult
  close(scope: ScopeId, session: SessionId, reason: CloseReason): CloseResult
  inspect(scope: ScopeId, session: SessionId): SanitizedSessionView
}

interface BudgetPort {
  reserve(owner: AttemptKey, maxima: ResourceCeilings): ReservationResult
  settle(reservation: ReservationId, usage: KnownOrUnknownUsage): SettlementResult
}
```

接口约束：

- `RegistrationResult` 对不存在的引用、含糊动作映射和无效预算返回字段级错误；禁止带缺陷注册。
- `SessionRef` 由模块创建；调用者先提供可信作用域，核心仍执行归属检查。`inspect` 仅返回脱敏视图，不暴露供应方密钥或完整模型上下文。
- `beginTurn` 必须支持 `Acquired`、`Replay`、`InProgress`、`Conflict`、`Busy`、`Closed` 等可区分结果；作用域检查先于重放查询，重放先于拒绝终态会话的新交互。
- `commitTurn` 保证状态、响应、已消费 ID 与最小证据原子写入；仓库不支持时不得声称具备该保证。
- `abortTurn` 只能释放其仍持有的处理权；不能撤销已提交状态或释放其他执行者的租约。
- `BudgetPort` 的预留/结算以尝试和记录 ID 幂等；供应方用量未知时保守处理，不能借业务回合失败退回已发生费用。
- `Pending` 不暴露候选成功响应，只允许持原 ID 查询/恢复；`Rejected` 表示当前调用未提供已提交结果，不承诺历史上从未提交，例如 `REPLAY_UNAVAILABLE`。其 `retryable` 不授权换 ID 重新执行。
- HTTP、终端等适配器只处理受支持语义，不自行发起网络访问或绕过核心预算。

## 6. 错误处理与模块不变量

| 情况 | 处理 |
|---|---|
| 请求超长、Schema 错误、规范化歧义 | `Rejected(INVALID_INPUT / INPUT_LIMIT)`；不调用模型 |
| 未登记场景或交互面 | `Rejected(UNKNOWN_SCENARIO / UNKNOWN_SURFACE)`；不尝试真实上游 |
| 已登记交互面上的不支持动作 | 提交确定性“未支持”响应，仅记录处理轨迹 |
| 会话归属错误、关闭、过期 | `SCOPE_MISMATCH / SESSION_CLOSED / SESSION_EXPIRED`；不新建替代会话；终态中已完成回合仅可按保留策略重放 |
| 输入 ID 冲突、同会话忙 | `Rejected(IDEMPOTENCY_CONFLICT / SESSION_BUSY)`；相同回合在途为 `Pending(IN_PROGRESS)`，不重复执行 |
| 模型不可用、草稿拒绝、模型额度不足 | 使用同一响应计划的确定性降级；未接收合格草稿不标为模型增强 |
| 会话总预算耗尽 | 受控停止或 `SESSION_BUDGET_EXCEEDED`；不无限生成 |
| 状态仓库不可用 | `STATE_UNAVAILABLE`；不私自创建临时空状态假装继续 |
| 租约/版本冲突、处理取消 | 放弃候选响应和状态；只有仍持权者能提交 |
| 提交结果未知 | 查幂等记录；无法确认返回 `COMMIT_UNKNOWN`，不重复执行 |
| 最小证据写入失败或容量耗尽 | 原子提交失败；不能静默丢弃必需证据后返回成功 |
| 可选诊断事件输出失败 | 不撤销已经提交的回合；记录丢失计数，不承诺诊断 exactly-once |

不变量：

1. 成功响应只描述已提交的合成状态；不同会话及作用域不共享可变资源。
2. 模型不能直接修改状态、状态码、权限、场景图或网络目标。
3. 未知动作不转为任意执行，未知资源不自动映射真实资源。
4. 降级不破坏会话一致性，也不隐式重置已发生的状态变化。
5. 所有历史、资源、重放记录和模型输出都受大小/期限上限约束。
6. 正常客户端可能访问蜜罐；交互证据不能单独作为恶意、AI 身份或远程控制成功的证明。

## 7. 模块边界与对外依赖

| 依赖/前提 | 是否必需 | 边界 |
|---|---|---|
| 可信作用域、会话引用与已解码请求 | 必需 | 不实现外部用户认证，但仍检查会话归属及输入合法性 |
| 已审核合成场景与处理器 | 必需 | 不爬取真实服务、不自动生成真实漏洞 |
| `SessionRepository` | 必需 | 要求原子提交、处理权和查重语义；不限定数据库产品 |
| `BudgetPort` | 必需 | 可用单实例实现；共享预算必须由提供方保证其原子范围 |
| `Clock`、随机数及规范化/Schema 库 | 必需 | 可注入测试时钟和种子；公开会话 ID 使用安全随机数 |
| `ModelPort` | 可选 | 实现可为本地模型或 API；模型关闭时保留确定性功能 |
| 可选诊断输出接口 | 可选 | 不替代仓库中与状态原子提交的最小证据 |

调用者应只提供必要字段，模块也执行字段白名单；不接受生产凭据，不把原始身份令牌传给模型或记录器。模型客户端的目标只能来自受控配置，不接受交互文本指定的供应方地址。

明确排除：欺骗线索投放、流量牵引、反向代理、TLS/监听端口、WAF、项目控制台、跨模块编排、告警平台、真实操作系统仿真、远程控制及第三方信息采集。

模块内部“不提供真实执行能力”不等同于进程拥有操作系统级隔离；运行环境的权限与网络隔离是对外前提，此处不展开其部署实现。

## 8. 开发维护与验收

建议内部划分为 `scenario`、`surface`、`state`、`session`、`response`、`model`、`budget`、`evidence`，依赖方向为核心逻辑依赖端口抽象，具体仓库/模型实现依赖抽象，不相反。

实现顺序：

1. 完成场景校验、确定性资源图和纯 `StateReducer`，用固定种子得到可复现结果。
2. 完成会话生命周期、幂等、处理租约、原子提交及最小证据。
3. 实现一种请求/响应语义适配器及明确的未支持路径。
4. 最后增加受限模型描述、输出校验和预算降级；模型关闭时全套基础测试仍须通过。

缓存策略：首版只使用幂等结果重放，不添加跨会话通用响应缓存。后续若增加缓存，键至少包含作用域、场景/处理器版本、会话与状态版本、规范化输入及模型/提示/校验策略版本；写操作不得跳过状态提交，缓存命中也要经过当前输出约束。

维护约束：

- 场景、Schema、提示、校验规则、处理器分别版本化；记录版本组合，不只记录模型名字。
- 用固定的会话脚本和黄金输出检查列表/详情/修改/读取的一致性。
- 重放分析优先使用已记录的最终响应，不重新调用随机模型冒充原始结果。
- 历史摘要只能帮助生成说明，不能成为状态事实源；不能要求或保存模型内部思维链作为证据。

| 验收维度 | 必备测试 |
|---|---|
| 资源一致性 | 列表与详情一致，修改后重读一致，分页边界和资源上限确定 |
| 会话隔离 | 相同资源 ID 在不同会话/作用域互不覆盖，错误作用域不能读取 |
| 幂等与并发 | 已完成或在途 ID 不触发额外模型调用、不重复提交状态；不同输入冲突；旧执行者提交失败；未提交回合恢复时可能重复推理但必须逐次计费 |
| 原子性与恢复 | 状态、响应、幂等记录及最小证据同时成功或失败；提交超时后能查询结果 |
| 模型边界 | 超长/畸形草稿、外部链接、未知字段、事实冲突被拒绝并稳定降级 |
| 费用与取消 | 预算争用不能超发；取消/超时的未知用量不被错误退款，迟到结果不可提交 |
| 生命周期 | 关闭、绝对/空闲过期、旧版本会话、重放保留期均按契约处理 |
| 失败语义 | 仓库断开不重置状态，未知动作不执行，降级不声称真实操作成功 |
| 模块独立性 | 使用内存仓库、固定时钟和模型桩即可验证，不依赖其他业务模块 |

模块指标：确定性/模型增强/降级回合数、草稿拒绝率、处理时延、模型用量、状态冲突、重复回放、会话过期、预算拒绝和证据写入失败。分母和采样窗口固定；无样本记 N/A，不以“模型调用占比高”代表效果好。
