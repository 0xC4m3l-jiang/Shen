# 0002. 决策取值：三值 + `severity`（否决五档的挑战页）

- 状态：✅ **已采纳**（2026-09-17 结案）—— 采纳**候选 C：三值 + `severity` 旁路字段**
- 日期：2026-09-17
- 影响范围：核心的决策类型（`director` 模块）、全部决策路径测试、`V-4`、指标口径、`docs/spec/metrics.md`
- 决策者：用户

## 背景

`TM-2` 已确认的取值是**三值**：

```text
route_origin   放行 → 真实业务
route_mirage   误导 → 蜜罐后端池
block          拦截
```

`docs/research/deception-engine-design.md` §2.1 / §4.7 提案**五档**，并映射为 7 种 Action：

```text
allow → PASS      observe → OBSERVE    challenge → CHALLENGE
isolate → ISOLATE  block → BLOCK       （外加 POISON / REDIRECT 两个执行动作）
```

**为什么必须重开**：这两个模型不是同一个抽象的粗细之分，而是**两种不同的世界观**。

- 三值假设：**处置只有三种结果**，其中「误导」是**透明**的 —— 客户端无法区分真实业务与蜜罐。
- 五档假设：处置是一条**可见性递增**的阶梯 —— `challenge`（挑战页）、`isolate`（本地短路）、`block`（拒绝）
  全部是**客户端可观测**的。设计稿自己也在 §9.1.16 承认要「含五档决策分支」测试。

**不决定的代价**：决策枚举是 `shen-core` 的核心类型。它一旦落地，全部判别器、调度策略、测试用例、
指标口径（`false_route_rate` 的分母是什么？）都跟着固化。**这是必须最早定的类型。**

## 候选

| 候选 | 它擅长什么 | 它的代价 | 什么条件下它最优 |
| --- | --- | --- | --- |
| **A. 维持三值** | 与「不拦截、改道」的定位一致；`route_mirage` 的**透明性**是命题核心，五档会稀释它；`V-4`（非法决策值 → 回落 `route_origin`）的判据简单；`NI-5`（未识别一律回落）唯一出口 | 无法表达「这个会话我要加重处置」——只能靠限速/加噪声等**不可见**手段，或跳出决策枚举另做 | 命题确实是「透明误导」；可见处置由接入层（Envoy 的 challenge）而非本引擎承担 |
| **B. 五档（对齐设计稿）** | 表现力强；`observe` 档对影子模式（`NI-6`）天然友好；`isolate` 的本地短路省一次核心调用 | 与「不拦截改道」的定位冲突（`challenge`/`block` 是可见的）；`TM-2` 作废；`INT-8`（禁止改写业务侧响应）需重新审视 | 本引擎同时承担 WAF 职责，而不只是欺骗调度器 |
| **C. 三值 + 独立的「处置强度」旁路字段** | 保住 `route_mirage` 的透明性；同时给「加重处置」一个正当的表达位（限速档位、噪声强度），且**不进决策枚举** | 多一个字段就要多一套语义与测试；两套概念容易被实现者混用 | 需要「不可见的加重」且不愿污染决策枚举时 |

## 决定

**采纳候选 C —— 三值决策 + `severity` 旁路字段。**

```text
decision  : route_origin | route_mirage | block     ← 去哪儿（三值闭集，禁止第四个）
severity  : none                                    ← 多重手（旁路，不改变去向）
```

取值与写法见 [`../../design/terminology.md`](../../design/terminology.md) §4；
归属与规则见 [`../../design/modules.md`](../../design/modules.md) §4（`MD-12`（决策取值只在 director 定义一次） / `MD-13`（severity 与决策取值并列输出） / `MD-23`（severity 的加重必须可归因于环境） / `MD-24`（severity 档位只能用登记过的值））。

**不采纳五档的 `challenge`（挑战页）。** 引擎是**欺骗调度器**，不是 WAF；可见拦截交给接入层的其他组件。

## 理由

### 1. 三值与五档的差集，实际只有一个能力增量

把两边取值对齐后：

| 三值 | 五档 | 是否同一件事 |
| --- | --- | --- |
| `route_origin` | `allow` | ✅ 改名 |
| — | `observe`（放行 + 重点记录） | ➖ **影子模式（`NI-6`）已覆盖** —— 它是**部署态**，不是判决结果 |
| `route_mirage` | `POISON` / `REDIRECT`（执行动作） | ✅ 同一件事 |
| — | `isolate`（本地短路） | ➖ 可实现为**不可见**（后续请求自然继续，只是不再问核心） |
| `block` | `block` | ✅ 同一件事 |
| — | **`challenge`（挑战页）** | 🔴 **唯一真正的能力增量** |

**所以本决策的实质是：要不要亲手弹一个挑战页。** 答案是**不要**。

### 2. 它会自曝 —— 而自曝与透明改道互斥

一个 Agent 打进来看起来是这样的：

```text
第 1 跳   GET /            200  "首页"
第 2 跳   GET /api/me      200  {"balance": 1000}
第 3 跳   GET /api/user/1  200  {"name": "张三"}     ← 它拿到了真数据
第 4 跳   GET /admin.php   404
```

假设第 3 跳时认出它。手上只有三种回应：

| 回应 | 它看到的 | 它的结论 |
| --- | --- | --- |
| 继续给真数据 | 一切正常 | 「这站没防护」→ 继续深入 |
| **悄悄换成假数据** | **也一切正常**（同域名 / 同 TLS / 同 URL） | 「我拿到数据了」→ 继续深入 ← **但拿的是假的** |
| 弹挑战页 / 403 | 一个质询 | **「我被拦了」** → 换 IP、换工具、重来 |

第二行是本项目的全部价值；第三行**主动放弃**了它。这就是 `D0` 推论 3：
**加重处置必然可见，而「可见」与「透明」是两套互斥机制。**

### 3. MVP 阶段它物理上执行不了

第 1 步是**旁路镜像，只观察** —— 引擎**根本不在请求路径上**，无法返回 403 或弹挑战页
（`INT-6` 已确认该形态不适用 `NI-3` / `NI-4` / `NI-10`）。

**若此刻选五档，`challenge` 与 `block` 在 MVP 里是死代码** —— 写了、测了，永远执行不到。

### 对候选 B 最强优点的回应

候选 B 的两个卖点是真实的：

1. **`observe` 档对影子模式天然友好** —— 但影子模式是**部署阶段**属性（`NI-6`），不是**判决结果**。
   影子模式下引擎只观测、不处置，**不产生任何决策值**。用 `observe` 表达它会把「部署态」与「决策态」混为一谈。
2. **`isolate` 的本地短路省一次核心调用** —— 这个收益**不必通过扩枚举获得**：
   适配器侧本来就有判定缓存（`AR-6`），短路是缓存机制的一部分，与决策取值无关。

### 为什么加 `severity` 而不是纯三值

`D0` 推论 2 规定「判错只能靠加重处置补救，**不能**改道」。若连 `severity` 都没有，
对「首跳看不出、后面越看越像」的慢热型 Agent **完全没有任何手段**。
`severity` 给这种情形一个**不可见**的表达位，且不污染决策枚举。

## 后果

- **正面**：命题的透明性得以保住；决策枚举是闭集（3 值），实现与测试面最小；`severity` 与决策解耦，可独立演进。
- **负面**：引擎**不具备**可见拦截能力 —— 低端扫描器拦不住（但那用现成 WAF / CDN 更划算）；需要维护「不可见加重」的归因纪律（`MD-23`（severity 的加重必须可归因于环境））。
- **引入的新风险**：`severity` 的档位与参数**是实测问题**（「多狠算不明显」无已知答案）；在实测前实现只支持 `none`，等于此能力暂时不可用。
- **被排除掉的可能性**：引擎兼做 WAF；挑战页 / 验证码这类明确防御信号。

## 失效条件

- 当**接入形态改为引擎在请求路径上**（第 2 步接管之后），且**确有客户要求引擎自带可见拦截**时 → 重开。
- 当**慢热型 Agent 占比被证明可忽略**（即首跳判准率足够高，`severity` 长期用不上）时 → 可简化为纯三值，移除该字段。
- 当**威胁模型的 R-3**（跨会话记忆与众包识破）被证明必须靠「会话边界多态」解决、而多态与 `severity` 冲突时 → 重开。
- 复查日期：**2026-12-17**

## 未解决

- **`severity` 的具体档位未定义** —— 已登记为 [`../../design/terminology.md`](../../design/terminology.md) §4.2 的未决项。
  在实测确定并登记前，实现**必须**只支持 `none`（依据 `TM-13`（severity 档位只能用登记过的值） / `MD-24`）。
- **`false_route_rate`（误调度率）的分母已可定义** —— 三值闭集使分母明确（改道 + 拦截）。
  `docs/spec/metrics.md` **不再被本记录阻塞**，可随时创建。
- 设计稿 §4.7 的 `POISON` / `REDIRECT` 是**执行动作**而非决策取值 —— 本记录采纳三值后，
  它们对应 `route_mirage` 的两种执行方式，**不必**进入决策枚举。
