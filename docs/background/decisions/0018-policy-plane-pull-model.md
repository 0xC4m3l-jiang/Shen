# 0018. 策略面（S4）的消费模型：Pull 轮询 + 回执 · JSON 载荷 · 远端覆盖本地兜底

- 状态：✅ **已采纳**（用户于 2026-09-19 批准全部九项推荐）
- 日期：2026-09-19
- 影响范围：[`../../design/structure.md`](../../design/structure.md) §1.6.4（接缝现状）· §2.2（`S4` 行）· §3（数据模型：回执）；[`../../spec/policy-payload.md`](../../spec/policy-payload.md)（新增契约）；[`../modules/policy.md`](../../modules/policy.md) · [`../modules/adapter-proxy.md`](../../modules/adapter-proxy.md)；`api/policy/v1/policy.proto`（`PolicyAck` 加 `adapter_id` / `reason`）
- 决策者：用户
- 依据：`ST-8`（策略面必须带版本号与校验和、支持回滚）· `AR-13`（下发必须版本化 + 各层必须回执以便对账）· `ST-24`（策略是数据）· `MD-20`（核心唯一 I/O 出口是 `store`）· `NI-1`（不影响原始业务）

## 背景

`api/policy/v1` 的**契约从阶段 1 就存在**（`Pull` / `Watch` / `Ack`，`PolicySnapshot{policy_id, version, payload, checksum, gray_pct}`），
但两端一直没实现：核心侧没有服务端、边缘侧没有客户端。后果是
`decoy` / `honeypot` / `responder` 这些阶段 2b 模块**装配了却不在这条链路上** ——
核心算出来的幻境后端池、诱饵定义、预生成内容**传不到边缘**。

同时，边缘现在用**环境变量**表达同语义的数据（`SHEN_PROXY_MIRAGE` 后端表 · `SHEN_PROXY_WHITELIST` 白名单 ·
`SHEN_PROXY_INJECT` 注入片段），与 `ST-24`「策略是数据」的意图只在「改配置要重启」这一层勉强对齐。

## 候选

| 候选 | 内容 | 真实优势 | 代价 |
| --- | --- | --- | --- |
| **A** | **`Pull` 轮询 + `Ack` 回执**（采用） | 最小可用：无长连接状态、断线即重试、回执满足 `AR-13` 对账 | 生效有延迟（一个轮询间隔） |
| **B** | `Pull` + `Watch` 流式 + `Ack` | 变更亚秒级生效 | 要处理长连接、断线重连、心跳、半开连接；契约已定义，加它不用改 proto |
| **C** | 边缘**直接读核心的配置文件**（共享卷） | 零协议 | 跨主机不可行；把「核心的配置格式」变成边缘的契约（版本与灰度无从表达） |
| **D** | **不下发**，继续用 env | 零成本 | `ST-24` 的意图落不了地；改后端表要重启适配器；无法做版本对账 |

## 决定

1. **RPC 面**：本轮实现 `Pull` + `Ack`；`Watch` **显式返回 `Unimplemented`**（不是挂住调用方）；
2. **载荷**：`payload` 是 **JSON**，带 `schema_version`；`checksum` = 对 `payload` **字节**的 SHA-256（适配器先验完整性再应用）；
3. **下发什么**：只下发适配器**真正消费**的两段 —— 改道后端表 + 白名单 CIDR。诱饵资产、规则、阈值留在核心；
4. **合并语义**：**远端覆盖 + 本地兜底**；其中后端表按逻辑名覆盖，**白名单是并集（只增不减）**；
5. **节奏与失败**：启动拉一次 + 每 60s（`SHEN_PROXY_POLICY_INTERVAL` 可配）；拉取/校验/应用失败**一律沿用当前策略**，绝不阻塞请求（`NI-1`）；
6. **服务端位置**：落在 `policy` 模块（它持有快照、版本与校验和），由 `cmd/core` 装配注册 —— **不新增模块**（`MD-18` 不触发）；
7. **回执**：`ack{policy_id, version, adapter_id, applied, reason}` 经 `store.PolicyStore` 落账（`MD-20`）；
   同一 `(policy_id, version, adapter_id)` **幂等**（适配器重启会重报），`applied=false` **必须**带原因；
8. **回滚**：沿用「回滚 = 发布一个新版本」的语义（`store.Publish` 强制版本单调递增），本轮不做触发 UI（控制台未实现）；
9. **灰度**：适配器**不消费** `gray_pct` —— 灰度仍在核心内逐请求收敛（`INT-12`）。

## 理由

### 1. 为什么不用 `Watch`（本轮）

`Watch` 的收益是**延迟**，成本是**状态**：长连接、重连、心跳、半开检测、代理/网关对流的支持。
而当前策略的变更方式是「改配置文件 + 重启核心」，一个轮询间隔（默认 60s）完全够用。
契约里已经有 `Watch`，将来需要时**不用改 proto**。

### 2. 为什么 `checksum` 覆盖「下发的那串字节」而不是「配置文件」

适配器要用它判断「我收到的这串字节有没有被改过」——「适配器与核心同主机」是**当前**的部署假设
（明文 gRPC），一旦跨节点就是真实威胁。配置文件级别的校验和留在核心台账里用于回滚对账，
两者语义不同，不能混用。

### 3. 为什么只下发两段（后端表 + 白名单）

**下发用不到的数据 = 给边缘多一份会过期的复制。** 规则求值、阈值、诱饵定义、预生成内容都只在核心用；
边缘真正需要的只有「改道后端在哪」与「谁不用判定」。JSON 载荷加字段是向后兼容的，将来真有需求再加。

### 4. 为什么白名单是**并集**而不是覆盖

白名单是**防误伤的护栏**（`INT-25`）：缩小它意味着把内部 IP / 健康检查 / 监控探针**送进判定**，
后果是把运维探针判成攻击者。护栏类配置**只增不减**；内容类配置（后端表）按名覆盖才是合理的。
这条差异是**故意**的，写在 `applyEdgePolicy` 的注释里。

### 5. 为什么失败必须沿用当前策略

`NI-1` 是最高优先级的约束，引擎的**任何**自身体系故障都不得影响原始业务。
策略面不是请求路径上的依赖：拉不到就用**上一次成功应用的版本**，再不行就用本地 env。

## 后果

| 类型 | 内容 |
| --- | --- |
| ✅ 正面 | 阶段 2b 的**结构性断点闭合**：核心 → 边缘的策略通路打通，改道后端表与白名单可下发、可对账、可回滚；`ST-8` / `AR-13` 第一次真正落地 |
| ⚠️ 负面 | 生效有最多一个轮询间隔的延迟；适配器侧多了一条后台 goroutine 与一块远端状态（原子替换，不参与请求语义）；`api/policy/v1` 的 `PolicyAck` 扩了两个字段（向后兼容） |
| 🔧 需同步 | `docs/spec/policy-payload.md`（新契约）· `structure.md` §1.6.4 / §2.2 / §3 · `modules/policy.md` · `modules/adapter-proxy.md` · `edge/proxy/README.md` 与 `config/*.env` |

## 失效条件

出现下列任一情形时**必须**重开本记录：

1. **需要亚秒级生效**（例如「发现攻击后立即把所有适配器切到新后端」成为硬需求）→ 重开，启用 `Watch`；
2. **载荷需要类型安全或强 schema 校验**（JSON 手工对齐两端结构开始出错）→ 重开，改成 proto 结构字段（扩展 `PolicySnapshot`，不再用 `bytes`）；
3. **边缘需要按灰度分批应用不同策略版本** → 重开（要与 `INT-12` 的核心内灰度划清关系）；
4. **`NI-1` 被策略面破坏**：任何一次策略拉取/应用失败曾导致请求路径受影响 → 重开，重新评估「适配器持有远端策略」这一形态本身。

## 未解决

- **注入片段与诱饵资产的边缘通路**：本轮载荷不带它们 —— 核心**没有**注入片段的配置来源
  （注入片段现在只在适配器的 env 里）。要下发它，得先在核心侧定义它的归属（`decoy` 产出？`responder` 预生成？）
  与配置段，属下一轮的设计议题；
- **`ack` 只落账、不告警**：「哪个适配器停在了旧版本」目前只能被人查，不能主动发现。
  需要一条「版本对账 → 告警」的路径（运营面，`analytics/` 未建）；
- **明文 gRPC 的同主机假设**：策略面与判定面共用一个监听，跨节点必须换 mTLS（未实现）。
  当前用「非回环地址启动即失败」兜住（`assertPlaintextListenIsLocal`）；
- **决策缓存窗口内的决策复用**：`decision_id` 不含 UA/指纹（`ST-10`），同一 `(IP, 会话, 路径, 60s)` 内共享一个决策 ——
  实测可复现「探针先到 → 同窗口的真实用户被改道」与「真实用户先到 → 同窗口的探针漏改道」。
  见 [`../kb/known-issues.md`](../kb/known-issues.md) 的 `K-20`；改它要动 `ST-10`，属**单独一轮**的设计议题；
- **`PolicyStore` 的 `Acks` 没有保留期**：内存实现无所谓，接 PostgreSQL 时要按 `NI-13` 定保留天数。
