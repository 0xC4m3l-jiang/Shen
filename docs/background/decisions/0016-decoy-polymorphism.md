# 0016. 诱饵多态与再生成：会话间轮换 + 识破信号触发（与 `AR-30` 的划界）

- 状态：✅ **已采纳**
- 日期：2026-09-18
- 影响范围：`decoy` 的诱饵标识与轮换；`responder` 的一致性键；`chain` 的识破信号识别；`strategy` 的再生成决策
- 决策者：用户
- 依据：用户「继续补充」+ 综述空白 F（[`../research/ai-agent-deception-defense-survey.md`](../research/ai-agent-deception-defense-survey.md) §6.3）+ 参考实现逆向 §6.3

## 背景

综述把「多 agent 共享记忆 → 诱饵众包识破」列为空白 F，并把评级**上调**为 ⭐⭐⭐：
参考实现的诱饵**完全静态且硬编码**（同一文件名 `site-backup-2025-05.zip`、同一假 DB 连接串、同一水印格式），
一旦进入多 Agent 的共享上下文（`2608.11436`），即可被**直接白名单化** —— 这是它最容易被击穿的一点。

`AgentSnare`（`2607.26998`）进一步证明：**静态诱饵会被渐进识破**，诱饵需要**多态**，调度需要**学习**。

**但这里有一个直接的张力**：`AR-30` 要求「同一 `(会话, 资源)` 永远返回同一答案」——
多态要求「同资源不同答案」。若不做划界，两条规则会互相抵消。

## 候选

| 候选 | 内容 | 真实优势 | 代价 |
| --- | --- | --- | --- |
| **A** | 静态诱饵（现状） | 简单；`AR-30` 天然满足 | 🔴 被共享记忆众包识破（空白 F） |
| **B** | **按时间窗轮换**（不同时期不同诱饵） | 打破「长期不变」的指纹；实现简单 | 轮换瞬间可能出现跨窗口不一致（需与 `AR-30` 划界） |
| **C** | **识破信号触发再生成** | 按需、有针对性 | 需要能识别「被识破」信号 |
| **D** | 学习型多态（按攻击者信念选态，超博弈 / DRL） | 理论上最优 | 需要前两者先跑通（参考实现教训：**不要在闭环未通用时上学习**） |

## 决定

**采纳 B + C，D 作为演进终点（不在本轮设计）**，并明确划界：

### 划界：`AR-30` 管「会话内」，多态管「会话间 / 时间上」

| 维度 | 规则 |
| --- | --- |
| **会话内**（同一 `(会话, 资源)`） | **必须**一致（`AR-30`）—— 重试 / 翻页 / 重放都同答案 |
| **会话间**（不同会话） | **允许**不同 —— 多态的粒度是**会话**或**时间窗**，不是请求 |
| **时间上**（同一会话跨轮换窗口） | **必须**粘住建立时的变体 —— 会话一旦选定变体，直到会话结束不变 |

> 一句话：**多态在会话边界上选择，在会话内部冻结。**
> 实现上，变体选择函数是 `variant = hash(会话键) mod N`（或按时间窗的 `hash(会话键, 时间窗)`），
> 会话内恒为定值 —— 这使 `AR-30` 与多态**同时成立**。

### 可多态的诱饵标识

| 标识 | 轮换方式 | 依据 |
| --- | --- | --- |
| 文件名（`site-backup-2025-05.zip` 类） | 按时间窗生成新名字 | 参考实现硬编码 |
| 假凭证的形态（用户名 / 口令策略 / 水印格式） | 按会话派生 | 参考实现固定 `Bk2026!<水印>` |
| 假 DB 连接串 / API Key | 按会话派生 | 参考实现同一串 |
| 诱饵 API 路径 | 按时间窗轮换 | —— |
| 消耗战数据集的字段与值 | 按会话派生（确定性） | 与 `AR-30` 配套 |

### 识破信号（触发再生成，候选 C）

| 信号 | 含义 |
| --- | --- |
| 诱饵路径被**直接跳过**（Agent 访问相邻真实路径但不碰诱饵） | 可能已知诱饵 |
| 诱饵命中后**无后续交互**（拿到即走，不深入） | 可能是白名单化的诱饵 |
| 诱饵特征出现在后续请求的**比对行为**里（如显式请求假文件名验证） | 正在验证 |
| 同一诱饵被**多个会话**以完全相同方式访问 | 共享记忆迹象 |

> 识破信号由 `chain`（攻击链）识别，**触发 `strategy` 生成再生成决策**，经 `policy` 下发 ——
> **不是**由响应路径直接改（`AR-32`：分析结论禁止直接回写响应）。

## 理由

### 1. 划界使两条规则共存，而不是二选一

`AR-30`（一致性）与多态（差异）看似矛盾，实际是**作用域不同**。把多态的作用域定在「会话边界」，
两条规则都成立 —— 且都不需要牺牲。

### 2. 多态的成本很低，收益是对抗共享记忆

变体选择是**纯函数**（哈希），不增加存储与延迟；而它直接对抗空白 F ——
不同 Agent 之间的记忆无法互相白名单化，因为「另一个 Agent 看到的诱饵文件名」在本会话里不存在。

### 3. 学习（D）必须有前两者才有意义

参考实现的教训明确：**连判别-执行闭环都没打通时，任何策略学习都无处着陆**。
B + C 提供了「可观测的差异（B）」与「可学习的信号（C）」，D 才有输入。

## 后果

| 类型 | 内容 |
| --- | --- |
| ✅ 正面 | 对抗众包识破（空白 F）；与 `AR-30` 不冲突（作用域划界）；成本极低（纯函数） |
| ⚠️ 负面 | 需要管理的**变体集合**（生成 + 校验）；识破信号的**误报**会触发无谓再生成；再生成有滞后 |
| 🔧 需同步 | `decoy.md` 的标识生成；`responder.md` 的一致性键（变体并入键）；`chain.md` 的识破信号；`strategy.md` 的再生成决策 |

## 失效条件

出现下列任一情形时**必须**重开本记录：

- **识破信号误报率过高**（大量无谓再生成，运营成本失控）→ 重开，评估更保守的触发；
- **多态被证明加速识破**（Agent 察觉「同一站点不同会话给不同答案」）→ 重开，评估更细的粒度或退回 A；
- **变体集合的管理成本超过收益** → 重开；
- **`AR-30` 的会话内一致性与多态在实际实现中无法共存** → 重开，两者需重新划界。
