# 0013. 归因令牌：会话蜜标（双角色）+ 凭证水印

- 状态：✅ **已采纳**
- 日期：2026-09-18
- 影响范围：`session` 增加「归因令牌」子能力；`decoy` 的诱饵携带令牌；`judge` 消费令牌回显
- 决策者：用户
- 依据：用户「核心是欺骗引擎的实现」+ 参考实现逆向 §3.8 + [ADR-0010](0010-functional-camouflage.md)

---

## 背景

欺骗引擎要回答的不止「是不是 Agent」，还有「**是哪一个、从哪来、去过哪**」。
参考实现用**一个 HMAC 令牌承担两个角色**，这是它第三有价值的原创（仅次于功能性伪装与蜜饵 observe-only）：

| 层 | 角色 | 行为 |
| --- | --- | --- |
| 检测处置层 | **蜜标**（canary token） | `X-Agent-Canary: <token>` 回显 → +70 分 → 持久化隔离 |
| 功能性诱饵层 | **API 会话令牌** | content / register / heartbeat 全程携带 → 写进名册归因 |

关键洞察：**追踪信标必须成为目标「正常工作流的一部分」**，而不是额外要求 —— 于是归因是**免费的**。

本项目的诱饵面（[ADR-0010](0010-functional-camouflage.md)）天然需要这样一个令牌：Developer API 诱饵要有会话令牌，
MCP 诱饵要有调用凭据，凭证蜜饵要有可溯源的水印。三者可以是**同一个派生令牌的不同呈现**。

## 候选

| 候选 | 内容 | 真实优势 | 代价 |
| --- | --- | --- | --- |
| **A** | 不做令牌，只靠会话身份（`session.Key`）归因 | 零额外机制 | 🔴 无法跨面归因（凭证在蜜罐里被偷走后复用，回不到原会话）；无「回显即铁证」的强信号 |
| **B** | **HMAC 派生令牌（双角色）+ 凭证水印** | 归因内生于工作流；回显即高置信信号；凭证复用可回溯到具体会话 | 需密钥管理；令牌泄露会污染归因（参考实现的实际缺陷）；需 TTL |
| **C** | 显式追踪 cookie | 实现简单 | 🔴 违反 `NI-9`（禁止新增客户端可见 Cookie）；且是蜜罐的签名 |

## 决定

**采纳 B**，并修正参考实现的两处缺陷：

1. **令牌派生**：`canary = HMAC-SHA256(secret, session_key)[:24]`；比较**必须**用常数时间（`hmac.Equal`）；
2. **双角色**：
   - **蜜标**：注入页面/诱饵，回显即高置信信号（`judge` 命中 → 加分 → 加重处置）；
   - **诱饵会话令牌**：Developer API / MCP 诱饵的会话凭据，接入流程天然携带，写进归因记录；
3. **凭证水印**：假凭证中嵌入会话指纹（如 `Bk2026!<水印>`），使**复用**成为归因事件（可回溯到具体会话）；
4. **必须带 TTL 与轮换**（参考实现无 TTL，令牌恒定生效 —— 这是它的缺陷）；
5. **归因闭环校验**（修正参考实现的漏洞）：诱饵面收到令牌时**必须**校验它属于一个真实存在的会话，
   **禁止**直接接受任意字符串（参考实现把 `ticket[:64]` 直接存为 `recruit_src`，可被伪造污染名册）。

## 理由

### 1. 归因必须内生于工作流，否则会自曝

一个「请带上这个头」的要求是显式指令（[ADR-0010](0010-functional-camouflage.md) 已否决）；
而「调用 API 时带上会话令牌」是**任何 API 客户端的标准行为**。后者不触发对齐层，且天然完成归因。

### 2. 凭证水印把「复用」变成证据

攻击者从蜜罐偷走凭证后，**下一次使用**就是归因事件。成本极低（一个字符串后缀），收益极高（跨面溯源）。

### 3. 参考实现的两个缺陷必须修正

- **无 TTL**：令牌恒定 → 一旦泄露可长期冒充；
- **无闭环校验**：任意 `ticket` 都被接受 → 名册可被污染（它是「归因完整性依赖令牌保密性」，而令牌出现在可见页脚 URL 里，会进 Referer / 代理日志 / 浏览器历史）。

本设计的两条修正（TTL + 闭环校验）是**采纳 B 的前提**，不是可选优化。

## 后果

| 类型 | 内容 |
| --- | --- |
| ✅ 正面 | 跨面归因（页面 → 诱饵 → 凭证 → 蜜罐）；回显即高置信信号；无新 cookie（`NI-9` 保持） |
| ⚠️ 负面 | 需密钥管理（`ST-21`：密钥禁止有默认值，缺失即启动失败）；令牌必须带 TTL 与轮换；归因链路需要存储支撑（`actor` / `session` 实体） |
| 🔧 需同步 | `session.md` 新增「归因令牌」；`decoy.md` 的诱饵携带令牌；`judge` 消费回显信号；`config` 的密钥段 |

## 失效条件

出现下列任一情形时**必须**重开本记录：

- **令牌出现在攻击者可见位置导致被识别为蜜罐**（例如令牌格式过于显眼）→ 重开，评估令牌形态；
- **闭环校验的开销无法接受**（每次诱饵请求都要查会话）→ 重开，评估短 TTL 缓存；
- **凭证水印被 Agent 识破为「非自然凭证」** → 重开，评估更自然的编码方式。

## 未解决

- **令牌 TTL 的具体值** —— 与 `severity` 档位同属实测问题；
- **水印的编码方式** —— `Bk2026!<8位>` 是参考实现的形态，是否自然需实测（可能因用户名/口令策略不匹配而被识破）；
- **归因链的存储实体** —— `actor` / `session` / `chain` 三个实体的关系需在 `structure.md` §3 细化（不在本决策范围）。
