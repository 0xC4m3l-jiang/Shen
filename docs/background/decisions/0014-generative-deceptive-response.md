# 0014. 生成式欺骗响应：快慢两路 + 「同会话同资源同答案」不变量

- 状态：✅ **已采纳**
- 日期：2026-09-18
- 影响范围：`responder` 模块（阶段 2b）；`llm-components`（L4，内容预生成）；`store` 的内容缓存；`edge-injection` 的响应改写
- 决策者：用户
- 依据：用户「核心是欺骗引擎的实现」+ [`architecture.md`](../../design/architecture.md) §4 第 6 条（快慢两路）与 §5（AR-15…AR-27）+ 参考实现逆向 §3.7 + 行业（GenPot / llmockapi）

---

## 背景

改道到幻境之后，**返回什么**决定欺骗是否成立。

- 返回静态假页 → 多 Agent 共享记忆后众包识破（综述空白 F）；
- 返回真业务数据 → 欺骗无意义；
- 返回**看起来像真实业务的响应** → 目标继续交互（本项目的价值）。

架构已定「快慢两条路」（[`../../design/architecture.md`](../../design/architecture.md) §4 第 6 条）：
**快路径 = 规则与模板响应（毫秒级，进程内）；慢路径 = LLM 会话仿真（调用 L4）**。
LLM 输出的纪律也已由 `AR-15`…`AR-27` 覆盖（契约校验、黑名单、超时、话术资源化）。

**但有一个硬约束此前未被写进设计**：

> **同一 `(会话, 资源)` 必须永远返回同一答案。**

理由在 `D0`（[`../notes/implementation-discussion.md`](../notes/implementation-discussion.md) §1）与
[`deception-engine-design.md`](../research/deception-engine-design.md) §2.4：
Agent 必然重复请求同一资源（验证、重试、翻页）。若同一会话两次拿到不同答案，**立刻识破**（同 URL 两个值 = 一眼假）。
而**LLM 的随机性恰恰最容易破坏这条**——它是最需要约束的组件。

## 候选

| 候选 | 内容 | 真实优势 | 代价 |
| --- | --- | --- | --- |
| **A** | 纯模板响应（确定性） | 快、可回放、天然一致 | 🔴 静态 → 被众包识破；保真度低 |
| **B** | 纯 LLM 逐请求生成 | 保真度高 | 🔴 随机性破坏一致性；延迟；`MD-6`（核心禁止外呼）；LLM 调用量随请求量增长（违反 `AR-14`） |
| **C** | **快慢两路 + 内容落库 + 按 `(会话, 资源)` 缓存** | 快路径毫秒级且一致；慢路径提供保真度；LLM 调用量与**会话数**而非请求数相关 | 需要内容缓存与一致性键设计 |

## 决定

**采纳 C**，并把一致性写成**不变量**：

1. **快路径**：`responder`（核心，Go）用**模板 + 确定性伪随机**生成响应。
   确定性伪随机的种子 = `(会话键, 资源键)` —— 同一组合必得同一输出，**不依赖任何 LLM**；
2. **慢路径**：`llm-components`（L4，Python）**离线/近线**用 LLM 生成高保真诱饵内容（假用户 / 假订单 / 假日志），
   **落库**到 `store`，按 `(会话, 资源)` 缓存；
3. **不变量（`AR-30`，本次新增）**：任何伪造响应**必须**按 `(会话, 资源)` 命中同一内容 ——
   重试、重放、翻页都得到同一答案。**禁止**在响应路径上引入非确定性（随机数、当前时间、LLM 采样）；
4. **核心不调 LLM**：`responder` 是核心模块，**禁止**外呼（`MD-6`）；它只从 `store` 读预生成内容或走确定性模板；
5. **只改写蜜罐侧**：响应改写**禁止**作用于真实业务（`INT-8`）。

### 分配

```text
请求 → director（route_mirage）→ edge-injection（改写）
                                      │
                                      ├─ 快：responder 确定性模板（毫秒级，进程内）
                                      │     种子 = hash(会话键, 资源键)
                                      └─ 慢：store 命中 llm-components 预生成内容
                                             （未命中 → 回落快路径；禁止同步等 LLM）
```

## 理由

### 1. 一致性是「不可区分」的必要条件，不是优化

`D0` 的一整条推理都建立在「同资源同答案」上。参考实现的工程约束（§2.4）也把它列为「AI 最容易破坏的东西」。
因此它必须是**不变量**（有 ID、可测），而不是「注意一下」。

### 2. 热路径放 LLM 是延迟自杀

`AR-29` 给业务路径 P99 的额外预算是 **5 ms**；LLM 推理是百毫秒级。
把 LLM 放在响应路径上，等于放弃这条路。落库预生成把 LLM 的延迟移出热路径。

### 3. 调用量与请求量解耦

`AR-14` 要求「触发 L4 必须经态势去重，禁止随事件写入量线性触发」。
按 `(会话, 资源)` 预生成，使 LLM 调用量与**会话数 × 资源数**相关，而不是与请求数相关 ——
攻击者狂刷同一路径不会放大成本。

## 后果

| 类型 | 内容 |
| --- | --- |
| ✅ 正面 | 热路径毫秒级且一致；LLM 成本与请求量解耦；内容可审计（落库） |
| ⚠️ 负面 | 需要内容缓存与一致性键设计；预生成有滞后（新资源首次访问只能模板兜底）；缓存存储成为依赖 |
| 🔧 需同步 | 新增 `AR-30`（一致性不变量）；`responder.md`；`llm-components.md`；`store` 的内容缓存实体；`config` 的响应段 |

## 失效条件

出现下列任一情形时**必须**重开本记录：

- **模板兜底的保真度被实测证明不足**（首次访问即被识破）→ 重开，评估更激进的预生成策略；
- **`(会话, 资源)` 键的基数爆炸**导致缓存不可行 → 重开，评估按资源类型聚类的生成；
- **一致性不变量与「诱饵多态」冲突**（多态要求同资源不同答案）→ 重开，两者需重新划界。

## 未解决

- **一致性键的粒度**（资源 = 完整路径？含 query？含方法？）—— 实现期定，需与 `sentinel` 的差异检查项对齐；
- **预生成的触发时机**（会话建立时？首次访问资源时？离线批？）—— 与延迟预算一起定；
- **与 `severity` 的交互** —— 加重处置（限速、缺字段）是否破坏一致性，需明确（倾向：不破坏，只改变时序）。
