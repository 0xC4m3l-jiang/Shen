# 0011. 蜜罐：只做模块入口与后端池，具体蜜罐接第三方

- 状态：✅ **已采纳**
- 日期：2026-09-18
- 影响范围：新增模块 `honeypot`（蜜罐入口）；`honeypot-protocol` / `honeypot-shell` 定位为**可选自研实现**；[`../../design/modules.md`](../../design/modules.md) §1.1；[`../../spec/config.md`](../../spec/config.md)
- 决策者：用户
- 依据：用户「蜜罐只做预留、只设计一个入口，类型通过 config 开关，后续管理」的指示 + 行业调研（开源蜜罐成熟度）

---

## 背景

本项目的定位是**欺骗引擎**：判别（`judge`）→ 决策（`director`）→ 透明路由（`adapter-proxy`）→ **幻境后端**。

「幻境后端」就是蜜罐。它的实现有两类现实选择：

- **自研**：协议仿真（SSH / MySQL / Redis / FTP）、命令表、内存文件系统、Web 克隆 —— 成本高，且与欺骗引擎的核心价值**无关**；
- **复用**：行业已有成熟开源实现（Beelzebub ~2.1k★ 覆盖 SSH/HTTP/TCP/TELNET/MCP，Oubliette、honey-ai、RabbitHole 等），
  且它们是**可替换组件**。

参考实现的教训也在这一侧：它把大量工程量投在 SSH 蜜罐 + 欺骗文件系统 + 协议矩阵上，
而那并不是它「拿不到三值决策收益」的原因 —— 缺的是**调度层**（本项目已补）。

用户已明确：**蜜罐只做预留**，当前只做欺骗引擎的核心能力，蜜罐后续接其他人的实现。

## 候选

| 候选 | 内容 | 真实优势 | 代价 |
| --- | --- | --- | --- |
| **A** | **全自研蜜罐**（自己实现协议仿真 + 命令表 + 文件系统） | 与判别深度耦合；可控 | 工程量巨大且**偏离核心价值**；重复造轮子 |
| **B** | **只做入口**：蜜罐类型注册 + config 开关 + 生命周期 + 后端池解析，具体蜜罐**接第三方** | 聚焦欺骗引擎；蜜罐可替换；符合「独立服务 + 接入物料」的交付形态（`INT-9`） | 需定义蜜罐接入契约；依赖第三方质量 |
| **C** | 只做协议蜜罐（部分自研） | 折中 | 仍偏离核心；且「部分」的边界无法稳定 |

## 决定

**采纳 B**：

1. 新增模块 **`honeypot`** —— 蜜罐的**入口与后端池管理**：
   - **类型注册**：蜜罐类型是一个**声明式清单**（见下），每种类型有「是否启用」的开关；
   - **config 驱动**：哪些类型启用、指向哪个后端，全部由配置决定（`ST-24`：策略是数据）；
   - **生命周期**：启动 / 停止 / 健康 / 资源上限（承接 `MD-14` / `MD-15` / `MD-16` 的进程纪律）；
   - **后端池解析**：把 `director` 在 `route_mirage` 中给出的**逻辑后端名**解析到具体蜜罐实例。
2. **具体蜜罐不实现**：接入方可以是第三方蜜罐（Beelzebub 类）、现成服务，或后续的 `honeypot-protocol` / `honeypot-shell`（**可选自研**，阶段 3）；
3. **本设计只登记类型清单，不实现任何一种**。

### 蜜罐类型清单（config 可开关；本设计只登记，不实现）

| 类型 | 仿真对象 | 默认 | 依据 |
| --- | --- | --- | --- |
| `ssh` | 交互式 SSH 假主机（命令表 + 假文件系统） | off | 参考实现重心；行业成熟 |
| `mysql` | MySQL 握手 + 查询捕获 | off | 横向移动常见目标 |
| `redis` | Redis 命令级仿真 | off | 凭证与配置泄露载体 |
| `ftp` | FTP 登录 + 目录列举 | off | 文件泄露路径 |
| `elasticsearch` | HTTP 形态 API 仿真 | off | 数据泄露路径 |
| `nginx-admin` | 假登录控制台（结构化凭证提取） | off | 后台凭证蜜饵 |
| `web-clone` | Web 应用克隆（Playwright 自包含） | off | 站点真实性欺骗（`INT-8`：只改写蜜罐侧） |
| `internal-wiki` | 内网 wiki 假站点 | off | 横向蜜网节点 |
| `database` | 内网数据库假实例 | off | 横向蜜网节点 |

> 默认全部 **off**：蜜罐是**幻境后端**，只有在明确配置并完成影子模式观察后才启用（`INT-11`）。
> 类型清单**可扩展**：新增类型 = 在 `config` 里加一项 + 提供一个满足蜜罐契约的后端，不改代码。

## 理由

### 1. 蜜罐不是本项目的差异化所在

综述与逆向报告共同指向：本项目的机会在**「判别 → 透明路由 → 幻境」这条调度链**，
而蜜罐只是这条链的**末端可替换件**。把工程投在蜜罐实现上，是在补行业已有的轮子。

### 2. 「只做入口」反而提高了能力上限

一个显式的**蜜罐契约** + 后端池，意味着任何满足契约的蜜罐都能接进来 ——
自研的、第三方的、客户的现成蜜罐。这比绑定单一自研实现更符合「独立服务 + 接入物料」的形态（`INT-9`）。

### 3. 与既有的蜜罐纪律不冲突

`MD-14`（进程组回收）/ `MD-15`（资源对称）/ `MD-16`（并发上限）管的是**进程纪律**，
无论蜜罐是自研还是第三方，这些纪律都落在 `honeypot` 的**生命周期管理**里 —— 位置更集中。

### 4. 被动组件边界（`SB-6`）不变

`honeypot` 只做**管理与编排**：它不主动连接任何目标，只承接已被 `route_mirage` 送来的流量。

## 后果

| 类型 | 内容 |
| --- | --- |
| ✅ 正面 | 聚焦欺骗引擎；蜜罐可替换；新增蜜罐类型不改代码；进程纪律集中在一处 |
| ⚠️ 负面 | 需定义并维护**蜜罐接入契约**（否则「可替换」是空的）；保真度取决于第三方；跨进程事件回传需经 `telemetry` |
| 🔧 需同步 | 新增 `honeypot` 模块；`honeypot-protocol` / `honeypot-shell` 从「必做」降为「可选自研」；`config` 增加 `honeypots` 段 |

## 失效条件

出现下列任一情形时**必须**重开本记录：

- **第三方蜜罐不满足核心保真度需求**（如特定协议的一致性、与判别深耦合的实时事件）→ 重开，评估自研范围；
- **蜜罐契约无法覆盖实际的蜜罐形态**（需要的能力超出「被动承接 + 事件回传」）→ 重开；
- **`honeypot-protocol` / `honeypot-shell` 被证明必须与判别同进程**（`MD-4` 依赖方向不允许）→ 重开。

## 未解决

- **蜜罐接入契约的具体形态**（进程外？容器？只读事件流？）—— 实现期定，登记在 `honeypot` 模块文档的未决项；
- **Web 克隆的合规边界** —— `SB-3` / `SB-4` 要求只克隆自有或书面授权站点，克隆能力的落地需台账支撑；
- **蜜罐后端从哪来**（克隆 / 模板 / 影子实例）—— 既有未决项（`modules.md` §7），本决策不改变它，只把「在哪管理」定在 `honeypot`。
