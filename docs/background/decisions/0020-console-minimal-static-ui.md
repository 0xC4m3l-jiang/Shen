# 0020. 控制台的最小实现：Go 进程 + 静态页（暂不引入前端工具链）

- 状态：✅ **已采纳**（用户 2026-09-19：要求「Web UI 显示查看方便，**不用实现的太复杂**」，且此前裁定**不引入 Python/前端工具链**）
- 日期：2026-09-19
- 影响范围：[`../../design/language.md`](../../design/language.md) §1 的**控制台行**（TypeScript）· [`../modules/console.md`](../../modules/console.md) · `console/`
- 决策者：用户
- 依据：`TB-20`（跨层语言须按 §1 选型）· `TB-15`（引入语言就必须有该语言的门禁）· `TB-4`（换某层实现须有决策记录）

---

## 背景

`language.md` §1 把控制台定为 **TypeScript**。但 `TB-15` 要求「引入一种语言就必须有它的门禁」：
Go 有 `make gate` 全套，Python/前端则要 `ruff` + `pytest` / `tsc` + `eslint` + `vitest`。
用户已明确裁定：**不引入那两套工具链**（此前一次未征询的引入已被要求回退）。

同时本轮目标是「**有一个能看告警 / 流量 / 流动的简单 Web UI，方便人工测试**」——
需求本体很小：一个页面、几个只读 JSON 接口。

## 候选

| 候选 | 内容 | 优势 | 代价 |
| --- | --- | --- | --- |
| **A** | **Go 进程 + 静态 HTML（`go:embed`）+ 原生 `fetch`**（采纳） | 无构建步骤 · 单文件二进制 · 复用 Go 门禁 · 交付最简 | 前端能力弱（无组件库、无类型检查）；页面复杂后会难维护 |
| **B** | TypeScript + 现代构建（Vite/React） | 前端生态成熟 | 引入 Node 工具链 + 前端门禁（用户已裁定不引入） |
| **C** | 不单独做控制台，把页面塞进核心进程 | 部署最简 | 违反分层（控制台是独立模块，`AR-10` 控制面不得参与请求路径） |

## 决定

1. **采用候选 A**：控制台是**独立 Go 进程**（`console/cmd/console`），页面是**静态 HTML + 原生 JS**（`go:embed` 进二进制）；
2. **只读**：不做改策略 / 干预请求等写能力（`AR-10`：控制面禁止参与请求级判定）；
3. **渲染纪律**：页面展示的是**攻击者可控**字符串（UA / 路径 / 来源 IP），**必须**用 DOM + `textContent`，**禁止**把数据拼进 `innerHTML`；
4. **`language.md` 的控制台行**在本记录生效期内视为**暂缓**：语言仍记为 TypeScript（长期目标），
   但**当前实现**是 Go + 静态页；等前端需求真的变复杂（需要组件化 / 状态管理）时，**先引入前端门禁再迁移**。

## 后果

| 类型 | 内容 |
| --- | --- |
| ✅ 正面 | 零新工具链 · 单文件交付 · 复用既有门禁 · 人工测试当天可用 |
| ⚠️ 负面 | 控制台暂时不在设计指定的语言上（已知偏离，登记于此）；页面复杂度有上限 |
| 🔧 需同步 | [`../modules/console.md`](../../modules/console.md)（状态 + §7 注明偏离）· 本记录列进决策索引 |

## 失效条件

出现下列任一情形时**必须**重开：

1. 页面需要**组件化 / 状态管理 / 复杂图表**（当前无构建步骤的做法开始拖慢改进）→ 重开，先引入前端门禁再迁移；
2. 控制台需要**写**能力（改策略 / 干预请求）→ 重开（那属控制面能力，另有规则约束）；
3. `TB-15` 的前端门禁被引入（无论出于何种原因）→ 此时候选 B 的代价消失，应重新评估。

## 未解决

- **控制台的多副本与鉴权**：当前单实例、无鉴权（只绑 `127.0.0.1`）。生产化需定访问控制（属控制面安全议题）；
- **观测面的保留期与分页**：内存实现只留最近若干条；接真实存储（ClickHouse）时按 `NI-13` 定；
- 页面的**时间基准显示**：事件 `created_at` 是 UTC、判定载荷 `At` 带本地偏移 —— 页面统一按本地显示，JSON 消费者需自知。
