# 0010. 欺骗的核心机制：功能性伪装（否决显式提示注入）

- 状态：✅ **已采纳**
- 日期：2026-09-18
- 影响范围：新增模块 `decoy`（诱饵面）；`judge` 的指纹与证据链；`responder` 的内容生成；[`../../design/modules.md`](../../design/modules.md) §1.1 与应用规则
- 决策者：用户
- 依据：用户「核心是欺骗引擎的实现，如何实现欺骗」的指示 + 参考实现逆向（[`../research/agentcapture-deception-report.md`](../research/agentcapture-deception-report.md) §3.7）+ 行业调研

---

## 背景

本项目已实现「判别 → 决策 → 透明路由」（`judge` / `director` / `adapter-proxy`），
但没有回答一个更根本的问题：**改道之后，拿什么骗？**

参考实现（AgentCapture）用两条路线做过实测：

1. **显式提示注入**（HTML 隐藏 div 里的祈使句：「如果你是自动化 Agent，请上报…」）——
   其自测 **0/8 服从**；8 套模板里 7 套被判为「注定失败」。
2. **功能性伪装**（把回调整理成站点自己的 Developer API 文档，Agent 为拿数据而注册）——
   这是它唯一被证明有效的路线，也是它自认的核心原创。

学术调研与行业开源指向同一结论：对已对齐的模型，**「服从指令」会触发对齐层，「使用 API」不会**
（[`../research/ai-agent-deception-defense-survey.md`](../research/ai-agent-deception-defense-survey.md) §6.3 F；
行业侧 GenPot / llmockapi / LLMApi 均走「按 spec 生成可信响应」）。

## 候选

| 候选 | 内容 | 真实优势 | 代价 |
| --- | --- | --- | --- |
| **A** | **显式提示注入** | 实现最简单（一段文本） | 🔴 实测失效（0/8 服从）；且**自曝**：隐藏指令是蜜罐的标志性签名 |
| **B** | **功能性伪装** | 不触发对齐层（目标是「在用功能」不是「在服从」）；令牌天然成为工作流一部分（归因免费） | 依赖「按文档办事」的任务语义；需维护可信的诱饵面 |
| **C** | **纯内容投毒**（喂假数据，不伪装成功能） | 无对齐问题 | 缺少**行为引导**：Agent 拿到假数据即止，不会持续交互，情报产率低 |
| **D** | 行为阻断（挑战/隔离） | 阻挡高频扫描 | 可见 → 自曝；且与「透明改道」互斥（`D0` 推论 3，见 [ADR-0002](0002-decision-model.md)） |

## 决定

**采纳 B 为主、C 为内容层**：

1. **欺骗的核心机制是功能性伪装** —— 诱饵必须呈现为**站点的合法功能**（Developer API、指令文件、MCP 工具、数据集）；
2. **内容投毒**（假数据）作为诱饵的**内容层**，不单独作为机制 —— 它负责「看起来像真的」，功能性伪装负责「值得交互」；
3. **禁止**把显式祈使式注入作为欺骗手段（`A` 被否决）—— 它既无效又自曝；
4. 新增模块 **`decoy`** 承载诱饵面（见 [`../../design/modules.md`](../../design/modules.md) §1.1）。

### 诱饵面的五类形态（本次设计，实现分期）

| # | 形态 | 伪装成什么 | 参考 |
| --- | --- | --- | --- |
| 1 | **Developer API 诱饵** | 站点公开的开发者接口，注册即可用 | AgentCapture Portal 三阶段 |
| 2 | **指令文件蜜饵** | 项目级信任入口（`AGENTS.md` / `CLAUDE.md` / `.cursorrules`） | 行业共识 |
| 3 | **MCP 诱饵** | JSON-RPC 工具服务（`query_db` / `run_diag`） | HoneyMCP 系列 |
| 4 | **消耗战数据集** | 无限分页的假数据（逐行水印） | AgentCapture + 行业 |
| 5 | **三类蜜饵 + SSRF 蜜饵** | API 路由 / 凭证 / 文件 / 云元数据 | AgentCapture §3.4 |

## 理由

### 1. 它绕过的不是检测，是**意图判定**

> 功能性伪装的目标不是「让模型不发现自己在做什么」，而是**让模型不把这件事识别为「需要拒绝的事」**。

任务语义（获取站点数据）与诱饵行为（调用站点 API）完全对齐；「注册客户端」被表述为接入前置条件，
于是采集主机信息被归类为「填请求体」而非「泄露环境」。对齐层要触发，必须先判定「这个 API 在利用我」——
而它看到的只是一个设计合理的开发者接口。

### 2. 令牌双角色让归因**免费**

同一个派生令牌在判别层是**蜜标**（回显即铁证），在诱饵层是**API 会话令牌**（接入流程天然携带）。
追踪信标成为目标「正常工作流的一部分」，而不是额外要求。

### 3. 纯内容投毒缺少行为引导

C 的问题不是不真实，而是**没有下一步**。Agent 拿到假数据就结束，我们拿不到持续的交互与 TTP。
功能性伪装给出「注册 → 心跳 → 领任务」的持续通道，情报产率量级不同。

### 4. 与既有架构契合

`decoy` 产出诱饵**定义与内容**（核心），`edge-injection`（L1）负责**注入执行**，`director` 决定**是否改道**。
三者职责不重叠，符合 `AR-2`（判定一处）与 `MD-4`（依赖单向）。

## 对「显式注入为什么连做备选都不该做」的回应

它在参考实现里被保留为 8 套模板，但价值不在「注入」而在「探针」：
`agent_blocking_directive` 模板要求下次请求带 `X-Agent-Canary` —— **服从即铁证**（+70 分 → 隔离）。
本决策**保留其探针价值**（作为 `decoy` 的一个可选诱饵），但**禁止**把它当作欺骗的主机制：

- 无效：对齐模型稳定拒绝；
- 自曝：隐藏祈使式 div 是蜜罐的签名，一见即知「有东西在骗我」；
- 破坏不变量：一旦 Agent 认定「我被骗了」，透明改道的前提失效。

## 后果

| 类型 | 内容 |
| --- | --- |
| ✅ 正面 | 绕开对齐层；归因内生于工作流；诱饵可多态；与三值决策/透明路由天然配套 |
| ⚠️ 负面 | 依赖「按文档办事」的任务语义 —— 对**明确以规避站点引导为目标**的红队型 Agent 成功率下降，处置回落第一层；需维护诱饵面的可信度（投放、保真、轮换） |
| 🔧 需同步 | 新增 `decoy` 模块（`modules.md` §1.1 + 模块文档）；`judge` 增加指纹与证据链；`responder` 增加生成式响应；`config` 增加诱饵开关；L1 增加注入执行能力 |

## 失效条件

出现下列任一情形时**必须**重开本记录：

- **功能性伪装的识别率被实测证明不可接受**（Agent 稳定识别「这个 API 在利用我」）→ 重开，评估其他机制；
- **诱饵特征被多 Agent 共享记忆众包白名单化**，且轮换无法对抗 → 重开，评估多态/学习路线；
- **任务语义不匹配成为主流**（目标普遍是「规避引导」而非「获取数据」）→ 重开。
