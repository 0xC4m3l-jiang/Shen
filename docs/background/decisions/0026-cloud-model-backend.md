## 背景

用户要求接入 DeepSeek 云端模型，用于**离线生成欺骗内容**（`kind=content`），并要求
「保证生成信息的安全与合规」+「相关信息可以在控制平台查看」。

三条既有约束挡在前面：

1. `analysis/aicap` 的**禁止依赖表**写着「任何网络出站库」——云 API 就是网络出站；
2. `ADR-0023` 的**失效条件 4**写着「模型后端必须出网 ⇒ 需单独 ADR」（本文即该 ADR）；
3. 多处文档声称「**生成器必须确定性**（同输入逐字节同输出）——这是 `AR-30` 的前提」。

不决定的代价：要么接不了模型（放弃多样性），要么在没有任何信任边界记录的情况下把观测发给第三方厂商 ——
后者是不可逆的（数据一旦出网就收不回）。

## 候选

| 候选 | 它擅长什么 | 它的代价 | 什么条件下它最优 |
| --- | --- | --- | --- |
| **A** | **本地 / 自托管模型**（vLLM + 本机权重） | ① **数据不出网**（最大的优点）；② 无供应商依赖、无配额；③ 延迟可控 | 🔴 需要 GPU 或量化权重 ⇒ 部署与运维成本；🔴 小模型在「像不像真实业务」上明显弱于前沿云模型 ⇒ 可能白接（多样性还是不够）；🔴 许可证台账要重新过一遍 |
| **B** | **云 API**（DeepSeek） | ① 零运维、零 GPU；② 质量高（探查显示能稳定产出合规 HTML 片段）；③ **支持结构化输出**（`json_object`），与 `AR-15` 的「结构由独立代码层校验」天然合拍 | 🔴 **观测与画像离开本方边界**（新的信任边界）；🔴 配额、可用性、供应商变更都成为外部依赖；🔴 按 token 计费，成本与内容量成正比 |
| **C** | **保持模板生成器**（不接模型） | ① 零风险、零成本、零依赖；② `AR-30` 的论证最简单 | 🔴 多样性不足（N=8 固定变体，措辞规律本身是**指纹面**）；🔴 「像不像」这件事永远无法验证 |

## 决定

**采纳 B**，并定下四条配套纪律。

### 决定 1 · 数据出网面压到最小

发给模型厂商的**只有**：

- **去敏后的画像**（`style_terms` 这类站点术语，不含真实资产标识）；
- **结构化观测的字段值**（资源路径、方法、判定信号等**已在数据区**的内容，`AR-31`）。

**不发送**：原始 URI 查询串、原始 UA、来源 IP、真实主机名与内网地址（`AR-22` 的泄露类清单）。

**理由**：这几样正是「识别客户身份」最有用的东西，而对生成「像不像的页面」没有贡献。
这条纪律的判据是：**把它们从数据区里删掉，生成质量不受影响**（下一轮接入时用同一组输入对比验证）。

### 决定 2 · **澄清**：生成期确定性**不是** `AR-30` 的要求

**核对 `AR-30` 原文**（`docs/design/architecture.md`）：

> 任何伪造响应**必须**按 `(会话, 资源)` 命中同一内容 —— 重试 / 重放 / 翻页都得到同一答案。
> **禁止**在**响应路径**上引入非确定性（随机数、当前时间、LLM 采样）。

它管的是**响应路径**。而多处文档把「**生成器**必须逐字节可复现」写成了 `AR-30` 的前提 ——
那是**阶段 A 的工程性质**（让通路可回归、让清单可复现），**不是规则要求**。

**决定**：

- **`AR-30` 一字不改**（它本来就没管生成期）；
- 纠正 **18 处**过度声称（清单见变更包 §5 场景 3）—— 它们把「生成期可复现」写成了 `AR-30` 的要求；
  其中 **ADR-0023 追加了一条「修正（2026-09-21）」**（历史快照不改正文）；
  `kb/ai-capabilities.md` §2.5 · `aicap/tasks/content.py` 与 `aicap/content.py` 的 docstring）；
- 热路径的字节一致改由**三条**保证（都不依赖模型可复现）：
  1. **产物冻结进清单** —— 分发的是清单字节，与生成过程无关；
  2. **`content_id` 由内容体算出** —— 同一份内容必得同一个 id（`content_id_of` 对 `body` 取哈希）；
  3. **会话内钉定** —— 同会话同资源恒同槽位（`variant = hash(session) mod N`，适配器钉定带 TTL）。

### 决定 3 · 适配器落在**唯一接缝** `analysis/aicap/model.py`

- 只暴露**一个**公开方法 `complete(prompt, *, session_id, timeout) -> str`（`AR-32`：不得有
  `tool` / `exec` / `request` / `http` / `url` 之类成员名）；
- 只依赖**标准库** `urllib.request`（**不引第三方 SDK**：少一个依赖面，也就少一次许可与供应链审查）；
- 用 `response_format={"type":"json_object"}`（实测可用），但**仍然**由 `llm.extract` 三段式提取 +
  `llm.contract` 校验 —— 结构化输出是**降低解析失败率**的手段，**不是**替代 `AR-15` 的理由。

### 决定 4 · 密钥只经环境变量

`SHEN_AICAP_MODEL_KEY`（或部署侧等价物）**必须**来自环境变量或密钥文件，**禁止**入库
（`ST-20` / `ST-21`，`.gitignore` 已忽略 `.env` 与真实配置）。**密钥禁止**出现在
日志、清单、遥测事件与控制台页面里。

## 理由

**为什么是 B 而不是 A**：A 的最强优点是「数据不出网」——这条用**决定 1** 回应：
把出网面压到「去敏画像 + 已在数据区的结构化观测」，剩下的泄露风险与「把同一批观测写进核心日志」
处于同一量级。而 A 的代价（GPU / 量化模型质量）会让「接模型」这件事**大概率白接**，
即花了成本仍解决不了多样性问题。

**为什么是 B 而不是 C**：C 的最强优点是「零风险」——但它把问题**推迟**而不是解决：
静态诱饵会被渐进识破（调研已证），多样性是这套机制能否成立的前提，不是优化项。

**为什么决定 2 必须先做**：只要「生成器必须逐字节可复现」还被当成规则要求，
接入模型就永远过不了自己的评审 —— 而那条要求**本来就不存在**，是文档自我加码。
先把规则与工程性质分开，接入才有清晰的成功判据。

## 后果

**正面**：

- 「接云模型」从「违规」变成「有边界记录的决策」：出网面、密钥来源、失败语义都写清了；
- 生成质量可望真正提升（实测：模型能稳定产出通过四关的 HTML 片段，且支持结构化输出）；
- `AR-30` 的论证变**更强**而不是更弱 —— 它从「依赖生成器可复现」变成「依赖产物冻结 + 内容寻址 + 会话钉定」，
  这三条在模型下**依然成立**；
- 顺带修掉一个真实缺陷：`import analysis.aicap.tasks.content` 的循环导入（消费方最自然的写法此前会炸）。

**负面 / 代价**：

- **数据出网成为既成事实**（哪怕只有去敏画像与结构化观测）—— 这是本 ADR 唯一不可逆的部分；
- 生成成本与内容量成正比（按 token 计费），需要配额与成本上限（见「未解决」）；
- 供应商成为可用性依赖：离线批次的失败率从此与第三方挂钩（**但热路径不受影响** ——
  本轮接入的是**离线** `kind=content` 的 `produce`，响应路径**不**经过它）。
  ⚠️ **注意范围**：`AR-30` 的适用面含 **L2 会话仿真与响应生成**（`docs/design/architecture.md` §5）；
  一旦哪一天让模型在**响应时**生成，那就不再受本 ADR 保护，而直接受 `AR-30` 约束
  （必须预生成或把结果钉定）。

**引入的新风险**：

- **密钥泄露**：缓解 = 只经环境变量 + 不入库 + 不进日志（决定 4）。用户已把一个 key 粘到对话里，
  该 key **应视为已泄露并轮换**；
- **模型可能成为新的指纹面**（同一厂商的内容风格趋同）⇒ 与「多样性能否解决指纹」是同一个待验证问题。

**被排除掉的可能性**：

- 把原始观测（含 IP / UA / 查询串）发给模型 —— 除非失效条件 3 触发；
- 引第三方 LLM SDK（如 `openai` 包）—— 除非出现必须的能力缺口。

## 失效条件

1. **决定 1 的「删掉去敏字段不影响质量」被证伪**（同一组输入下去敏前后生成质量明显下降）⇒
   出网范围需重开（可能必须回退到候选 A）；
2. **成本或配额成为实际瓶颈**（例如单次全量生成超过约定预算）⇒ 需要定「生成预算」并把
   「按需生成 / 增量生成」纳入设计；
3. **必须发送原始观测**才能生成（去敏后模型无法产出合规内容）⇒ 候选 A 重新进入比较；
4. **供应商侧出现上述模型不可用 / 下线 / 条款变更** ⇒ 适配器可替换性必须被验证
   （决定 3 的「只依赖标准库」正是为此）；
5. **实测发现模型输出在 `AR-22` 三类上频繁越界**（拒绝率过高导致批次不可用）⇒
   需要重新评估提示词与风格画像，而不是放宽护栏。

**复查日期**：2026-12-21（或首个真实批次跑完时，以先到者为准）。
