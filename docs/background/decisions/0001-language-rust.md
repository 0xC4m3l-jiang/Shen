## 背景

新增了一条**「保证」型**硬约束：**必须保证不影响原始业务**（`NI-1`，最高优先级）。

这条约束的难点在于它是「保证」而不是「努力」——它要求架构机制承担可用性，而不是靠代码写对。
语言选择因此必须回答：**该语言能在多大程度上让"不影响业务"成为结构性事实，而不是纪律要求。**

**不决定的代价**：`shen-core` 与两个编译目标（ext_proc 服务 / Envoy WASM filter）的划分无法落地；
判别与调度逻辑会被迫在两个目标里各实现一遍（双份缺陷面）。

## 候选

| 候选 | 它擅长什么 | 它的代价 | 什么条件下它最优 |
| --- | --- | --- | --- |
| **A. Rust 全覆盖**（在线全 Rust + 离线 Python） | 结构性无 GC（尾延迟不抖动业务）；编译期排除整类缺陷；`shen-core` 纯逻辑 crate 可同时供 ext_proc 与 WASM 使用 | 异步复杂度（`tokio` + 生命周期 + `Pin` + async trait）；编译时间长，AI 生成代码易陷入编译—修复长循环 | 有两个以上编译目标、且必须共用同一套判别逻辑时 |
| **B. Go 做控制面，Rust 留给 WASM 层** | 增量编译 1–5 s；`go test -race` / `-fuzz` / `-bench` / `net/http/pprof` 内建；隐式接口使测试替身极轻；gRPC 生态成熟 | GC 抖动对毫秒级延迟敏感场景不友好；`switch` 不强制穷尽（漏改分支不报错）；若同时需要 WASM，判别逻辑要写两遍 | 不需要 WASM filter，且开发速度权重高于尾延迟时 |
| **C. 分层多语言**（L0 C/Rust + L1 Lua + 核心 Go + L2 Python + 控制台 TS） | 每层用该层生态最成熟的库 | 5 套工具链与 CI；跳语言可观测性需统一 OTel；跨语言 FFI 边界不可独立升级/独立崩溃 | 团队规模足以支撑多套工具链，且各层确有独立演进需求时 |

> 候选 C 是 `docs/research/deception-engine-design.md` §2.1 / §6.1 的提案，此处如实记录。

## 决定

**在线组件用 Rust，离线能力用 Python，全项目两种实现语言。**

```text
shen-core      纯逻辑：Judge / Director / 策略求值（禁止任何 I/O）
   ├──► shen-control   ext_proc 服务（tokio + tonic）
   └──► shen-wasm      Envoy WASM filter（proxy-wasm）
```

## 理由

**对候选 A 的证据**：`NI-1` 要求的三项保障 —— 尾延迟不劣化业务、不抢业务资源、不含会打挂业务的 bug ——
Rust 是**结构性**满足（无 GC / 小 footprint / 编译期排除），Go 是**纪律性**满足（可压但存在）。
V-5（CPU 饱和打压引擎，业务 P99 不劣化）正是这三项的直接验证。

**对候选 B 最强优点的回应**（开发速度与 profiling 确实 Go 胜）：
本项目的形态允许把 Rust 的最大摩擦源关进笼子 ——
`ext_proc` 处理器是**线性 5 阶段**状态机（不是任意状态爆炸）；插件集是**封闭集合**，
因此用 `enum` 分发即可完全避开 `dyn Trait` 的 object safety 与 async trait 问题（见 `TB-10`）。
代价从「不可避免」降为「有界的」。开发速度的劣势由 `cargo check` 内循环 + workspace 拆分 + `sccache`/`mold` 缓解（`TB-17`）。

**对候选 C 最强优点的回应**（每层用最成熟的库确实合理）：
本项目是**一个服务**，不是一套平台（`INT-9`）。`TB-3` 禁止第三种语言换来的收益是
**判别与调度逻辑只实现一次且两个编译目标共用**（`TB-7`）—— 这是候选 C 无法提供的：
它的「核心 Go」与「L1 Lua」必然导致判定逻辑分裂两处，而这正是审计偏差 B3 指出的失败模式。

> **必须同时承认**：`NI-1` 的保证**主要来自架构，不是语言**（`NI-2` 明确禁止以语言作为依据）。
> 语言只提供额外保险。若把保证寄托在这条决策上，设计就已经错了。

## 后果

- **正面**：`shen-core` 一处实现、两个编译目标；编译期排除整类缺陷；无 GC 抖动；可 `#![forbid(unsafe_code)]`（`TB-13`）。
- **负面**：迭代速度慢于 Go；异步 Rust 是 AI 生成代码迭代次数最多的形状；编译时间是真实成本。
- **引入的新风险**：把「不影响业务」误认为已由语言保证，从而跳过架构机制（`NI-2` 专门禁止）。
- **被排除掉的可能性**：第三方插件生态（Rust ABI 不稳，只能走 WASM/gRPC）；即便需要，也应先有 ADR（`TB-4`（新增语言层必须先有 ADR））。

## 失效条件

- 当 **spike（见下）显示 ext_proc 形态下每次改动需数十次编译迭代**，导致迭代成本不可接受时 —— 触发 `TB-18`，控制面可回退 Go，Rust 只留 WASM 层。
- 当 **确认需要实现独立的第三方插件市场**（而非内部能力增长）时 —— 候选 B/C 的优势会反超。
- 当 **团队构成发生结构性变化**（如完全没有 Rust 经验且无学习窗口）时。
- 复查日期：**2026-12-17**

> **触发 `TB-18` 必须同时满足三条**：① spike 数据记录在案；② 用户确认；③ 新增 ADR。
> 即使触发，`TB-6` / `TB-7` / `TB-9` / `TB-12` 依然有效。
