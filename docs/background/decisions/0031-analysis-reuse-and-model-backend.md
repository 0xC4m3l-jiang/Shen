## 背景

[ADR-0024](0024-ai-oss-reuse-boundary.md) 定了**判据**（默认行为是否 fail-closed、是否接管处置语义、是否破坏确定性）
并关闭了 ADR-0023 未解决 1/2 的**前置条件**（Python 依赖审计面），但留了四项未解决。
本轮要把 L4 的三个分析（`intent` / `chain` / `strategy`）接到模型上 ——
那正好把四项未解决全撞上：**接哪个后端、怎么保证结构化输出、外发数据里的 PII 怎么办、
以及消费者侧那几百行到底该不该复用**。

不决定的代价：

1. **`AR-33` 会成为一段空话**。任务登记表此前只登记 `content`，而 `intent` / `chain` / `strategy`
   的提示词早已写好（躺在 `analysis/llm/resources/prompts/` 下，只被单测渲染过）。
   只要有人「先把模型接上」，最自然的写法就是在 `worker.py` 里直接调客户端 ——
   那会绕开两道护栏，而门禁的结构检查（`MD-4`）只能拦「谁 import 了客户端」，拦不住「护栏被跳过」。
2. **两套提示词系统会固化**。`llm/resources/prompts/` 与 `aicap/resources/prompts/` 并存
   已在 `kb/ai-capabilities.md` §10 发现 1 里记过一次；再拖一轮，第二套就会长出它自己的约定。
3. **「模型说的」会被当成「算出来的」**。两条路的产出形状相同、可信度不同，
   若不写清是谁产的，读结论的人无法分辨。

## 决定

### 决定 1 · 模型后端与结构化输出：**云模型 + 现有三段式提取 + 独立契约校验**

- 后端＝**云模型**（[ADR-0026](0026-cloud-model-backend.md) 已拍板 DeepSeek），
  适配器落 `analysis/llm/deepseek.py`，**只依赖标准库**（`http.client`），**只暴露一个公开方法** `complete`；
- 结构化输出＝**既有的**三段式提取（`llm/extract.py`，`AR-17`）+ **独立的**契约校验（`llm/contract.py`，`AR-15`）
  + 后置护栏四关（`aicap/guardrail/inspect.py`）；
- **不引入** `Outlines` / `Instructor`：两者的默认行为与本项目的 `AR-15` 不同向
  （一个做约束解码、一个做 Pydantic 重试与修补），而 `AR-15` 要的是「不合规即拒绝，不修不补」；
  且它们会进调用图，与 ADR-0024 决定 1 的第 2 条（不接管处置语义）冲突。
- 环境变量（**只经环境变量，禁止入库** —— `ST-20` / `ST-21`）：
  `SHEN_AI_KEY`（必需）· `SHEN_AI_BASE`（默认 `https://api.deepseek.com`）·
  `SHEN_AI_MODEL`（默认 `deepseek-flash`）· `SHEN_AI_TIMEOUT_S`（默认 `30`）。
  缺 key ⇒ 显式失败的客户端；**超时写错 ⇒ 抛异常**（不悄悄换默认值）。

### 决定 2 · PII 与泄露识别：**本轮不引 Presidio / detect-secrets**

- 不引的理由：两者的形态（NER 模型文件 / 密钥扫描器）与本轮的**实际威胁面**不匹配 ——
  今天外发的内容是「去敏画像 + 已在数据区的结构化观测」（ADR-0026 决定 1），
  而 PII 的识别对象（自由文本里的姓名/邮箱/证件号）在本轮**还不存在**（模型的自由文本只有 `rationale`，≤500 字）；
- 本轮的落实方式（两道，都不新增依赖）：
  ① **提示词禁令**：三个模板明确禁止回显原始 URI 查询串 / `User-Agent` / 来源 IP；
  ② **受检字段**：`rationale` 是每个任务的 `checked_fields`，于是黑名单三类（泄露 / 自曝 / 超长）
  与风格一致性都对它生效；
- **已知缺口**（不假装它被守住）：**原始 URI 查询串与 UA 的机器识别并不存在** ——
  黑名单能抓的是内网地址（内置正则）与部署方注入的真实业务标识（`AR-22`）。
  该缺口记在变更包 §7，触发条件见失效条件 2。

### 决定 3 · `Faker` vs `Mimesis`：**阶段 B 再选**，本轮只记判据

判据（按优先级）：① `seed()` 的可复现性（跨版本同种子是否同产出 —— 破 `AR-30` 就作废，ADR-0024 失效条件 5）；
② `locale` 覆盖与中文数据的可信度；③ 依赖面（是否拖入科学计算栈）。
**本轮不做基准**：今天没有生成假数据的调用方，做基准等于给一个还不存在的需求先付费。

### 决定 4 · L4 复用边界：**以调研材料的结论为准（零新增运行期依赖）**

- `Sigma` / `OSSEM` / `NetworkX` = **⛔ 不复用**（理由各异：输出侧署名义务 / 停更 31 个月 / 没有图算法需求）；
- `MITRE ATT&CK` / `OWASP CRS` = **🟡 只借知识**（术语对齐 / 特征形态参考），不引入数据集与规则引擎；
- 结论：`analysis/requirements.txt` **保持三项**（`grpcio` / `protobuf` / `PyYAML`）。

### 决定 5 · 落地口径（本轮新出现的三个具体取舍）

| # | 取舍 | 决定 | 理由 |
| --- | --- | --- | --- |
| 1 | 三个 L4 任务的**提示词放哪** | 迁到 `analysis/aicap/resources/prompts/`，并按三段式改写 | 它们是**任务**的提示词，而任务必须登记在 `aicap`（`AR-33`）；两套系统合并 = 消灭 `kb/ai-capabilities.md` §10 发现 1 |
| 2 | 三者的**契约（schema / 类别闭集 / 阈值下界）放哪** | 新模块 `analysis/llm/schemas.py`，领域模块从那里导入（**只定义一次**） | `aicap` 只允许依赖 `analysis.llm` 与自己（`MD-4`）；把契约放领域模块会让 `aicap` 无法声明它，两边各写一份则会漂移（先例：`spec/events.md` §4） |
| 3 | 结论里的**生成器标识** | `generator` ∈ {`model-v1`, `rules-v1`}（任务声明的 id，**不**写模型名） | 适配器**只暴露 `complete`**（`AR-32` 的成员名检查），拿模型名就得再开一个公开成员；`model-v1` 已能回答「这份结论是谁产的」 |

### 决定 6 · `AR-30` 的适用面不改（重申）

本轮接的是**近线/离线**的三步分析；**热路径仍然零模型**（`AR-29` / `AR-30`）。
worker 的模型路径失败时**回落确定性版**，整轮仍然成功（`NI-1`）；
回落原因记进 `AnalysisRun.model_rejected` 与结论载荷的 `model_rejected` ——
**不**把它写进 `errors`（`errors` 只装「本轮真的没做成的事」，两者混在一起会让「有回落但成功」看起来像「失败」）。

## 理由

**为什么后端用云模型而不是本地自托管**：ADR-0026 已就这一点拍板（数据出网面被压到「去敏画像 + 数据区观测」，
与「把同一批观测写进核心日志」同量级）。本 ADR **不重开**那个决定，只补它在结构化输出侧的具体口径。

**为什么坚持零新增运行期依赖**：不是洁癖 —— 三条具体收益：① 离线可跑（`make gate` 不依赖网络）；
② 无供应链与升级负担；③ 许可台账继续只有三项要审。
而材料显示，能替掉那几百行的东西**根本不存在**（§4 的五条空白），
唯一「对口」的 NetworkX 解决的是**不存在的问题**。

**为什么闭集与阈值边界要放进 `llm/schemas.py` 与任务 `build`**：
`AR-15` 禁止默认值，而越界类别此前会被静默回落成 `reconnaissance`（`intent/recognize.py`）。
闭集由 `Field.allowed` 守（拒绝而非回落）；`INT-11` 的数值边界（灰度上限 / 阈值下界）
不属于内核固定的四个检查点（ADR-0025 决定 1），所以在任务的 `build` 里显式失败 ——
为它扩内核的影响面远大于在一处 fail-closed。

**为什么回落原因不进 `errors`**：`errors` 的既有语义是「本轮哪里没做成」（遥测不可达 / 链作废 / 上报失败），
而模型不可用是**设计内的降级** —— 确定性版已经产出结论，整轮是成功的。
把两者混起来会让 `--once` 的退出码把「成功但有回落」报成失败，也会让 operator 学会忽略 `errors`。

## 后果

**正面**：

- `AR-33` 的覆盖从「只有内容」变成「四类生成全在内」：`intent` / `chain` / `strategy` 都经唯一出口 + 两道护栏；
- 提示词系统**合并为一套**（`aicap/resources/prompts/`），`kb/ai-capabilities.md` §10 发现 1 关闭；
- 结论新增 `generator` / `model_rejected` 两个审计字段：读结论的人能分辨「模型说的」与「规则算的」，
  也能看到模型那一路为什么没成 —— 这是将来做质量对照的**前提**；
- 两条路产出**同一 schema 形状**（`strategy` 的规则版也补了 `rationale`），使并排比较成为可能 ——
  **但不完全逐字相同**：规则路的 `data` 另有可选的 `truncations`（`AR-18` 的截断记录，模型路没有）。
  读结论的人不应假定两侧键集相等（[`spec/events.md`](../../docs/spec/events.md) §3 已写明这层可选项）。
- 依赖面零增长：`requirements.txt` 仍是三项。

**负面 / 代价**：

- `SHEN_AI_KEY` 成为**运行环境的一个前置条件**（只有 `--llm` 才需要；默认关闭 ⇒ `make gate` / `make dev` / CI 不受影响）；
- 结论载荷加了两个字段 ⇒ **幂等键（`event_id` 的摘要）随之改变**：同一批事件在升级后会产生新的结论事件
  （旧结论仍在遥测里，靠 `AR-11` 的幂等键去重 —— 不会重复入库，但控制台会同时看到新旧两条）；
- 三段式提取的**失败率**现在是真实指标（此前只有探针样本，样本量 3）。

**引入的新风险**：

- **模型路径被拒 ≠ 结论消失**：回落会让结论照常产出，但产出者变成规则版 ——
  若没人看 `model_rejected`，团队会以为模型在工作。故它同时进结论载荷与 worker 日志两处。
- **`Field.allowed` 只作用于字符串字段**：`chain` 的 `stages[].name` 与 `broken_decoy_signals[]` 的闭集
  **没有机器守卫**（只靠提示词 + worker 的形状校验）。这是本轮明确接受的缺口（变更包 §7 有记）。

**被排除掉的可能性**：

- 引 `Outlines` / `Instructor` 做结构化输出（决定 1）；
- 引 `Presidio` 做 PII 识别（决定 2，条件是失效条件 2）；
- 引 `NetworkX` 做链还原（决定 4）—— 尽管它许可干净、极其活跃；
- 在 `worker.py` 里直接调模型客户端（那会绕开 `AR-33` 的唯一出口）。

## 失效条件

写成可观测的触发条件：

1. **三段式提取的实测失败率超过 10%**（按 `run.model_rejected` 里的提取类原因占比统计，样本 ≥100 次模型调用）
   ⇒ 重开决定 1：评估带 `strict=True` 的修复型解析器（ADR-0024 失效条件 1 仍然适用）；
2. **需要识别自由文本里的 PII**（姓名 / 邮箱 / 证件号）或需要对完整请求行做泄露扫描
   ⇒ 重开决定 2：引入 Presidio（或等价物）并单独过许可台账（`TB-16`）；
3. **真出现图算法需求**（跨会话攻击者图、路径搜索、环检测）⇒ 重开决定 4 之中的 NetworkX 一项，
   并给出「为什么 hash 分组不够」的具体用例；
4. **任一被借知识的上游改了许可**（ATT&CK / CRS）⇒ 立即复核本材料的 §3.1 / §3.2 判定；
5. **OSSEM 复活并重新活跃**（12 个月内有提交）⇒ 它的判定从 ⛔ 回到「重新评估」；
6. **`SHEN_AI_TIMEOUT_S` 或 `SHEN_AI_MODEL` 的默认值被证实在真实部署里不合适**
   ⇒ 只改默认值，不改契约（本 ADR 不重开）。

**复查日期**：2026-12-21（或阶段 B 立项时，以先到者为准）。
