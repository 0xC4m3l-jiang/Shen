## 3. 知识点盘点：这份语料让你「会」了什么

### A. 概念与词汇（能参与学术对话）

1. **欺骗的四要素分类框架**（`1712.05441`）与博弈论/ML 两条研究线（`2101.10121`、`1903.01442`）
2. **超博弈 on graphs**：把「防御方对攻击者认知的建模」形式化（`2008.03210`）——调度策略的理论骨架
3. **LLM 蜜罐的两条工程路线**：有状态多 Agent 架构（`2606.27990`）／ 投机执行降延迟（`2606.17986`）
4. **HoneyRoute 的路由范式**：「检测 → 路由到蜜罐」已被证明可行（`2609.08306`），但发生在**模型服务层**
5. **代理必须是有状态的**：时序累加器范式（`2606.20746`）
6. **加密流量让内容判别退化**：QUIC 感知中间盒的难题（`2602.03354`）

### B. 判断力（知道什么会失败）

1. **静态诱饵会被渐进识破**（AgentSnare `2607.26998`）→ 诱饵需要多态 + 调度需要学习
2. **LLM 攻击者能推理 artifact 识破传统蜜罐**（`2609.08093`）→ 「真实性 + 隐蔽性」前提失效
3. **显式提示注入对已对齐模型无效**（AgentCapture 自测 0/8）→ 必须功能性伪装
4. **规则型 WAF 对新变体检测率 < 12%** → 量化了「不靠拦截靠欺骗」的动机
5. **多 Agent 共享记忆会众包识破蜜罐令牌**（`2608.11436`）
6. **单事件判别必然失效** → 判别必须会话级有状态

### C. 一手工程细节（可以照着设计）

 1. **AgentCapture 的五类欺骗面**：HTML 注入／路径蜜饵／凭证蜜饵／站点克隆／功能合法性
 2. **功能性伪装三阶段**：可见页脚 API 文档 → 幂等注册 → 心跳即任务通道
 3. **令牌双角色**：同一 HMAC 在检测层是蜜标、在诱饵层是 API 令牌
 4. **蜜饵面必须 observe-only**：否则在第一步就掐断自己的情报源
 5. **会话水印凭证**：把会话身份编码进造假凭证，让「复用」成为归因事件
 6. **12 项源码级工程发现**（含 3 处设计自相矛盾），以及它**没有**调度层的根因

### D. 方法论纪律（本轮新装 skill 覆盖）

 1. `research-survey`：检索 → 结构化提取 → 空白矩阵 → 证据分级
 2. `design-decision`：候选对比 + 负面后果 + **失效条件**
 3. `threat-model`：对手分档 + **识破路径表**
 4. `spec-first-dev`：决策未定不写代码
 5. `adversarial-benchmark`：先定指标与失效判据、对照组与消融组

## 4. 语料的三个系统性偏差

| # | 偏差 | 后果 | 对冲方式 |
| --- | --- | --- | --- |
| **B1** | **确认偏误** | 语料是为「论证空白存在」而收集的，缺反证。「找不到反例」被当成了「没有反例」 | 主动执行 G1：专门去找「做过但没用」的证据 |
| **B2** | **论文层偏重** | 工程、生态、合规三层几乎空白。而本项目的差异化**恰恰在工程层** | 补 G2 / G7 / G10 |
| **B3** | **单一样本** | 全部工程知识来自 AgentCapture，而它的架构是「内联响应」。我们做的是「透明路由」——**它的失败模式不等于我们的失败模式** | 找第二个参考实现（哪怕不同层次），或自建最小验证 |

## 5. 直接回答「思考够不够」

**不够，但方向是对的。** 具体分档：

| 层 | 状态 |
| --- | --- |
| 「这个领域长什么样」 | ✅ 够了 |
| 「空白在哪里、为什么是空白」 | 🟡 论文层够了，**生态层没验**（G1） |
| 「怎么做出来」 | ❌ **不够**（G2、G7、G8） |
| 「对手是谁、怎么识破我们」 | ❌ **不够**（G3） |
| 「怎么证明有效」 | 🟡 有素材，无设计（G5） |
| 「能不能合法地做」 | ❌ **不够**（G9） |
| 「叫什么、怎么说」 | ✅ 够了 |

**最小可行动作**：补 G1 + G2 + G3 三项，就可以开始写设计与选型了；
其余缺口可以边做边补，但 G1/G2/G3 不补就动手，风险是**架构选错**或**结论站不住**。
