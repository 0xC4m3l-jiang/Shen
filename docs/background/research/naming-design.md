## 1. 为什么从「海市蜃楼」取名是对的

不是因为它好听，而是因为它给的不只是一个名字，而是**一整套自洽的命名空间**——这是绝大多数取名方式给不了的。

### 1.1 理由一：语汇格完整，一个语源喂饱所有模块

「海市蜃楼」不是孤立的四字成语，它的背后是一条**完整的发生链**，每一环都能对应一个工程组件：

```text
蜃（生成者）──呼出──► 蜃气（介质）──凝成──► 海市／蜃楼（幻象本体）──呈现──► 蜃景（被看见的景）
      ↑                                              ↑
   本引擎的核心                                  幻境后端池
```

对照：`Fata Morgana` 只能给你一个名字（整个项目叫这个名字，模块还得另起）。`蜃` 给你一整套**同源、可推理、互不重叠**的模块名（见 §3）。

### 1.2 理由二：它命名的是「生成者」，不是「幻象」

这是全文最重要的一条判据。

「海市蜃楼」作为成语，词典义是「**比喻虚幻不实的事物**」。如果项目叫「海市」或「蜃景」，名字描述的是**幻象本身**——而幻象是攻击者看到的东西，不是你的系统。

而「**蜃**」是**吐气成楼台的那个东西**。它描述的是**生成并调度幻象者**——恰好就是架构里 `Director` 的位置（`docs/research/agentcapture-deception-report.md` §7.3）。

> **命名判据**：引擎叫生成者，不叫产物。
> — 反面：`Mirage` / `Phantom` / `Decoy` / `Honeypot` 全部在命名**产物**，它们描述「假的」，不描述「把你去哪」。

顺带解决了一个品牌风险：成语义偏负面（「虚妄」），但单字「蜃」的主体性是**主动的、施动的**——是你在制造蜃景，不是你是蜃景。对外文案必须守住这条（见 §8.6）。

### 1.3 理由三：汉字文化圈的公共词汇，天生国际化

| 语言 | 词 | 来源 |
| --- | --- | --- |
| 中文 | 蜃景 / 海市蜃楼 | — |
| 日文 | **蜃気楼**（しんきろう） | 同源汉字词 |
| 韩文 | **신기루**（sin-giru） | 同源汉字词 |

一次性讲清楚的名字，在东亚三个市场不用重新起名。而且它的西文对应物 **Fata Morgana** 是**同一种物理现象**（大气折射形成的上蜃景 / superior mirage）——所以中英双名不是「翻译关系」，而是「**同一现象在不同文明中的各自命名**」，这在品牌叙事上是加分项而不是替代关系。

## 2. 语源考据（五段原文，逐段核验）

考据不只是装饰：**「蜃」的词义演变本身，就是这个引擎的设计说明书。**

### 2.1 最早义：一种实有的东西 —— 大蛤的壳

> **《周禮·地官司徒·掌蜃》**：「掌蜃：掌斂互物蜃物，以共闉壙之蜃。祭祀，共蜃器之蜃。共白盛之蜃。」 〔甲级 · 维基文库原文核验〕

解读：周代有专职官吏叫「**掌蜃**」（编制：下士二人、府一人、史一人、徒八人），职责是征收蛤蚌之属，用途有三——填塞墓穴（闉壙）、制作祭器（蜃器）、**把墙壁涂白**（白盛，即烧蜃壳成灰）。

**关键洞察**：`蜃` 最早的用法是一个**完全实有的、功利的、可以被官府征收的东西**——用来刷墙的贝壳灰。

**它后来才成为「吐气成楼台城郭」的幻觉之源。**

> **一个先有实物、后被赋予幻象之名的字——正好就是本引擎要做的事：用真实的内容（真实业务的响应、真实的克隆页面）去生成一个并不存在的后端。**

这条考据建议直接写进 README 的第一段。

### 2.2 变形神话：陆上的鸟变成海中的蜃

> **《禮記·月令》**孟冬之月：「水始冰，地始凍。**雉入大水為蜃。**虹藏不見。」 〔甲级 · 维基文库原文核验〕

解读：古人相信冬天野鸡潜入大海，会变成蜃。

这是「蜃」的**第二次身份**：一个**变形者**（transformation）——陆生之物化入水中，获得另一种形态。

**映射**：这正是**诱饵多态（polymorphism）**的古典表述。对抗多 Agent 共享记忆的众包识破（综述空白区 F），靠的就是「诱饵要能变成另一个形态」。

### 2.3 最早的「蜃气成楼台」记载

> **《史記·天官書》**：「……金寶之上，皆有氣，不可不察。**海旁蜄氣象樓臺；廣野氣成宮闕然。**雲氣各象其山川人民所聚積。」 〔甲级 · 维基文库原文核验〕

**注意一个字**：维基文库本作「海旁**蜄**氣象樓臺」——`蜄` 是 `蜃` 的异体字。后世通行引述多写作「蜃」。

解读：这是「气 → 楼台城郭」这条因果链第一次被写进正史。司马迁记的是**望气之术**：海边的蜃气呈现出楼台的形状，旷野的气呈现出宫阙的形状——**气各像其地的山川人民所聚积**。

**映射**：注意最后半句——「**雲氣各象其山川人民所聚積**」。幻象的内容取决于它所在的地方。这就是**幻境保真度的第一性要求**：幻境后端必须「像它所替代的那个真实业务」，而不是像任意一个蜜罐。

### 2.4 北宋的怀疑论：名字比解释活得更久

> **《夢溪筆談》卷二十一（異事）**：「登州海中，時有雲氣，如宮室、臺觀、城堞、人物、車馬、冠蓋，歷歷可見，謂之『海市』。或曰『蛟蜃之氣所為』，**疑不然也**。」 〔甲级 · 维基文库原文核验；「或曰」维基文库本作「或日」，系转录异文〕

解读：沈括（1080 年代）记录了登州海市——云气「如宫室、台观、城堞、人物、车马、冠盖，**历历可见**」——然后明确表态：有人说是蛟蜃吐气形成的，**我怀疑不是这么回事。**

**这是全篇最有价值的一句，因为它对攻防双方都成立**：

- 对**防御方**：沈括已经指出，「历历可见」才是海市的可信度来源——**保真度决定欺骗是否成立**。
- 对**攻击方**：十一世纪的人已经不信「蜃吐气」这套机制解释了，**但「海市」这个名字留下来了**。

> **机制被识破，不等于欺骗失效。** 一个 Agent 完全可以推理出「这个站点是精心构造的」，同时仍然按照站点的 API 文档去调用它——因为它判定的是「这样做对我的任务是否合理」，而不是「这个站点是否真实」。
> 这一条正对应 `docs/research/agentcapture-deception-report.md` §3.7 的实测结论：**功能性伪装的有效性不依赖隐藏机制，只依赖任务语义是否对齐。**

### 2.5 文学顶点：苏轼

> **蘇軾《登州海市》并序**（元丰八年，1085，知登州五日而召还）
> 序：「予聞登州海市舊矣，父老云：『嘗出於春夏，今歲晚不復見矣。』予到官五日而去，以不見為恨，禱於海神廣德王之廟，明日見焉，乃作此詩。」
> 詩：「東方雲海空復空，群仙出沒空明中；**蕩搖浮世生萬象**，豈有貝闕藏珠宮？**心知所見皆幻影**，敢以耳目煩神工。」 〔乙级 · 通行本，多源一致〕

两处可直接用作设计箴言：

| 诗句 | 对应设计 |
| --- | --- |
| **「蕩搖浮世生萬象」** | **多态与再生**：扰动之中生成万象。诱饵必须能随扰动重新生成（综述空白区 F） |
| **「心知所見皆幻影」** | **威胁模型的诚实表述**：对手明知是幻影也可能继续——这解释了为什么「识破」不是失败条件，**「识破延迟」才是我们的指标** |
| 「豈有貝闕藏珠宮」 | 贝阙珠宫 = 蜃的贝类本义（呼应 §2.1） |

### 2.6 两个关键的定性句：来自《聊斋志异·山市》

《山市》（卷一作《山市》，通行本卷六）记的是**陆上版**的蜃景——般（奂）山山市：

> 「奐山山市，邑八景之一也，數年恆不一見。孫公子禹年，與同人飲樓上，忽見山頭有孤塔聳起，高插青冥。相顧驚疑，念近中無此禪院。無何，見宮殿數十所，碧瓦飛甍，始悟為山市。未幾高垣睥睨，連亘六七里，居然城郭矣。中有樓若者、堂若者、坊若者，歷歷在目，以億萬計。忽大風起，塵氣莽莽然，城市依稀而已。既而風定天清，**一切烏有**，惟危樓一座，直接霄漢。」
> 尾句：「又聞有早行者，見山上人煙市肆，**與世無別**，故又名『**鬼市**』云。」 〔乙级 · 通行本，多源一致〕

| 原文 | 直接对应 |
| --- | --- |
| 「**與世無別**」 | **幻境的验收标准**：与实境不可区分。这就是综述空白区 B/E 里「同域名同 URL、TLS/时序一致」的古典表述——四个字说完 |
| 「一切烏有」 | **真实的成本**：幻境里没有真实资产，所以误导是可逆的、无损的 |
| 「**鬼市**」 | 高保真克隆站的现成名字（见 §3） |
| 「相顧驚疑，念近中無此禪院」 | **识破的触发点**：Agent 一旦发现「近中无此禅院」（本地不该有这个服务），就识破了。**保真度必须做到「近中有此禅院」** |
| 「數年恆不一見」 | **稀缺性提高可信度**：不是每次访问都给幻境，这本身就是可信度的一部分 |

### 3.2 一条命名纪律：只给「需要被记住的东西」起文学名

仔细看上面的表——**真实侧用的是技术标准词 `origin`，不是「实景」**。

因为文学名的价值在于**稀缺**。如果每个组件都有诗意名字，就变成了「用隐喻写代码」，日志没人看得懂、新人上手成本爆炸、搜索也搜不到。

**纪律**：

| 起文学名 | 不起文学名 |
| --- | --- |
| 项目名、核心组件（4–6 个，需要被口头传播、需要在架构图上被记住） | 数据结构、字段、决策值、指标名、配置键 |
| 例：`director` / `shenqi` / `haishi` | 例：`score` / `signals[]` / `route_mirage` / `p99_latency_ms` |

## 8. 命名禁忌与风险

### 8.1 不要用「罗刹海市」

刀郎 2023 年同名歌曲热度极高。《罗刹海市》（聊斋）的语义是「**美丑颠倒的幻国**」——是一个价值判断，不是技术含义。用它会造成：① 海量无关检索；② 语义误读；③ 时效性绑定（一首歌的热度会过去，名字留下）。

### 8.2 `海市` 与 `海事` 同音

`hǎishì` / `hǎishì`。口头沟通、语音搜索、电话会议里会产生歧义。这是排除 `haishi` 的第二条理由（第一条是 GitHub 被 `HaishinKit` 3,068★ 污染）。

### 8.3 `蜃景` 与 `神经` 近音

`shènjǐng` / `shénjīng`——声调不同，但快速念读极易混。**不要用 ASCII `shenjing`**。

### 8.4 「蜃」是次常用字

不少中文读者不确定读音（易误读为 chèn 等），部分输入法需要翻页。

**对策**：

1. 所有正式场合首次出现时标注拼音：**蜃（shèn）**；
2. 必须有 ASCII 名（`Shen`）用于仓库 / 二进制 / 主机名 —— **不能只有中文名**；
3. README 第一句就给出词源（§7.4），读者一旦知道「海市蜃楼」就不会再忘。

### 8.5 ⚠️ 最重要的一条：`蜃 / 海市 / 蜃气` 不得出现在任何对外可观测面

这是来自 `docs/research/agentcapture-deception-report.md` 的一条实测教训：**AgentCapture 用 `X-Agent-Capture-Decision` 响应头直接告诉攻击者「你被判定为 block，分数 95」**（发现 3、发现 11 相关）。对欺骗系统而言，这等于给对手一张答卷。

**你的引擎必须反向做。** 黑名单（禁止出现在攻击者可见处）：

| 位置 | 禁止 | 替代 |
| --- | --- | --- |
| HTTP 响应头 | `X-Shen-*`、`X-Mirage-*`（暗示有另一半） | 完全不加自定义头；或使用与真实业务一致的既有头 |
| `Server` 头 | `shen` | 与上游一致（或直接透传上游） |
| TLS 证书 CN/SAN | `*.shen.internal` 出现在面向攻击者的证书里 | 使用真实业务域名证书 |
| 错误页 / 500 栈 | `shen`、`蜃`、`haishi` | 通用错误页；栈只进服务端日志 |
| 容器名 / 主机名 / 内网 DNS | 可被指纹推断的一切 | 中性命名（`edge-01`、`pool-b-3`） |
| 幻境页面内容 | 「本页面为蜜罐」类字样 | 与真实业务一致的文案 |

**例外**：`deploy/nginx/` 等**纯服务端**配置可以自由使用主题名（攻击者看不到）。区分标准只有一条：**这个字符串会不会出现在攻击者的屏幕上？**

### 8.6 品牌风险：成语义偏负面

「海市蜃楼」的词典义是「**比喻虚幻不实的事物**」。用于产品名时，存在被读成「你们这东西是假的/不落地的」的风险。

**对策（也是选择单字「蜃」而非「海市蜃楼」的核心理由）**：始终强调**蜃是生成者，不是幻象**。

| ❌ 不要这样写 | ✅ 这样写 |
| --- | --- |
| 「蜃楼——我们的蜜罐平台」 | 「**蜃** —— 制造蜃景的那一个」 |
| 「海市蜃楼防御系统」 | 「不拦截，改道。」 |
