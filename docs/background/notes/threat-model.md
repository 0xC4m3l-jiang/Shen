## 1. 资产

不是"系统"，是具体的东西。按重要性排序：

| # | 资产 | 为什么是资产 | 谁来承担损失 |
| --- | --- | --- | --- |
| **A1** | **被接入业务的可用性与正确性** | `NI-1` 定为最高优先级，**优先于欺骗效果与情报采集** | 客户 → 我方（合同 / 信任） |
| **A2** | **对手无法察觉自己被骗**（不可区分性） | 这是本项目的**唯一命题** —— 一旦被识破，`引流决定` 等于把攻击者送进一个标着"蜜罐"的房间 | 项目本身（失去存在理由） |
| **A3** | **我方内部术语不泄漏** | 术语泄漏 = 直接暴露 A2；且暗示"存在另一半" | 项目本身（`OH-1`） |
| **A4** | **第三方不被牵连** | 伪造他人品牌 / 指向他人主机 / 向无关主机发载荷，会把客户和我方拖入法律与声誉风险 | 我方（`SB-3` / `SB-5`） |
| **A5** | **真实业务数据不外泄** | 蜜罐后端若误连真实数据源，我方就成了数据泄露的放大器 | 客户（最严重的一类事故） |
| **A6** | **我方日志与观测面本身** | 记录攻击者 IP / UA / 会话 / 凭证，是**新的攻击面与合规负担**（`G9` 未研究） | 我方（合规） |
| **A7** | **情报产出**（归因、画像、TTP） | 项目的收益面；但它**不能**与 A1/A2 冲突（`NI-1` 明文） | 我方 |

> ⚠️ **A2 与 A1 会冲突**：要"骗得像"就得消耗资源、承担延迟（威胁 T6）。`NI-1` 已经预先裁定 —— **业务优先**。

## 2. 对手（分档）

对手是「会推理、会记忆、会跨会话复用结论」的 Agent —— 这条**显式写成能力**，而不是默认没有。

| 档位 | 能力 | 资源 | 动机 | 已知技术 | 劝退因素 |
| --- | --- | --- | --- | --- | --- |
| **O1 传统扫描器** | 固定 payload、无状态、不看响应语义 | 单机 / 云函数 | 撒网找 CVE | `nuclei` / `sqlmap` / 目录爆破 | 任何非 200 响应、限速、WAF 拦截 |
| **O2 智能爬虫 / 数据采集方** | 会解析 JS、会跟随登录流、有会话 | 代理池、分布式 | 抓数据 / 比价 | Playwright 系、指纹伪装 | 账号封禁、验证码、数据无价值 |
| **O3 自主渗透 Agent** ⭐ **主对手** | **推理**（读页面理解语义）、**记忆**（跨跳复用结论）、**工具集**（浏览器 / curl / 代码执行）、会读源码注释与 API 文档 | 商用 LLM API + 少量出口 IP | 完成任务（拿 flag / 拿数据 / 拿 shell） | AgentCapture 的 C 级实测显示：五款主流 Agent CLI 均能完成站点巡检与诱饵 API 接入 | **任务无进展**（时间预算耗尽）；**目标看起来不值得**；**每一步都成功但总拿不到东西** |
| **O4 有备而来的人类红队** | 上述全部 + 人工判断 + 会读本项目的公开材料 | 充足时间与预算 | 定向评估 / 竞争情报 | 手工比对响应差异、抓包分析 TLS 指纹、跨会话比对 | 时间成本；**若我方公开材料泄漏了机制，则无法劝退** |
| **O5（特殊）众包识破网络** | 多个 O3 实例**共享记忆 / 交换结论** | 共享的蜜标黑名单 | 集体规避 | 「多 Agent 共享记忆会众包识破蜜罐令牌」（综述 `2608.11436`） | 我方诱饵多态化（`G12`，未研究） |

> **O3 是设计的主对手**：本项目存在的理由就是它。O1/O2 用传统 WAF 就能处理。
> **O4 是最危险的**：它不受时间预算约束，且会主动去找"这个防御系统是怎么工作的"。
> **O5 决定了我方诱饵不能是静态的** —— 一个被识破的诱饵会通过共享记忆污染所有实例。

## 3. 信任边界

```text
对手(O1–O5) ──┐
              │  ① 不可信：全部请求内容（含 TLS 指纹、UA、路径、body）
              ▼
      ┌───────────────────────────┐
      │  接入层（Envoy / Nginx / 代理）│  ← ③ 在此校验：TLS 终止、SNI、会话身份提取
      └───────────┬───────────────┘
                  │  ② 不可信：核心判定接口的调用（需防 malformed protobuf / 超时）
                  ▼
      ┌───────────────────────────┐
      │   核心（core，Go）         │  ← 本项目的信任边界在此
      │   适配器（L1，Lua/Wasm）   │
      └───┬───────────────────┬───┘
          │                   │  ④ 半可信：离线模型产物（带版本号，但需校验）
          ▼                   ▼
   ┌────────────┐      ┌──────────────────┐
   │ 蜜罐后端池 │      │ L4 分析（Python） │
   └────────────┘      └──────────────────┘
   └─────┬──────┘
         │  ⑤ 必须单向、只读、无出网（SB-5 / SB-6）
         ▼
   ┌──────────────────────┐
   │ 取证 / 遥测存储       │  ← ⑥ 这是新的资产与攻击面（A6）
   └──────────────────────┘
```

**关键判定**：

| # | 边界 | 谁执行转换 | 现状 |
| --- | --- | --- | --- |
| ① | 对手 → 接入层 | **永不转换** —— 对手输入始终不可信 | ✅ 已确认（`NI-8`：禁止写业务存储） |
| ② | 接入层 → 引擎 | Envoy 的 `failure_mode_allow` + 我方硬超时 | ✅ 已确认（`NI-3` / `NI-4`） |
| ③ | 会话身份提取 | 按 `INT-19` 优先级；**禁止**在客户端留痕、**禁止**上行或回传（`INT-20`） | ✅ 已确认 |
| ④ | 离线模型 → 热路径 | 只传**查表数据**，不传可执行逻辑；带版本号 | 🔵 提案（`notes` §3.4） |
| ⑤ | 引擎 → 蜜罐 / 外部 | **出网默认拒绝**；`SB-5` 禁止向业务外主机投递 | ✅ `SB-5` / `SB-6`；白名单机制**未实现** |
| ⑥ | 引擎 → 遥测 | 日志是**新的资产**，需要自己的访问控制与保留策略 | ❌ **未研究**（`G9`） |

## 4. 威胁表

> 每条威胁指向具体档位；没有对手能实施的威胁不列。

| # | 威胁 | 前提 | 影响 | 现有缓解 | 残余风险 | 检测方式 |
| --- | --- | --- | --- | --- | --- | --- |
| **T1** | **引擎故障拖垮业务** | 引擎进程崩溃 / 卡住 / 返回非法值 | **A1 直接损失** —— 这是唯一能一次毁掉项目的威胁 | `NI-3`（fail-open）/ `NI-4`（硬超时）/ `NI-5`（默认回落）/ `NI-10`（熔断）/ `NI-7`（资源围栏） | 🟢 低 —— 由架构机制提供，**多个机制互为兜底** | `V-1…V-5`（`NI-12` 强制入 CI）+ 建议的 `availability sentinel` |
| **T2** | **引擎抢占业务资源** | 引擎 CPU / 内存 / 连接数失控 | A1 降级（P99 劣化） | `NI-7`（独立进程 + cgroup 上限） | 🟡 中 —— cgroup 上限的**具体数值未定**（`G6` 时延与容量预算） | `V-5`（CPU 饱和打压）+ 资源监控 |
| **T3** | **会话被改道后自相矛盾** | 同会话内先给真实数据、后给蜜罐数据（或反之） | **A2 直接损失** —— 对手一次比对即识破 | `INT-21`（同会话幂等于同后端）；D0 推论 1（误导只能落在首跳） | 🔴 **高** —— `D0` **未拍板**，`INT-21` 的语义仍待 D0 定案后细化；且 AI 生成内容是**最容易破坏它**的组件（`notes` §5.4） | 差异哨兵 检查项 7（同资源第 2、3 次是否同答案） |
| **T4** | **元数据泄漏内部术语 / 机制** | `Server` 头 / 自定义头 / TLS 证书 CN / 错误页 / 容器名出现内部词 | A3 → 直接暴露 A2 | `OH-1`（禁用清单）/ `OH-3`（CI 自动检查）/ `OH-5`（禁止回显决策） | 🟡 中 —— 检查是**字符串扫描**，无法覆盖"两个中性头同时出现的组合特征" | `shen check-leak`（CI）+ 人工核对每个新增字符串（`OH-2`） |
| **T5** | **TLS 指纹与真实站不一致** | 我方栈（默认 rustls）与真实站（常见 nginx+OpenSSL）的 JA3/JA4 不同 | **A2 直接损失** —— O3/O4 抓一次握手即知"这不是同一个服务" | ❌ **无**（仅登记为待验证假设） | 🔴 **高** —— 若成立，是**架构级缺陷**，所有内容层伪装都白做 | 差异哨兵 检查项 9（JA3/JA4）；**前置实验未做**（`notes` §2.3） |
| **T6** | **时序分布可区分** | 蜜罐响应比真实业务慢（或快），或调度本身增加固定延迟 | A2 损失（O3 可测量） | 🔵 仅有"流量整形"作为候选手段，**未采纳** | 🟡 中 —— `p99_latency_overhead_ms` 的可接受值**未定**（`G6`） | sentinel 检查项 6（P50/P99 是否落在对方分布内） |
| **T7** | **主动探测 / 标记注入** | 对手故意写入一个标记，看它是否在别处回显；或发一个不该存在的路径看错误页形状 | A2 损失 | ❌ **无专门缓解** | 🔴 高 —— 这是**最有杀伤力的识破路径**（见 §5），且**我方无法检测对手已识破** | ❌ **无检测手段** —— 需新建 |
| **T8** | **跨会话记忆复用** | O3 把上一次会话观察到的特征（cookie 名、响应头顺序、错误文案）带到下一次 | A2 损失（渐进识破） | ❌ 无 | 🟡 中 —— 与 T4/T6 叠加时更严重 | ❌ 无（需要跨会话一致性监控） |
| **T9** | **众包识破（O5）** | 多个 Agent 实例共享"这是蜜罐"的结论 | A2 损失，**且是全局性的**（一个实例的识破污染所有） | ❌ 无 | 🔴 高 —— `G12`（诱饵多态与再生机制）**完全未研究** | ❌ 无 |
| **T10** | **蜜罐后端误连真实数据源** | 蜜罐实例配置错误 / 克隆时抓到了真实数据 | **A5** —— 我方成为数据泄露放大器 | `SB-5`（禁止向业务外主机连接）/ `SB-6`（禁止主动连接） | 🟡 中 —— 依赖**配置正确性**，无运行时校验 | 🔵 建议：蜜罐后端启动期断言"数据源在白名单内" |
| **T11** | **clone/回连能力被滥用为 SSRF** | 若蜜罐内容生成走"抓取目标站"路径，则可被诱导访问内网 / 云元数据 | 我方成为跳板；A4 牵连 | ❌ 未确认本项目是否需要外呼能力（`D7` 未定） | 🟡 中 —— 若 `D7` 选"克隆"路线则**必须**做出网白名单 | 🔵 建议：出网默认拒绝 + 私网段与元数据地址阻断（外部设计稿 §10.1.4 的同名约束可参考） |
| **T12** | **日志成为合规与泄露负担** | A6 —— 我方留存攻击者 IP / 凭证 / 上传的恶意文件 | 法律责任；且若日志被拖库，等于替攻击者做了归档 | ❌ **未研究**（`G9`） | 🔴 高 —— **在部署取证型组件前必须先解决** | ❌ 无 |
| **T13** | **决策路径缺陷（判错方向）** | 判别器把正常用户判成 Agent | **误调度** —— 正常用户看到假数据，是不可逆的信任损失 | 影子模式首发（`INT-11`）+ 渐进阶梯（`INT-12`）+ `false_route_budget`（**口径未定**，`D12`） | 🟡 中 —— 后果严重但概率可控；**前提是 `D12` 先定** | `false_route_rate` 指标（**被决策档位阻塞**（[ADR-0002](../decisions/0002-decision-model.md)，暂缓），分母定义依赖它） |
| **T14** | **对手已知我方存在并知道机制** | O4 读了本项目的公开材料 | 安全性**不能依赖隐蔽** | ❌ 无 | 🟡 中 —— 必须设计成**即使机制公开也仍然有效**（见 §7 必答问题 1） | N/A |

## 5. 识破路径（欺骗类专用）

> 逐条给出**可观测的识破信号**与**我们能否检测到对手已识破**。

| 识破路径 | 对手需要的观察 | 我们是否可检测 | 缓解 | 缓解的代价 |
| --- | --- | --- | --- | --- |
| **① 内容不一致（两次访问不同）** | 对同一 URL 请求 2–3 次，比对 JSON 值 | ✅ **可检测**（sentinel 检查项 7） | D0 首跳定终局 + AI 产物按 (会话,资源) 落库缓存 | 缓存必须持久且与会话绑定；限制 AI 的"每次生成新内容"能力 |
| **② 时序异常** | 测量 P50/P99，与"真实站基准"对比 | ✅ 可检测（检查项 6） | 流量整形 / 蜜罐侧注入延迟 | 整形增加资源消耗；过度整形本身成为特征（T6 的两难） |
| **③ 元数据泄漏** | 读响应头 / `Server` / 错误页 / 证书 | ✅ 可检测（`OH-3` 字符串扫描） | `OH-1` 禁用清单 + 与上游一致的头 | 只能覆盖字符串；**头序、头集合、TLS 扩展序**等结构性特征不在此列 |
| **④ 环境矛盾** | 发现不该存在的服务（蜜罐里出现真实内网 IP、真实主机名、真实版本号） | 🟡 部分可检测（黑名单式校验） | 生成内容黑名单（泄露类） | 黑名单不可能完备（外部设计稿 §9.1.18 已承认） |
| **⑤ 行为反馈（写入不生效）** | 在蜜罐里创建一条记录，再读回来 —— 若读写都"成功"但重启后消失，即识破 | 🟡 难检测 | 蜜罐需有**自洽的持久化语义**（至少会话内一致） | 需要真的存储，成本与复杂度上升；**当前无设计** |
| **⑥ 跨会话记忆** | 把上次会话的特征带到下次并比对 | ❌ **不可检测** | 对外可观测面必须**长期稳定**（不能今天 `edge-01` 明天 `edge-02`；不能今天错误页是 A 版明天是 B 版） | 与"诱饵多态"（G12）**直接冲突**：多态要求变化，一致性要求不变。**这条冲突尚无解** |
| **⑦ 主动探测（注入标记看回显）** | 写入一个唯一标记，在别处搜索它是否出现 | ❌ **不可检测** | 无 | — |
| **⑧ 指纹级握手比对**（本项目特有） | 抓 TLS 握手，比对 JA3/JA4 与真实站 | ✅ 可检测（检查项 9） | 使用与真实站一致的 TLS 栈（可能需要 `boring` 而非默认 `rustls`） | 引入 `boring` = 引入 BoringSSL；**前提是前置实验证明这是真需求**（`notes` §2.3） |
| **⑨ 内容体量与结构比对**（本项目特有） | 对比真实业务与蜜罐的 body 长度分布 / JSON 键集合 / 分页行为 | ✅ 可检测（检查项 1–5） | sentinel 全部 12 项检查 | sentinel 本身成本；且它只覆盖**已列入清单**的维度 |
| **⑩ 会话身份推断**（本项目特有） | 观察"新出现的 cookie / 新出现的响应头" | ✅ 可检测（检查项 11，`NI-9`） | 只用业务自身的 session cookie；**禁止**新增任何客户端可见标识（`INT-20`） | 若业务本身无 session cookie，只能退到"IP+UA 指纹"，**跨出口 IP 的 Agent 会掉出粘性** → 一致性被破坏 |

### 关于 ⑥ 的冲突（必须记录）

> **诱饵多态（对抗 O5 众包识破）要求蜜罐内容随时间变化；跨会话一致性（对抗 ⑥）要求它不变。**
>
> - 只做多态 → 对手第 2 次访问就发现不同 → ① 类识破。
> - 只做一致 → O5 一旦识破一个实例，全局失效。
>
> **可能的出路**：多态发生在**会话边界**（不同会话看到不同但各自自洽的蜜罐），而不是**会话内部**。
> 这与 D0「会话出生即终局」同构 —— 若 `D0` 采纳模式 A，这条出路是现成的；若采纳模式 C，需要重新推导。
> ⚠️ **本冲突在 D0 定案前无法解决，登记于此。**

## 6. 明确接受的残余风险

> 写「已缓解」但实际上只降低概率的，要写明降低后的量级。无实验支撑的标注为「设计意图，未验证」。

| # | 残余风险 | 为什么接受 | 量级 / 依据 | 复查条件 |
| --- | --- | --- | --- | --- |
| **R-1** | T5（TLS 指纹可区分）**可能无法解决** | 若真实站用 nginx+OpenSSL，完全一致需要引入 BoringSSL 级控制，成本高 | 🔴 **未知** —— 前置实验未做。若实验证明可区分，**必须**重新评估整个欺骗命题的成立性 | 前置实验完成后**立即**复查 |
| **R-2** | T7（主动探测与标记注入）**无法检测** | 欺骗的本质是对手可以设计任意实验；没有通用的"识破探测器" | 🟡 只能降低**成功概率**（让回显路径不存在），不能阻止对手**尝试** | 出现真实被识破案例时 |
| **R-3** | T8/T9（跨会话记忆与众包识破）**当前无缓解** | 需要统一的"跨会话/跨实例一致性 + 会话边界多态"机制，属 `G12` 未研究 | 🔴 高 | 蜜罐后端构造方案（`D7`）定案时 |
| **R-4** | T12（日志合规）**未研究** | 需要法律意见，非技术问题（`G9`） | 🔴 高 —— **但取证型组件在解决前不得进入生产** | `G9` 完成时 |
| **R-5** | 本威胁模型**未覆盖 O0 档位（内部误操作）** | 内部权限模型不在本项目范围（本引擎无控制面，`SB-1`） | 🟢 低 | 若将来引入控制面（需新 ADR，`INT-10` 现禁止 SDK / 内嵌形态） |
| **R-6** | 对手**完全知道**我方机制（T14） | 依赖隐蔽的安全性是不可接受的（本文件 §7 问题 1）；只能设计成"机制公开仍然有效" | 🟡 中 —— 待验证：机制公开后，差异哨兵 的 12 项检查是否仍全部通过？ | `D0` 定案后 |

## 7. 必答问题清单

| 问题 | 当前答案 | 状态 |
| --- | --- | --- |
| 对手**已经知道**我们存在、并知道我们在欺骗，会怎样？ | 按 `T14` 处理：安全性**不得**依赖隐蔽。**但"机制公开仍有效"这一点从未论证过** —— 是 R-6 | 🔴 **未答** |
| 对手换一个身份标识（UA / 会话 / 出口 IP）要花多少成本？ | O3 换 UA 零成本、换出口 IP 极低（代理池）、**换会话则丢失全部历史**（这对我方有利）。`INT-19` 的优先级 ③（IP+UA）在换 IP 时失效 | 🟡 部分 |
| 误处置一个正常用户的后果是什么？谁承担？ | 正常用户看到假数据 → 不可逆的信任损失。按 `NI-1`，**业务可用性优先于欺骗效果**，所以阈值必须偏保守。承担方：客户 | 🟡 部分（`D12` 口径未定） |
| 我们的日志本身是不是新的攻击面？ | **是**（A6 / T12）。记录了什么、谁能看、留多久 —— **全部未定义** | 🔴 **未答** |
| 会不会牵连第三方？ | `SB-3`（禁止伪造第三方品牌）、`SB-5`（禁止向业务外主机投递）、`SB-6`（禁止主动连接）已确认。但**蜜罐内容的素材来源台账尚未建立** | 🟡 规则已定，落地未做 |
| 失败模式是「失效开放」还是「失效关闭」？ | **失效开放**（fail-open），与业务期望一致（`NI-3` / `NI-4` / `NI-5`） | ✅ **已答** |
| 我们如何知道防御**正在起作用**？ | 差异哨兵（12 项不变量）+ `false_route_rate` + `time_to_recognition`。但**指标口径未定**（`D12`） | 🟡 装置已提名，口径未定 |
