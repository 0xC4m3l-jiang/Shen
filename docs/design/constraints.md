## 一、非侵入性（NI）—— 不影响原始业务

| ID | 规则 | 验证方式 |
| --- | --- | --- |
| **NI-1**（总则，最高优先级） | 本引擎**必须**保证：在其完全故障、超时、返回非法值或资源被压满时，被接入业务的可用性与正确性**不受影响**。本规则优先于本项目其他一切目标（含欺骗效果与情报采集）。 | 强制测试 **V-1…V-5** 全部通过 |
| **NI-2** | 上述保证**必须**由架构机制提供；**禁止**以「所用语言更安全」作为满足 NI-1 的依据。 | 设计评审；检查 NI-3…NI-12 是否逐条落地 |
| **NI-3** | 在请求路径上的接入形态（DNS 引流 / 反向代理 / Sidecar）**必须**在接入层配置失败放行（如 Envoy 的 `failure_mode_allow: true`）。旁路镜像形态不适用（见 [`integration.md`](integration.md) 的 INT-6）。 | 配置评审 + 故障注入测试 |
| **NI-4** | 决策**必须**有硬超时；超时**必须**返回「无意见」并放行到真实业务。 | 单元测试 + 注入延迟测试 |
| **NI-5** | 任何未识别、未匹配、解析失败或不确定的状态，**必须**回落**放行到真实业务**（即 `route_origin`，见 [`terminology.md`](terminology.md) §4.1）。 | 单元测试（默认决策用例） |
| **NI-6** | 首次上线**必须**运行在影子模式：只观测、不处置、不回写。 | 上线检查单 |
| **NI-7** | 引擎**必须**以独立进程运行，并**必须**施加 cgroup CPU / 内存上限。 | 部署清单评审 + 资源限制生效验证 |
| **NI-8** | 引擎**禁止**写入被接入业务的任何数据存储。 | 代码评审 + 凭据与依赖检查 |
| **NI-9** | 引擎**禁止**新增任何客户端可见的 Cookie 或响应头。 | 差异哨兵 + 自动检查 |
| **NI-10** | 引擎**必须**实现熔断：决策错误率或超时率超过阈值时，**必须**自动切换为纯放行。 | 故障注入 + 指标断言 |
| **NI-11** | 解除接入**必须**能通过移除一段配置完成，且**禁止**要求重启被接入业务。 | 回滚演练 |
| **NI-12** | 测试 **V-1…V-5** **必须**纳入 CI，且在**每次改动决策路径**后**必须**重新执行。 | CI 配置评审 + 流水线记录 |

### NI-1 的强制验证

| # | 测试 | 必须断言 | 适用形态 |
| --- | --- | --- | --- |
| V-1 | 杀死引擎进程 | 业务请求 100% 正常 | 在路径的形态（②③④） |
| V-2 | 向决策注入 > 超时预算的延迟 | 业务请求 100% 正常 | 同上 |
| V-3 | 返回 malformed protobuf | 业务请求 100% 正常 | 同上 |
| V-4 | 返回非法决策值 | 回落**放行到真实业务** | 同上 |
| V-5 | CPU 饱和打压引擎 | 业务 P99 不劣化（相对基线差值在预算内） | 全部形态 |

> 旁路镜像形态（①）下引擎不在请求路径上，V-1…V-4 无对象 —— 该形态只需满足 V-5 与出站审计。

## 二、可观测面卫生（OH）—— 不向对手暴露自身

| ID | 规则 | 验证方式 |
| --- | --- | --- |
| **OH-1** | 下列字符串**禁止**出现在任何攻击者可见的位置。英文侧：`honeypot`、`honey_pot`、`decoy`、`canary`、`canarytoken`、`mirage`、`deception`、`deceive`、`tarpit`、`trapserver`、`x-deception`、`x-honeypot`，以及本项目的仓库名 / 二进制名 / 服务名。中文侧：`蜜罐`、`蜜饵`、`蜜标`、`投毒`、`引流`、`欺骗`、`诱捕`、`仿真蜜罐`、`会话水印`。 | CI 中的 leak 检查 |
| **OH-2** | 判断某字符串是否受 OH-1 约束的唯一标准是：**这个字符串会不会出现在攻击者的屏幕上？** 会 → 禁止；不会 → 允许。 | 人工核对（对每个新增字符串） |
| **OH-3** | 工程**必须**提供自动检查，对响应面模块的字符串字面量扫描 OH-1 清单。 | CI 中的 leak 检查 |
| **OH-4** | 自动检查的例外**必须**逐条显式声明并附理由；**禁止**整目录豁免。 | 检查配置评审 |
| **OH-5** | 决策结果与风险分数**禁止**通过任何响应头回传给客户端（对照：参考实现用 `X-Agent-Capture-Decision` 直接告知对手「你被判定为 block，分数 95」—— 对欺骗系统而言等于递交答卷）。 | 自动检查 + 集成测试 |

> **OH-1 与 `terminology.md` 不矛盾**：`TM` 管**内部命名**，OH 管**外部可见性**。
> `honeypot` / `decoy` 这类行业词**允许**出现在源码、配置与内部文档，但**禁止**出现在响应面。
> 判据始终是 OH-2。
>
> ⚠️ 采用行业术语后，泄漏风险的性质变了：行业词**不构成可被指纹推断的内部信息**，
> 但**依然自曝「你在被骗」** —— 而后者才是 OH 要防的。

### OH-2 适用位置判定表

| 位置 | 状态 |
| --- | --- |
| HTTP 响应头（含自定义头） | **禁止** |
| `Server` 头 | **禁止**（**必须**与上游一致或直接透传） |
| TLS 证书 CN / SAN | **禁止**（**必须**使用业务域名证书） |
| 错误页与错误响应体 | **禁止** |
| 蜜罐页面内容 | **禁止** |
| Cookie 名 | **禁止**（**必须**中性，如 `sid`） |
| 容器名 / 主机名 / 内网 DNS | **禁止**含可被指纹推断的内部术语 |
| 服务端配置与内部日志（攻击者不可见） | 允许 |

## 三、范围边界（SB）

| ID | 规则 | 验证方式 |
| --- | --- | --- |
| **SB-1** | 本项目**禁止**实现控制面能力，包括但不限于：C2 服务端、任务下发与回收、Beacon / 植入体生成、载荷投递、木马捆绑、漏洞利用框架对接、**向任何第三方 Agent 或系统下发指令并回收其执行结果**。 | 代码评审 + 对外接口清单核对 |
| **SB-2** | 收编类行为**仅限**用于检测与归因（记名册、算成功率、做画像）；**禁止**具备下发指令与接收执行结果的能力。 | 接口清单核对 |
| **SB-3** | **禁止**伪造第三方品牌或站点。蜜罐内容**必须**基于自有素材或已获书面授权的站点。 | 内容来源台账 |
| **SB-4** | 克隆类能力**必须**在文档与界面中显式标注「仅限自有或书面授权站点」。 | 文档与界面评审 |
| **SB-5** | **禁止**向被接入业务之外的任何主机投递载荷或发起连接。 | 网络策略评审 + 出站连接审计 |
| **SB-6** | 引擎**禁止**主动连接任何目标；它**必须**是被动组件。 | 出站连接审计 |
| **SB-7** | 部署文档**必须**声明：仅限拥有或获得书面授权的环境使用。 | 文档评审 |
| **SB-8** | 抓取、克隆、回调类能力**必须**配置目标白名单；私网地址段与云元数据地址**必须**默认阻断。 | 单元测试 + 出站审计 |

## 四、取证与日志（新的资产与攻击面）

| ID | 规则 | 验证方式 |
| --- | --- | --- |
| **NI-13** | 取证数据**必须**按类别（事件 / 会话转录 / 凭证 / 登录日志）**分别**配置保留天数，并**必须**有启动期与周期性清理。 | 配置评审 + 清理任务测试 |
| **NI-14** | 日志**必须**按状态变化输出（稳定轮询与正常心跳降噪，状态跃迁 / 决策变更 / 失败 / 超时按事件输出）。 | 日志量断言 |
| **BA-1** | 在法务结论（合规缺口 `G9`）完成前，**禁止**把取证型组件投入生产。 | 上线检查单 |

> `BA`（boundary & audit）为新增前缀，用于承接原属 `设计.md` §10 且与本项目边界相关的规则。
