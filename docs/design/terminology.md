## 1. 架构与分层术语

| 概念 | 唯一写法 | 说明 | 禁止写法 |
| --- | --- | --- | --- |
| 流量入口层 | `L0` / **接入层** | TLS 卸载、路由；**不自研** | 边缘入口、gateway layer |
| 边缘处置层 | `L1` / **边缘欺骗层** | 投毒、假路径、引流**执行**；**不含判定** | edge injector |
| 高交互层 | `L2` / **高交互欺骗层** | 协议仿真蜜罐 + LLM 多轮会话 | 交互蜜罐层 |
| 网络欺骗层 | `L3` / **网络欺骗层** | 蜜网编排、微隔离、假拓扑 | 蜜网层 |
| 分析决策层 | `L4` / **分析决策层** | 意图识别、攻击链还原、策略生成 | 大数据层 |
| 判定与响应生成的唯一实现 | **核心**（`core`） | 无状态多副本，经 gRPC 对外 | 引擎主体、decision service |
| 接入形态的薄封装 | **适配器**（`adapter`） | 只做拦截、查缓存、处置、上报 | 插件、连接器、connector |
| 实际产生欺骗效果的组件集合 | **欺骗执行面** | L1 处置 + L2 蜜罐 + L3 网络策略 | deception plane |
| 策略编排与人工干预 | **控制面**（control plane） | **不参与请求级判定** | 管理面、后台 |
| 核心依赖的存储集合 | **数据面**（data plane） | Redis / ClickHouse / PostgreSQL | 存储层 |

## 2. 欺骗概念术语

| 概念 | 唯一写法 | 说明 | 禁止写法 |
| --- | --- | --- | --- |
| 单次请求的风险判定 | **判定**（`Judge`） | 给出风险分值、信号列表与处置动作 | 检测、识别、打分 |
| 诱骗资产 | **蜜饵** | 假 API 路由 / 假文件 / 假凭证 | 诱饵、decoy（作名词时） |
| 可回显追踪的令牌 | **蜜标**（Canary Token） | 被回显即判定自动化客户端 | 蜜罐令牌 |
| 仿真服务实例 | **蜜罐** | 协议仿真与高交互会话承接方 | 幻境节点 |
| 嵌入蜜罐会话的标识 | **会话水印** | 凭证被复用时回溯到具体会话 | 指纹、标记 |
| 返回伪造或误导性内容 | **投毒**（`POISON`） | 直接改写响应体 | 污染、篡改 |
| 把可疑流量转发至蜜罐 | **引流**（`REDIRECT`） | 转发目标改写 | 改道、重定向（作动作名时） |
| 对来源在 TTL 内短路判定 | **隔离**（`isolate`） | 不再调用核心 | 封禁、拉黑 |

## 3. 工程术语

| 概念 | 唯一写法 | 说明 |
| --- | --- | --- |
| 重试与重放去重的键 | **幂等键** | `decision_id` / `event_id` / `(policy_id, version)` |
| 触发 L4 重算的门槛 | **态势去重** | 仅当新增证据达阈值或攻击阶段跃迁时才触发 |
| 判定不可用时默认放行 | `fail-open` | 业务可用性优先 |
| LLM 输出的结构与内容约束 | **契约**（Contract） | 由独立代码层校验，与提示词分离 |
| 需唯一写入方的数据 | **核心状态** | 隔离名单、策略版本、会话归属 |
| 逐请求数据与配置的确定性接口 | **契约**（`api/`） | 见 [`structure.md`](structure.md) |

## 4. 决策取值与加重强度

> 候选对比、负面后果与**失效条件**见 [ADR-0002](../background/decisions/0002-decision-model.md)。

### 4.1 决策取值（三值，闭集）

| 取值 | 语义 | 对客户端 |
| --- | --- | --- |
| `route_origin` | 放行到真实业务 | **不可见** |
| `route_mirage` | 悄悄改道到蜜罐后端（同域名 / 同 TLS / 同 URL / 同会话语义） | **不可见** |
| `block` | 拦截 | 可见 |

**禁止**新增第四个取值。**禁止**把「可见处置」（挑战页 / 质询页 / 验证码 / 维护页）并入本枚举。

### 4.2 加重强度（`severity`，旁路字段）

`severity` 与决策取值**并列输出**，表达「加重」—— 在不改道的前提下施加压力。

| 取值 | 语义 | 备注 |
| --- | --- | --- |
| `none` | 不加权 | **当前唯一合法取值** |

> ⚠️ **限速 / 加噪声的具体档位尚未定义。** 「多狠算不明显」是**实测问题**。
> 在实测确定并登记到本表之前，实现**必须**只支持 `none`；**禁止**自行发明档位。

| ID | 规则 | 验证方式 |
| --- | --- | --- |
| **TM-12** | `severity` **必须**是独立于决策取值的**旁路字段**；**禁止**并入决策枚举，**禁止**用它表达任何可见处置。 | 类型定义评审 |
| **TM-13** | `severity` 的取值**必须**只使用 §4.2 登记的值；新增档位**必须先**实测并登记到本表。 | CI 术语检查 + 配置校验 |

## 7. 与可观测面卫生的关系（重要，勿混淆）

| ID | 规则 | 验证方式 |
| --- | --- | --- |
| **TM-6** | 本文件的术语**只能**用在**内部**：源码标识符、配置、内部文档、日志、提交信息。 | 人工核对 |
| **TM-7** | 这些术语**禁止**出现在攻击者可见表面 —— 清单与判据见 [`constraints.md`](constraints.md) 的 OH-1 与 OH-2。 | CI 中的 leak 检查 |

> **两套规则不矛盾**：`TM` 管**内部命名**，`OH` 管**外部可见性**。
> 对外使用中性名（如 `edge-01`），源码与配置里用本文件的术语。
>
> ⚠️ 采用行业术语后，**泄漏风险的性质变了**：`honeypot` / `decoy` / `canary` 本就是安全行业通用词，
> 它们出现在响应头或错误页上**依然是自曝**（对手立刻知道自己在被骗），
> 但出现在源码里**不构成可被指纹推断的信息**。判据始终是 **OH-2：这个字符串会不会出现在攻击者的屏幕上？**
