# 看告警 · 看流量 · 看流动

## 数据从哪来

```text
客户端 → L0（客户 LB/nginx，终结 TLS）→ 适配器（白名单 → 判定缓存 → gRPC 判定）
        → 核心（judge 打分 → director 三值）→ 按决策执行（放行 / 改道+注入 / 拦截）
        → 异步遥测（事件写回核心）→ 观测控制台读出来
```

- **判定记录**（含分值 / 命中信号 / 去向）由核心在**服务面**记一笔（`core/internal/control` 的观测面记录器）；
- **适配器侧的行为**（是否影子、是否引流回落）由适配器异步上报成遥测事件；
- 控制台**只读**，不写策略、不干预请求（`AR-10`：控制面禁止参与请求级判定）。

## 控制台

```sh
make console            # 只起控制台（核心需已在跑；核心地址取 SHEN_CORE_ADDR）
scripts/demo/run.sh     # 或连核心一起起
```

页面四块（自上而下）：

| 区块 | 回答什么 |
| --- | --- |
| **概览** | 事件总数 · 按决策分布（放行/改道/拦截）· 告警条数 · 时间范围 |
| **告警** | 决策为 `block` 或 `severity` 非 `none` 的记录（**影子模式下通常为空 —— 这是对的**） |
| **流量访问与流动** | 最近判定：时间 · 决策 · 来源 IP · 方法 · 路径 · UA · **分值** · **命中信号** · 后端名；可按决策筛选 |
| **最近事件（原始）** | 未加工的遥测事件流（排障时看原始形状） |

JSON 接口（页面的数据源，也方便脚本化）：

| 接口 | 用途 |
| --- | --- |
| `GET /api/summary` | 概览 |
| `GET /api/flow?limit=300` | 判定流动（含分值 / 信号 / 后端） |
| `GET /api/events?limit=100&type=decision` | 原始事件（`type` 可空） |
| `GET /healthz` | 控制台进程存活（**不**代表核心可达 —— `ST-17` 的探针语义区分） |

## 三条判读要点

1. **分数与信号只在这里可见**：判定响应**禁止**回显它们（`ST-7`），所以「为什么判成这样」只能看控制台或 `make replay`。
2. **影子模式下没有 `block`**：看到「告警 0 条」不代表没抓到东西，去看**分值**与**命中信号**。
3. **时间**：页面按浏览器本地时区显示；JSON 里 `created_at` 是 UTC、`At` 带本地偏移 —— 同一时刻，别被两个时区吓到。
