# `fingerprint` —— TLS 指纹采集与对比（实验 `E2`）

| 项 | 值 |
| --- | --- |
| 依据 | 威胁模型 `A2`（对手无法察觉自己被骗 —— **本项目的唯一命题**）· 实验 [`E2`](../../docs/background/notes/pending-experiments.md) |
| 依赖 | 只用 Go 标准库（`crypto/tls` + 自写的握手解析）—— 不引入任何指纹库，避免「用别人的口径解释自己的结论」 |
| 状态 | ✅ 已实现（含 10 例单测） |

## 为什么它最重要

攻击者**最先**看到的不是我们的页面，而是 **TLS 握手**。若握手形状与真实站一眼可辨，
后面的页面伪装都不必谈。`E2` 的判定标准里写明：**可区分且无法对齐 ⇒ 威胁模型 `R-1` 必须重估整个欺骗命题**。

## 用法

```sh
# ① 采真实站（A 组）
make fp-capture ADDR=shop.example.com:443 OUT=/tmp/real.json

# ② 采我方栈（B 组）—— 起一个带 TLS 的 adapter-proxy，或直接指向 L0
make fp-capture ADDR=127.0.0.1:8443 SNI=shop.example.com OUT=/tmp/ours.json

# ③ 对比 → 出结论
make fp-diff A=/tmp/real.json B=/tmp/ours.json
```

退出码：`0` = 可继续（不可区分 / 可调齐）；`2` = **不可对齐**（脚本可据此拦住后续动作）。

## 采什么

| 类别 | 字段 | 为什么要 |
| --- | --- | --- |
| 协商结果 | TLS 版本 · 选用密码套件 · ALPN | 攻击者一条 `openssl s_client` 就能看到 |
| 服务端握手形状 | **ServerHello 的扩展类型与顺序**（`server_extensions`） | 这是 JA3S 的核心，也是最能一眼辨认的地方 |
| 会话行为 | 会话票据 / 恢复 · OCSP 装订 | 真实站关掉恢复时我们也应关掉 |
| 我们发出的形状 | ClientHello 的扩展 / 套件 / 曲线（`client_*`） | 上游方向（我们→业务/幻境后端）的指纹 |
| 证书链形状 | 自签 vs 公有链 · 链长 · 密钥类型 · 签名算法 · SAN 数量 | 证书内容会替换，**形状**同样可指纹化 |

JA3 / JA3S 以**规范原文**形式输出（`ja3_line` / `ja3s_line`），不在这里算哈希 ——
比对时要看的是「差在哪一项」，哈希只能告诉你「不一样」。要与外部工具对账时：

```sh
printf '%s' "771,4865-49199,43-10-11,29-23,0" | md5
```

## 三种结论（判定标准写死在 `diff.go`，不由人解释）

| 结论 | 含义 | 后续 |
| --- | --- | --- |
| **不可区分** | 只剩证书形状差异（部署时会替换） | `R-1` 关闭，方案可用 |
| **可区分（属可配置项）** | 差在 ALPN / 会话恢复 / OCSP 之类**能配**的项 | 调齐 → 重采 → 重跑；**调齐前不得声称「不可区分」** |
| **不可对齐** | 差在版本 / 套件 / **扩展序列** | **停下**：`R-1` 重估命题；出路见报告里的三条候选 |

## 它**不**保证什么

- 它比的是**一次握手**，不是流量分布；不同客户端库（JA3）与服务端版本可能给出不同形状，真实结论需**多次采样**（建议：至少 3 次、间隔错开）；
- 它**不做**证书链的逐字节比对（只比形状）；
- 它不能替代 `E2` 的全貌：`E2` 还要求对照组与「同款真实栈」的定义（见 `pending-experiments.md`）；
- **不要把它的中间结论当成结论**：结论以 `pending-experiments.md` 里登记的为准。
