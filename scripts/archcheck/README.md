# `archcheck`

架构与依赖方向检查。把设计文档里「写了验证方式、但没人执行」的规则变成可执行的检查。

| 项 | 值 |
| --- | --- |
| 阶段 | 1 |
| 依据 | `ST-1` · `ST-2` · `ST-3`（兜底）· `ST-4` · `MD-18` · `MD-19` · `MD-20` · `TB-20` · `TB-21` · `TB-24` · `AR-33` |

## 它是什么

一个不依赖任何第三方库的 Go 程序，用 `go list -json ./...` 拿真实的包与 import 关系，
再对照设计文档里的清单做结构检查。

它**不检查代码风格**，只检查结构：谁允许依赖谁、哪个目录允许存在、存储访问是否只有一个出口。

## 检查项

| 检查 | 拦什么 | 依据 |
| --- | --- | --- |
| 顶层目录白名单 | 新增顶层目录却没更新 `structure.md` §1.1 | `ST-1` |
| 禁止跨顶层目录 import | `core/` 依赖 `edge/` 这类跨平面耦合；`api/` 不再是叶子 | `ST-2` · `ST-4` |
| 核心内部包的可见性 | 适配器 import `core/internal/`（编译器已拦，这里是更清楚的消息 + 兜底） | `ST-3` |
| `store` 是核心唯一 I/O 出口 | 其他核心模块直连数据库驱动；`store` 反向依赖业务模块 | `MD-20` |
| 模块目录与清单一致 | 代码里有清单外的模块目录 | `MD-18` · `MD-19` |
| 禁止 CGO 与本地库 | `import "C"`、`.c` / `.so` / `.dylib` 等文件 | `TB-24` |
| 语言层数 | 引入第 6 种实现语言 | `TB-20` · `TB-21` |
| 护栏是唯一出口 | `analysis/` 下除 `ai-capability` 的出口（`service.py`）、接缝（`model.py`）、`llm/` 自身与测试外，import 模型客户端 | `AR-33` |

## 怎么跑

```sh
make archcheck              # 作为门禁的一部分
go run ./scripts/archcheck  # 直接跑
go run ./scripts/archcheck -dump   # 只打印解析出的清单，不做检查
```

## 两个刻意的设计

**清单从文档解析，不硬编码。** 顶层目录取自 `structure.md` §1.1 的目录树，
模块目录取自 `modules.md` §1.1 的表格。这样改文档即改检查，不会两边漂移。

**解析结果不合预期时直接报错退出。** 例如模块行解析不到 15 条就断定文档格式变了，
拒绝继续 —— 否则文档一改格式，检查会「通过」一个空清单，比不检查更危险。

**非 Go 模块看「目录在不在 + 里面有没有东西」。** `go list` 只看得到 Go 包，
所以 L4 的 Python 模块、L3 的声明式产物与纯配置模块（如 `edge/dns/`）在它眼里不存在。
早先的版本因此把它们全列进「清单里有、代码尚未实现」的提示里 —— 读的人会以为这些模块没做。
现在对这类模块改用**目录是否含文件**判定，并把剩下的分成两类说清：

```text
ℹ 清单里有、代码尚未实现的模块目录 1 个（阶段 2/3，不算错）：
      deception/shell/（目录尚未创建）        ← 用户裁定推迟
      某个模块/（目录已建，里面还没有文件）    ← 建了目录但没东西，排查方向不同
```

## 豁免名单

`core/internal/contract` 不要求出现在模块清单里：按 `structure.md` §1.2 它只放类型、
不放逻辑，没有自己的职责边界，因此不是模块。进程入口（`*/cmd/<name>`）同样不是模块。

这个名单是**刻意写死的少数几项**，不允许它悄悄变长。

## `AR-33` 的护栏结构检查

它回答一个具体问题：**有没有一条不过护栏的生成路径**。

`ai-capability` 把四关（结构 / 黑名单 / 长度 / 风格）做在唯一出口 `service.generate()` 里面；
如果别处直接 import 模型客户端（`analysis/llm/client`）自己生成内容，四关就被绕过了。
因此本检查扫描 `analysis/**/*.py` 的 import 语句，只允许这四个前缀：

| 允许 | 为什么 |
| --- | --- |
| `analysis/aicap/service.py` | 唯一出口（`AR-33` 的判据） |
| `analysis/aicap/model.py` | 模型接缝（取客户端 + 核对无执行面，`AR-32`） |
| `analysis/llm/` | 客户端自身所在层 |
| `analysis/tests/` | 测试不是生成路径 |

扫不到 Python 文件、或护栏出口/接缝文件不存在时，它**直接报错**而不是静默通过。
