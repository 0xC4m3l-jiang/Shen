# `gate`

CI 门禁的检查脚本。**Makefile 只负责编排，判定逻辑放在这里。**

| 项 | 值 |
| --- | --- |
| 阶段 | 1 |
| 依据 | `TB-14`（禁止未处理的错误返回值）· `TB-15`（CI 门禁） |

## 它是什么

门禁的各个检查项。每个脚本**只做一件事**，失败即非零退出。

| 脚本 | 检查 | 依据 |
| --- | --- | --- |
| `check-fmt.sh` | 所有 Go 文件已格式化（**只检查、不改文件**） | `TB-15` |

其余检查项由 Makefile 直接编排，因为它们本身就是单条命令：

| 检查 | 命令 | 依据 |
| --- | --- | --- |
| 静态检查 | `go vet ./...` · `staticcheck ./...` | `TB-15` |
| 未处理的错误返回值 | `errcheck ./...` | `TB-14` |
| 架构与依赖方向 | `go run ./scripts/archcheck` | `ST-1`…`ST-4` · `MD-18`…`MD-20` · `TB-20`/`TB-21`/`TB-24` |
| 单测与数据竞争 | `go test -race ./...` | `TB-15` |

## 怎么跑

```sh
make gate      # 全套门禁（需要先跑一次 make tools 装工具）
make check     # 快速内循环：不需要下载任何工具
```

## 状态

✅ **已实现。**

## 纪律

**工具缺失时门禁必须失败，不得跳过。** 静默跳过等于假绿 —— 那比没有门禁更糟，
因为它给了「检查过了」的错觉。因此 `staticcheck` / `errcheck` 未安装时目标直接报错退出。
