# 伪造流量与判定核对（`scripts/traffic/`）

给欺骗引擎发**伪造流量**，然后从**观测面**核对判定结果 —— 用于人工测试与回归验证。

```sh
scripts/traffic/send.py                    # 全部场景
scripts/traffic/send.py --group 自动化探针  # 只跑一组
scripts/traffic/send.py --only probe-git-headless --repeat 3
scripts/traffic/send.py --json             # 机器可读（自动化）
```

等价入口：`scripts/shen.sh traffic` · `make traffic`。

## 两个文件

| 文件 | 是什么 |
| --- | --- |
| `scenarios.json` | **声明式场景**：每条 = 一次请求（方法 / 路径 / 头 / 可选 body）+ 期望 |
| `send.py` | 发送 + 从控制台核对 + 汇总；只用**标准库**（不需要 venv 或任何依赖） |

## 为什么要从观测面核对（而不是看响应）

判定响应**禁止**回显分值 / 规则名 / 枚举（`ST-7`）。所以：

```text
请求 ──► 引擎 ──► 响应（只有业务内容，没有判定细节）
                     │
                     └─► 异步遥测 ──► 控制台 /api/flow（分值 / 命中信号 / 决策）
```

脚本正是按这条规矩写的：**发请求看响应状态**，**看判定问控制台**。

## 期望字段

| 字段 | 含义 |
| --- | --- |
| `min_score` / `max_score` | 分数上下界（含） |
| `signals_any` / `signals_all` | 至少要命中一个 / 必须全部命中（信号 ID 来自配置里的规则 `id`） |
| `action` | 三值之一；**不写则不判定**（影子模式与接管后取值不同，`INT-11`） |
| `observe_only` | `true` = 只发不判：用于示例配置未覆盖的流量（人工观察，或等加了规则再收紧） |

**所有场景都会额外检查两件事**（无论期望怎么写）：

1. **业务不受影响**（`NI-1`）：HTTP 状态码不得 ≥ 500；
2. **响应头卫生**（`OH-2`）：响应里不得出现 `x-shen*`、`Via`，也不得出现 `Caddy` 字样。

## 当前期望值的依据

期望按 [`../../deploy/config/config.example.yaml`](../../deploy/config/config.example.yaml) 里**实际生效的两条示例规则**写：

| 规则 id | 匹配 | 权重 |
| --- | --- | --- |
| `ua-headless` | `user_agent` 含 `HeadlessChrome` | 0.6 |
| `path-probe` | `path` 前缀 `/.git` | 0.3 |

所以 `probe-git-headless`（两者都命中）期望 `min_score: 0.8`，而 `/.env`、`/wp-login.php`、SQLi、Actuator 这类**示例规则没覆盖**的流量标为 `observe_only` —— 它们仍然很有用（人工看引擎"看见了什么"），但脚本不会替你断言一个尚未定义的期望。
**改了规则请同步 `scenarios.json`**（否则断言会与真实配置漂移）。

## 两个容易踩的点

1. **防缓存参数**：同一 `(来源, 会话, 方法, 路径)` 在时间窗内复用判定（`ST-10` 判定缓存），
   不换参数的话第二轮不会有新记录 —— 核对就变成"看到上一轮的结果"。脚本默认追加 `?r=<随机>`；
   要复现"同窗复用"行为时用 `--no-nonce`。
2. **异步上报**：判定写完与控制台可见之间有间隔（`AR-11` 异步批量）。脚本默认最多等 8 秒
   （`--wait`），等不到会在结果里报出来，而不是假装通过。

## 退出码

| 码 | 含义 |
| --- | --- |
| `0` | 全部断言通过（观察类不计入），且无响应头卫生问题 |
| `1` | 有断言失败 / 响应头泄漏 / 控制台不可读 |
| `2` | 用法或场景文件错误 |
