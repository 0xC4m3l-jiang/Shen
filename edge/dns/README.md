## 它是什么

按**来源**决定域名解析到**引擎**还是**真实业务**（`INT-2`）。

**本模块不产生源码**（`AR-3`：L0 接入层禁止自研，必须复用现成组件）。
交付物是给 **CoreDNS** 的配置模板 —— `view` 插件的 `expr incidr(client_ip(), …)`
支持按客户端网段返回不同答案，**不需要编译自定义插件**。

## 为什么是 CoreDNS

`Apache-2.0`，通过 `TB-16` 许可审计；且按来源分流可纯配置实现。

被 `TB-16` 拦掉的候选：`dnsmasq`（GPL-2.0）· `mosdns`（GPL-3.0）· `AdGuard Home`（GPL-3.0）。

## ⚠️ 这个形态的 `NI-1` 风险高于其他三种

镜像形态天然不碰业务路径；代理形态引擎挂了可以放行；
但 **DNS 形态一旦接管解析，引擎就成了业务可达性的前置条件**。

因此模板里写死了三条，**不满足禁止启用**：

1. 只接管白名单外的**指定域名**，默认不接管任何域名；
2. 引擎侧必须有可用的放行路径（形态 ③ 的 `adapter-proxy`，或真实业务本身）；
3. 能一键回退，且 TTL 短到回退能快速生效。

## ⚠️ 顺序即语义

带 `view` 的 server block **必须**写在兜底 block 之前。
若兜底在前，它会先匹配一切，带 `view` 的块永远不会被命中 —— **且不报任何错**。
现象是「配置看起来生效了，分流完全不发生」。

## 验收

从两个来源网段查同一域名，必须得到不同结果：

```sh
dig @<coredns-ip> example.com +short                  # 普通来源 → 真实业务
dig @<coredns-ip> -b 203.0.113.7 example.com +short   # 可疑来源 → 引擎 IP
```

这是本形态唯一的验收标准，应作为 `shen doctor`（`INT-17`）检查项 ⑤ 的一部分。
