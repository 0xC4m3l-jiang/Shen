# 适配器 · ② DNS 智能解析引流

| 项 | 值 |
| --- | --- |
| 所属层 | L1 |
| 语言 | **配置**（本模块**不产生源码** —— `AR-3` 禁止自研 DNS） |
| 阶段 | **2a** |
| 模块文档 | [`../../docs/modules/adapter-dns.md`](../../docs/modules/adapter-dns.md) |
| 配置 | [`config/Corefile.example`](config/Corefile.example) |

## 它是什么

按**来源**分流：可疑来源解析到引擎 IP（由引擎接住继续判定），其余来源解析到真实业务 IP、完全走原路径。

**不做的事**：不做判定（`AR-7`）· 不维护会话状态（`AR-7` / `INT-20`）· 不改写业务响应（`INT-8`）·
**只对指定域名生效**（配错会影响面，见下）。

## 怎么用

```sh
# 1) 把模板拷到你的 DNS 服务（CoreDNS）配置目录
cp edge/dns/config/Corefile.example /etc/coredns/Corefile
# 2) 按你的环境改三处：域名 · 可疑网段 · 引擎 IP（模板里都有注释标出）
# 3) 校验并加载
coredns -conf /etc/coredns/Corefile -dns.port 0   # 语法自检：能起来说明语法正确，随即 Ctrl-C
```

## 怎么确认分流生效（两条 `dig` 就是全部验收）

```sh
# ① 可疑来源 → 应得到**引擎** IP
dig @127.0.0.1 -b 203.0.113.7 shop.example.com +short     # 期望：10.0.0.99（引擎）
# ② 其他来源 → 应得到**业务真实** IP
dig @127.0.0.1 -b 198.51.100.20 shop.example.com +short   # 期望：业务真实 IP
```

两条都符合即生效。**顺序即语义**：带 `view` 的块必须写在兜底块之前（模板顶部有警示注释）——
反了不报错，只是分流完全不发生。

## 怎么回退（`NI-11`：移除一段配置即可，不重启业务）

把解析改回业务真实 IP 即可（或删掉带 `view` 的块）。模板把 TTL 压到 30 秒，就是为了让回退**快**。

## 配错的影响面（本形态的 `NI-1` 风险最高）

一旦解析被接管，**引擎就是业务可达性的前置条件**：引擎不可达 ⇒ 可疑来源的请求无人接住。
因此模板里写了三条**启用前必须确认**的回退开关（见 Corefile 末尾注释）。本形态**不具备**形态 ③④ 的
「进程内 fail-open」—— 它依赖你把引擎侧接好（建议指向形态 ③ 的 `adapter-proxy`）。
